# osnova-fabrica

Кодогенератор для языка **Основа** — кириллического языка программирования с VLIW-поддержкой.

```
task (текст) → LLM → .osnova → компилятор → .osvbc → VM → результат
```

## Язык Основа

Русскоязычный язык с синтаксисом, читаемым как структурированный русский текст. Целевая платформа — VLIW-процессоры (модель e2k). Компилируется в байткод `.osvbc` (JSON), исполняется на стековой VM.

Каноничные источники для языка и генерации кода:

- `docs/language-v2.md` (человекочитаемая спецификация v2.0.0)
- `docs/osnova/language-schema.json` (machine-readable канон)
- `docs/pipeline-v1.md` (актуальный pipeline)
- `docs/traces-v1.md` (актуальные трейсы)

`docs/legacy/**` — архив. Не использовать как источник истины для генерации нового кода.

```
модуль Пример

процедура главная(): Ничто
  пусть x: Целое32 = 42
  система.лог.вывести(x)
конец
```

## Структура

```
src/
  compiler/        — лексер, парсер, AST, кодогенератор (.osnova → .osvbc)
  runtime/         — стековая VM, runner, sandbox, storage, UI-сервер
  vliw/            — VLIW-планировщик e2k: модель устройств, граф зависимостей,
                     планирование с задержками, перестановка, счётчики конвейера
  llm/             — провайдеры LLM (DeepSeek, QwenCli, Ollama)
docs/              — спецификации языка, грамматика, протоколы
examples/          — корпус примеров: программа + эталон результата + статус VM/e2k
```

Готовые программы — в `examples/` (индекс: `examples/README.md`): каждая
собирается и исполняется, у каждой эталон получен **независимо**, а помеченные
`e2k` проходят и на цели — против того же эталона. Границы названы там же:
программа, которая на цели не идёт, стоит в индексе с причиной, а не молчит.

## VLIW: модель e2k

Планировщик знает о железе «Эльбрус» не по догадкам, а по руководству МЦСТ
(`docs/elbrus-prog-1.2_2024-02-28.pdf`); каждое число и ограничение — со ссылкой
на страницу. Подробно: `docs/vliw-e2k-model.md`.

Что учтено:

- **24 канала выдачи** в широкой команде: 6 АЛУ + СТ + 3 PL + 6 QP + 4 APB +
  4 LIT (стр. 54–56). АЛУ **не равнозначны**: деление и корень — только АЛУ5,
  запись — только АЛУ2 и АЛУ5, чтения нет у АЛУ1 и АЛУ4.
- **Длительности операций** (стр. 71–72): целочисленные 1 такт, `mul` 4, деление
  11/14, чтение L1/L2/L3/память 3/11/40/~100, подготовка возврата 6, штраф
  `fp→int` +2. Калибровка — по примеру самого руководства (стр. 70).
- **Задержки материализуются как `nop`** — так это выглядит в ассемблере e2k
  (стр. 70, 193).
- **Перестановка независимых операций** возможна на регистровом коде, где
  операнды указаны явно. На стековом байткоде порядок `push`/`pop` — часть
  семантики, поэтому там упаковка остаётся in-order.
- **Счётчики конвейера** в терминах `dprof` (стр. 63–64): `TICKS`, `EXEC`,
  `BUB_E2`. Счётчики, которых мы не моделируем (`BUB_B`, `IB_NO_COMMAND`,
  `L2_QUERY`, `L2_HIT`), возвращаются как `null`, а не нулём.

Измеренный выигрыш перестановки против in-order на том же графе (реальный код):
18–38% тактов на четырёх программах из пяти; на пятой — 0% (длинные чтения и
зависимости, переставлять нечего).

### Два уровня абстракции

Формат байткода Основа и железo e2k — разные вещи, и они намеренно разведены:

| Что | Где | Смысл |
|---|---|---|
| Модель железа e2k | `src/vliw/e2kDevices.ts` | 24 канала, длительности, реальные ограничения устройств |
| Формат пакета Основа | `src/vliw/e2kModel.ts` | `VLIW_SLOTS = 4` — ширина пакета **формата**, не железа |

`VLIW_SLOTS` остаётся равным 4, потому что это значение записано в модулях
`.osvbc` и проверяется golden-прогоном. Менять его значило бы сломать формат ради
числа, к формату отношения не имеющего.

## Зависимости

- **Node.js** >= 20
- **TypeScript** 5.x, strict mode
- **tsx** — запуск TS напрямую без сборки
- **js-yaml** — парсинг манифестов `.osapp.yaml`
- **vitest** — тесты
- **typescript-eslint** — lint (ESLint v9 flat config)
- **LLM провайдер**: `qwen-cli` (по умолчанию), `deepseek` или `ollama`

Скопируй `.env.example` в `.env` и выставь `OSNOVA_PROVIDER`.

### Известные ограничения e2k-линии (измерено, 2026-09-24)

| Ограничение | Измерение |
|---|---|
| **Вытеснение в память: все 16 процедур пяти ядер раскладываются** | Минимальное вытеснение (`src/vliw/spill.ts`, оракул `src/vliw/spill.test.ts`): когда регистра не хватает, в слот уезжает **самое дешёвое** значение (предел — **4** на процедуру, число взято замером `.tmp/convolution-spill-need.ts`), адрес слота кладётся литералом (`movtd`), чтение — `ldd`, запись — `std`. `fir/фильтр` — 1 значение, `correlation/корреляция` — 2, `convolution/свёртка` — 4. Покрытие пяти ядер **464 из 464**, отказов **0** (было 424 из 446 и 22 отказа; последний — `IR.div` ядра `iir` — снят заменой трюка через остаток на оператор `div`) — `docs/e2k-regalloc-debt.md` §14 |
| **FIR = 181: ядро понижается целиком, исполняется — встроенным** | `tests/dsp/kernels/fir.osnova` понижается **102 из 102** (мешающих носителей нет). Исполнение в модели даёт **181** для того же алгоритма **без вызова** — текст живёт в корпусе примеров (`examples/01-свёртка-fir/`, читается через `src/e2k/firReference.ts`, проверка «FIR целиком: 181»), и тот же эталон сверяется на VM оракулом корпуса. Прогон ядра КАК ЕСТЬ (с вызовом `фильтр`) невозможен, и причина измерена: окно вызываемой — восемь регистров, а `фильтр` требует десять даже после вытеснения. Это долг **окна**, а не раскладки, и он **отложен решением владельца**: `docs/hardware-debt.md` §3.24 |
| **`gate:qemu`: 79 из 79** | Раскладка встроенной свёртки (`src/e2k/e2kConvolutionQemu.test.ts`) удалась после правки сопоставления пар (у вызова считается только существующий аргумент). **Но** прогон встроенной свёртки **не доводит программу до выхода** и за 60 с, и причина **не установлена** (прежняя ссылка на дефект раскладки циклов снята — тот дефект закрыт): `docs/hardware-debt.md` §3.19. Двадцать четыре проверки добавлено корпусом примеров (2026-09-26): исполнение на цели против тех же эталонов, что и на VM, плюс сверка образа с конвейером владельца. Не входят в шлюз примеры с названным СЛОЕМ расхождения: потеря старших разрядов у значений не меньше 256 — слой «модель» (21, 25); возврат со значением не один — слой «обвязка», раннер отказывает (26, 30), такие программы вынесены в границы tools/e2k-hardware/limits/; причина не установлена — пример 17 |
| **QEMU-оракулы требуют WSL с `qemu-e2k`** | `npm run gate:qemu` не входит в `npm test` и не входит в `npm run ci`: он зависит от внешнего ресурса (шим `mmap`, занятость машины) |
| **`npm run test:e2k-targets`: 113 проверок, 0 красных** | Четыре прежние проверки-цели **достигнуты** вытеснением в память (2026-09-24): раскладка `фильтр` в десяти регистрах, окно вызываемой после материализации, размещение всех 22 `IR.invoke` у FIR, качество раскладки `фильтр`. Числа перемерены прогоном |

**Проверки.** `npm run ci` — **11/11 зелёный**; `npm test` — полный набор, 0 падений.
Точные числа файлов и проверок печатает сам прогон, и они растут вместе с набором,
поэтому здесь не дублируются. Шаг `npm run coverage` — тот же набор **без**
`src/agents/RepairEngineer.test.ts`: два разных набора, а не расхождение прогонов,
и именно поэтому числа двух прогонов не совпадают.
`gate:qemu` — **79 из 79**: 55 проверок оракулов цели плюс **24** из корпуса примеров
(`src/scripts/examplesE2k.audit.test.ts` — примеры, объявленные исполняемыми на e2k,
сверяются с тем же эталоном, что и на VM). FIR целиком проверяется прогоном и равен
**181** на встроенном источнике (см. таблицу).
