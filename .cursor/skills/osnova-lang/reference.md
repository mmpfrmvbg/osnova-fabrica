# Osnova — reference

Читать при сомнении в типах, циклах, syscall или алиасах. Канон: `src/compiler/language-registry.ts`. При конфликте с этим файлом — код.

## Ключевые слова (implemented)

`модуль` `процедура` `тип` `использовать` `экспорт` `из` `пусть` `если` `иначе` `иначе_если` `пока` `попробовать` `иначе_попытка` `выбросить` `для_каждого` `в` `цикл` `прервать` `продолжить` `конец` `вернуть` `истина` `ложь` `пусто` `и` `или` `не` `тогда` `когда` `есть`

`тогда` после условия — опционально.

## LLM-алиасы → канон

Лексер принимает английские/C-лексемы; **в файле пиши русский канон**.

| Алиас | Канон |
|-------|-------|
| `module` | `модуль` |
| `function` / `fn` | `процедура` |
| `type` | `тип` |
| `let` / `const` / `var` | `пусть` |
| `if` / `else` / `elif` | `если` / `иначе` / `иначе_если` |
| `return` | `вернуть` |
| `while` | `пока` |
| `for` / `in` | `для_каждого` / `в` |
| `break` / `continue` | `прервать` / `продолжить` |
| `true` / `false` / `null` | `истина` / `ложь` / `пусто` |
| `and` / `or` / `not` / `end` | `и` / `или` / `не` / `конец` |
| `export` | `экспорт` |

Также: `&&`→`и`, `===`→`==` (см. lexer / docs). Цепочка `a < x < b` → `(a < x) и (x < b)`.

## Модуль и процедуры

```osnova
модуль Имя
использовать модуль Утил из "утил.osnova"   // только до процедур
тип Точка { x: Число, y: Число }            // только до процедур
процедура экспорт удвоить(x)
  вернуть x * 2
конец
процедура главная()
  вернуть Утил.удвоить(21)
конец
конец
```

- Несколько `модуль` в одном файле допустимы; точка входа — из **первого** модуля.
- Экспорт: `процедура экспорт имя` или `экспорт процедура имя`.
- Импорт только в начале модуля. Неэкспортированные чужие процедуры не вызывать.
- `главная(аргументы)` — опциональный массив CLI-строк (не путать с `запуск` пакета Dviglo).

## Типы

VM: `number` | `string` | `boolean` | `null` | object | array.

В языке:

- `тип Имя { поле: Тип, ... }`, nullable `?Тип`
- `пусть x: Тип = …`
- Поля именованных типов: `Целое32`, `Число` (синоним), `Строка`, `Логический`; вложенный `тип` и `[Тип]` — по коду компилятора (см. тесты P0).
- Отдельного KW `массив` в аннотации типа нет — литерал / `система.массив.*` / `[Тип]` где поддержано.

## Переменные и операторы

- Объявление: `пусть x = expr` (+ опционально `: Тип`)
- Присвоение: `x = expr`, `x +=` / `-=` / `*=` / `/=`
- Поле: `obj.поле`, `obj.поле = …`, составные `+=`…
- Арифметика: `+ - * / %`; сравнения `== != < <= > >=`
- `+` склеивает, если есть строковый операнд
- Логика: `и` `или` `не` (short-circuit для `и`/`или`)

Запреты: `:=`, повторный `пусть` на то же имя, присвоение до `пусть`, `если x = 0`.

## Ветвления и циклы

```osnova
если условие
  ...
иначе_если другое
  ...
иначе
  ...
конец

пока условие
  ...
  если стоп
    прервать
  конец
  если пропуск
    продолжить
  конец
конец

цикл
  ...
конец

для_каждого эл в arr
  ...
конец

для_каждого эл, индекс в arr
  ...
конец
```

`прервать` / `продолжить` — ближайший `пока` или `цикл` (не «выйти из процедуры»).

## Массивы и объекты

| Синтаксис | Смысл |
|-----------|--------|
| `[a, b]` | литерал → codegen: `создать` + серия `добавить` + local |
| `arr[i]` | сахар → `система.массив.получить(arr, i)` |
| `arr[i] = v` | сахар → `система.массив.установить` |
| `{ a: 1 }` | литерал объекта |
| `obj.поле` | доступ / присвоение |

`система.массив.*` (argc): `создать(0)`, `добавить(2)`, `установить(3)`, `удалить(2)`, `срез(3)`, `длина(1)`, `получить(2)`.

`система.объект.*`: `получить(2)`, `установить(3)`, `ключи(1)`.

Предпочтение: сахар `arr[i]` вместо голого `получить`, если уместно (см. forbiddenPatterns).

## Ловушки стека (syscall)

Стековая VM: аргументы на стек → `invoke` → возврат на стек (или `null`).

**Критично:** `система.массив.добавить` / `установить` / `удалить` в default VM **мутируют массив и возвращают `null`**, не массив.

- Литерал `[…]` в аргументе вызова безопасен: codegen кладёт массив в local и снова поднимает на стек.
- Не писать код, который ожидает «добавить вернёт массив» (как JS `push` иногда используют в цепочках).
- Не вкладывать сырые `добавить(...)` как выражение там, где нужен массив-результат — держи массив в переменной.
- Исторический баг: если `добавить` клал массив обратно на стек, литерал в аргументе `игра.выбор(..., пункты)` съедал предыдущие аргументы. Не возвращать это поведение.

Перед новым `система.*` в выражении: argc в registry + что реально кладёт invoke на стек (код VM / host handler).

## Прочие syscall (кратко)

Полный список — `SYSCALLS` в registry. Частое:

- `система.лог.вывести(1)`
- `система.строка.*` (объединить, длина, подстрока, …)
- `система.хранилище.*` (в пакетах Dviglo — через хост/`игра.сейв`, не сырое хранилище телефона)
- `система.время.*`, `система.json.*`, `система.математика.*`
- `система.сеть.*` / `система.файлы.*` — в реестре Фабрики есть; **в пакетах Dviglo запрещены песочницей**

Host: `compileSource({ extraSyscalls })` + VM `extraInvokes` — имена вроде `игра.очистить` известны компилятору/VM только через хост, не через LANGUAGE_REGISTRY.

## Исключения

```osnova
попробовать
  выбросить "ошибка"
иначе_попытка е
  вернуть е
конец
```

Выбрасывай только объявленные в процедуре имена.

## Нет в языке (не выдумывать)

HOF / лямбды / классы / generics / pattern matching / `конец_*` / `система.вывести` / `система.окружение.*` / конверторы `целое32()` / `система.число.из_строки`.

## Forbidden patterns

Сверяй массив `forbiddenPatterns` в `language-registry.ts` — там bad/good эталоны для LLM и валидации.
