# v3: два фронтенда — один AST, один кодоген, один рантайм

**Дата решения:** 2026-10-01
**Статус:** план. Ничего из описанного ниже, кроме `src/compiler-v3/` (заготовка),
в дереве ещё нет.

## Решение

```
src/compiler/       — v2: лексер, парсер, AST. Заморожен.
src/compiler-v3/    — v3: лексер, парсер. Выдаёт AST ФОРМЫ v2.
src/runtime/        — ОДИН рантайм. Копий v3 нет и не будет.
src/e2k/            — ОДИН кодировщик. Копий нет.
src/vliw/           — ОДИН планировщик. Копий нет.
src/spec/           — исполняемая спецификация: тонкий слой поверх compiler-v3.
src/emitter|semantic — та же форма AST, тот же путь.
```

Правило, которое решает всё: **фронтендов два, дальше путь один.** v3-лексер и
парсер выдают тот же `Program` из `src/compiler/ast.ts`, что и v2. Байткод,
VM, кодировщик e2k и планировщик не знают, на каком синтаксисе написана
программа.

## Почему разрез именно такой

**Рантайм и e2k не знают синтаксиса.** Байткод один, VM одна, кодировщик один.
Если потащить их в v3, получится два рантайма — и v3 умрёт: в нём не будет ни
DSP-ядер, ни self-hosted, ни `gate:qemu`, ни сверки с `as`/`objdump`. v3 — это
**фронтенд**, а не проект.

**Дифференциальный оракул достаётся бесплатно.** В дереве уже есть сверка трасс
двух VM (`src/oracle/parity.ts`). Тот же приём расширяется на фронтенды, уровень
за уровнем:

| уровень | утверждение | что краснеет |
|---|---|---|
| 1 | `parse_v2(источник) == parse_v3(эквивалент)` | дефект v3-фронтенда, с точным узлом |
| 2 | байткод обеих сборок совпадает | расхождение на кодогене или семантике |
| 3 | трасса исполнения совпадает | расхождение в рантайме |

Первое расхождение называет место. Это дешевле любого «написать тесты на парсер».

## Порядок (шаги не переставлять)

1. **`src/compiler-v3/`** — лексер и парсер, выдаёт AST формы v2. **Сделано**
   (заготовка: `lexer.ts`, `parser.ts`).
2. **Оракул на AST:** 5 программ, `parse_v2` против `parse_v3`.
   Пока он не зелёный — дальше нельзя.
3. **`src/spec/`** импортирует из `compiler-v3` и перестаёт быть отдельным
   контуром: спецификация становится фронтендом, а не вторым языком.
4. **Первая реальная программа на v3** (200–300 строк, не пример) — через
   v2-AST → байткод → VM; сверка с v2-версией той же программы.
5. **`language-registry` + `language-schema.json`** строятся ИЗ грамматики v3,
   одним коммитом. Только после шага 4.
6. **Корпус (110 программ) мигрирует**; `src/compiler/` → `src/compiler/legacy/`.

## Запреты (иначе v3 расползётся в проект)

- не создавать `runtime-v3/`, `e2k-v3/`, `vliw-v3/` — ни одной копии;
- не заводить отдельный test-runner: оракул v3 живёт в общем `npm test`;
- не тащить в `examples/` до шага 5;
- **не трогать `language-registry` и `language-schema.json` до шага 4.**

Последний запрет — не осторожность, а выученный урок: `docs/token-cost-report.md`
замерил, что естественная русская форма вдвое дешевле склеенной через `_`, и
назвал `при ошибке` заменой для `иначе_попытка`. Метрика была — решения не было:
в компиляторе по-прежнему `иначе_попытка`. **Метаданные, уехавшие вперёд кода,
выглядят как решение ровно так же, как настоящий код, — и так же молчат.**

## Соответствие синтаксисов (для оракула шага 2)

| v2 (канон сейчас) | v3 (по спецификации `docs/osnova-spec.md`) |
|---|---|
| `модуль Имя` … `конец_модуля` | шапки нет: файл = модуль |
| `конец_процедуры`, `конец_пока`, `конец_если`, `конец_для` | `конец`, `конец пока`, `конец если`, `конец для` |
| `попробовать` / `поймать e` | `защита` / `при ошибке как e` |
| `выбросить x` | `поднять x` |
| `истина` / `ложь` | `да` / `нет` |
| `для эл в` / `для_каждого` | `для каждого эл в` |
| `?Тип` | `Может Тип` |
| `[Т]` | `Список Т` |
| `10 div 3` | `10 нацело 3` |
| `если х = 5` (`=` как `==`) | только `==`: v3 не прощает |
| `вернуть(x)` | `вернуть x` |
| `система.лог.вывести(х)` | `вывести х` |
| `система.массив.длина(а)` | `длина а` |
| `система.массив.добавить(а, х)` | `добавить в а элемент х` |
| `система.массив.получить(а, 0)` | `а[0]` |
| `система.строка.объединить(а, б)` | `а + б` |

Единственное соответствие «один к одному» здесь — форма AST. Всё остальное —
написание; если для какого-то правила v3 нет, это **дыра v3**, а не повод
ослабить оракул.

## `длина`: нейтральное имя, реализацию выбирает семантика

`длина "абв"` и `длина [1, 2, 3]` **синтаксически неотличимы**, а вызовов в каноне
два: `система.строка.длина` и `система.массив.длина`. Решает не парсер, а слой,
который знает тип: проход `resolveLength` внутри `validateNamedTypesAndRewrite`
(`src/compiler/compiler.ts`) выбирает реализацию по типу операнда, а если тип не
выведен — остаётся массивная длина (прежнее поведение; молчаливая смена была бы
хуже).

Это не «вкус», а блокер прикладных программ: в них строки везде (имена,
описания), и при жёсткой привязке к массиву строковая длина недостижима вовсе.
Оракул — `src/compiler-v3/nativePath.test.ts`: `длина` строки и списка считается
**значением** на обеих VM (304 = 3·100 + 4), а контроль проверяет, что в AST
стоят ДВА разных вызова, а не один.

## Счётный цикл: разворот, а не новый узел (замер)

Вопрос был: расширять AST (вариант «а») или разворачивать v3-формы в v2-узлы.
Замер (`compileToReg` на обоих вариантах):

| что подано в `regcodegen` | исход |
|---|---|
| узел-выдумка `вызов диапазон(1, 10)` | **отказ**: «Неизвестная процедура: диапазон» |
| развёрнутая форма (`пусть` счётчика и предела + `пока`) | **принят**: `vregs 7`, `localToVreg` заполнен |

Вывод: **достижимость нативного пути даёт разворот, а не новый узел.** Новый узел
купил бы не достижимость (она уже есть), а второй путь в обоих кодогенах и в VM —
ровно то, от чего разрез «один AST» и защищает. Отдельный узел `цикл_диапазона`
остаётся возможной **оптимизацией** позже, если профиль покажет, что развёрнутая
форма дорога; сегодня данных для этого нет.

Что разворачивает фронтенд (и только он):
`для i от a до b [шаг s]` → `пусть i = a`; `пусть __предел_i = b`;
`пока <i <= предел | i >= предел> … i = i + шаг`. Знак берётся по литералу шага;
сложное выражение считается неотрицательным — граница названа, а не угадана.

`повторять N раза`, `проверить`, `Словарь К → Т` остаются **названным отказом**:
их разворот требовал бы семантики (перебор, обработка ошибок, словарь), а не
структурной замены. Это следующий шаг, а не поблажка.

## Что уже проверено на нативном пути

`src/compiler-v3/nativePath.test.ts` — 5 проверок: `длина` строки и списка,
`длина` по аннотации параметра, счётный цикл `от 1 до 10`, счётный цикл с шагом и
убыванием, контроль «два разных вызова длины». Каждая считается **значением** и на
стековой, и на регистровой VM: расхождение трасс ловится, а не только форма AST.

## Что считается сделанным на шаге 2

- `parse_v3` разбирает 5 программ и выдаёт AST, **поструктурно равный** v2;
- сравнение не «оба собрались», а **равенство деревьев** (иначе оракул зелен по
  построению — ровно тот класс, что ловили в `docs/verification-debt.md`);
- проба краснеет, если убрать любое из различий синтаксиса (негативный контроль);
- оракул собран в общем прогоне (`npm test`), и сторож `check:test-files`
  его видит.
