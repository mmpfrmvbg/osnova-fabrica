# Байткод Основа v1

Формальная спецификация формата байткода `.osvbc` и поведения VM.
Источник опкодов и структур — [bytecode.ts](../src/runtime/vm/bytecode.ts) (тип `Op`);
исполнение — [interpreter.ts](../src/runtime/vm/interpreter.ts); эмиссия — [codegen.ts](../src/compiler/codegen.ts).

---

## 1. Структура OsVbcModule

| Поле | Тип | Описание |
|------|-----|----------|
| `version` | number | Версия байткода (1) |
| `moduleName` | string | Имя модуля |
| `constants` | unknown[] | Пул констант (числа, строки, булевы, null) |
| `procedures` | ProcedureDef[] | Список процедур |
| `code` | CodeElement[] | Инструкции (линейные или VLIW-пакеты) |
| `vliwSlots` | number? | Максимум слотов в пакете (v2, опционально) |

---

## 2. Структура процедуры (ProcedureDef)

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | Имя процедуры |
| `codeOffset` | number | Смещение в `code`, с которого начинается тело |
| `argc` | number | Количество аргументов |
| `localsCount` | number | Количество слотов локалов (включая аргументы) |
| `returnsValue` | boolean? | Процедура возвращает значение |
| `pure` | boolean? | Процедура объявлена как `чистый` (без побочных эффектов) |
| `deps` | ProcedureDeps? | Граф зависимостей блоков — hint для VLIW-планировщика; VM игнорирует |

Интерпретатор при `call fi`: снимает `argc` значений со стека, инициализирует
`locals[0..argc-1]`, остальные `locals[argc..localsCount-1]` — `null`, устанавливает
`pc = proc.codeOffset`. При `ret` — возврат из процедуры с восстановлением кадра.

## 3. Инструкции

### 3.1. Константы и локальные

| Опкод | Поля | Стек: снимает → кладёт | Особые случаи |
|-------|------|------------------------|---------------|
| `const` | `type`, `k` | — → `constants[k]` | `k` вне границ → InterpreterError |
| `const.true` | — | — → `true` | |
| `const.false` | — | — → `false` | |
| `const.null` | — | — → `null` | |
| `local.get` | `i` | — → `locals[i]` | `i` вне [0..localsCount) → InterpreterError |
| `local.set` | `i` | `value` → — | `i` вне [0..localsCount) → InterpreterError |

`const.type` ∈ `i32` | `f64` | `str` | `bool` | `null`

### 3.2. Арифметика

Конвенция: `push a; push b; op` → результат `a ∘ b`. Второй операнд (b) на вершине.

| Опкод | Стек: снимает → кладёт | Особые случаи |
|-------|------------------------|---------------|
| `add` | [a, b] → [a+b] | |
| `sub` | [a, b] → [a-b] | |
| `mul` | [a, b] → [a*b] | |
| `div` | [a, b] → [a/b] | `b === 0` → InterpreterError |
| `rem` | [a, b] → [a%b] | `b === 0` → InterpreterError |

### 3.3. Сравнения

| Опкод | Стек: снимает → кладёт |
|-------|------------------------|
| `eq` | [a, b] → [a===b] |
| `ne` | [a, b] → [a!==b] |
| `lt` | [a, b] → [a<b] |
| `le` | [a, b] → [a<=b] |
| `gt` | [a, b] → [a>b] |
| `ge` | [a, b] → [a>=b] |

### 3.4. Логические

| Опкод | Стек: снимает → кладёт |
|-------|------------------------|
| `and` | [a, b] → [Boolean(a && b)] |
| `or` | [a, b] → [Boolean(a || b)] |
| `not` | [v] → [!v] |

### 3.5. Объекты

| Опкод | Стек: снимает → кладёт | Примечание |
|-------|------------------------|------------|
| `obj.new` | — → [{}] | Пустой объект (null-prototype) |
| `obj.get` | [obj, key] → [obj[key] ?? null] | Не-объект или отсутствующее поле → `null` |
| `obj.set` | [obj, key, val] → [obj] | Объект **остаётся на стеке** (peek, не pop); поле записывается |

### 3.6. Стек

| Опкод | Стек: снимает → кладёт | Особые случаи |
|-------|------------------------|---------------|
| `dup` | [v] → [v, v] | Дублирует вершину |
| `pop` | [v] → — | Пустой стек → InterpreterError |

### 3.7. Управление и вызовы

| Опкод | Поля | Стек: снимает → кладёт | Особые случаи |
|-------|------|------------------------|---------------|
| `call` | `fi` | [arg0..argN] → — | Вызов процедуры по индексу; результат при ret |
| `invoke` | `name` | [arg0..argN] → [result] | Системный вызов; argc из invokeRegistry; всегда кладёт ровно одно значение (`null`, если обработчик ничего не вернул) |
| `jmp` | `off` | — → — | Переход на `pc = off` |
| `jmp_if` | `off` | [cond] → — | truthy → jump, иначе next |
| `jmp_if_not` | `off` | [cond] → — | falsy → jump, иначе next |
| `try_begin` | `off` | — → — | Начало try-блока; `off` = адрес catch-обработчика |
| `try_end` | — | — → — | Конец try-блока, pop из стека обработчиков |
| `throw` | — | [value] → — | Выбросить значение; переход к ближайшему catch или ошибка VM |
| `ret` | — | [value?] → — | Возврат из процедуры |

### 3.8. VLIW-пакеты

Элемент `code` может быть VLIW-пакетом:

```json
{
  "packet": true,
  "slots": [ { "op": "const", "type": "i32", "k": 0 } ],
  "deps": [[0, 1], [2, 3]]
}
```

- `slots` — обязательный контракт VM: исполняются последовательно slot[0], slot[1], … slot[N-1].
- `deps` — **hint для VLIW-планировщика** (src/vliw/): пары `[from, to]` индексов зависимостей. VM игнорирует.
- Компилятор по умолчанию эмитирует только линейные инструкции; VLIW-пакеты создаются планировщиком (src/vliw/).

## 4. Пример

**Программа на Основе:**

```основа
модуль главный

процедура главная()
  пусть х = 2 + 3
  система.лог.вывести(х)
конец

конец
```

**Упрощённый OsVbcModule:**

```json
{
  "version": 1,
  "moduleName": "главный",
  "constants": [2, 3],
  "procedures": [
    { "name": "главная", "codeOffset": 0, "argc": 0, "localsCount": 1 }
  ],
  "code": [
    { "op": "const", "type": "i32", "k": 0 },
    { "op": "const", "type": "i32", "k": 1 },
    { "op": "add" },
    { "op": "local.set", "i": 0 },
    { "op": "local.get", "i": 0 },
    { "op": "invoke", "name": "система.лог.вывести" },
    { "op": "ret" }
  ]
}
```
