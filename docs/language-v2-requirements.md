# Требования к языку Основа v2 — по измеренным данным

**Статус: документ требований. Часть пунктов реализована (см. статусы).**
**Дата:** 2026-09-19; статусы пунктов сверены 2026-09-25.
**Источники чисел:** `docs/trace-failure-report.md` (замер по `runs/traces.jsonl`),

## Правило этого документа

Здесь только требования. Гейт «парсер, лексер и список алиасов **не тронуты**: до
первого работающего «hello» в QEMU язык не меняется» **снят** — hello достигнут
(`AGENTS.md`), и изменения языка перечислены статусами пунктов и
`docs/language-changelog-v2.md`. Каждый пункт — с числом, с тем, что пишет
модель, с тем, что язык принимает сейчас, и с предложением, которое можно
принять или отклонить отдельно.

## Пересчёт на датасете (2026-09-23) и причина расхождения

### Причина расхождения — найдена, и это не популяция

|---|---:|---:|---:|

| `unknown_syscall` | 41 | **41** | 16 |

Опыт воспроизводится: `git worktree add .tmp/old-compiler 554e58a`, затем

прогону — vitest подхватывает их).

Вывод: **числа документа не ошибочны — они условны по знаменателю**, то есть по
тому, сколько программ вообще доходит до семантического анализа. Датасет и
классификатор здесь ни при чём (`semantic.ts` после документа менялся один раз, и
не в этих видах).

**Механизм, посчитанный точно.** Между 2026-09-18 и HEAD парсер стал принимать
программы, которые раньше падали. Не доходят до семантики: было **41** исходник,
стало **27** — четырнадцать перешли в разбор. Прирост целиком на них:

| вид | прирост от «раньше не разбиралось, теперь разбирается» | от «разбиралось и раньше» |
|---|---:|---:|
| `undeclared_var` | **+92** | 0 |
| `unknown_procedure` | **+67** | 0 |
| `syscall_argc` | 0 | +3 |

Причина перехода у всех трёх тяжёлых исходников одна и та же — прежняя ошибка
`Ожидается выражение, получено: =`, то есть **`=` вместо `==` в условии, пункт 1.1
этого документа**. Три программы (131, 111 и 105 строк) дали +91, +49 и +12 —
итого **+152** из +162. Диагностики концентрированные: 106 вхождений
`undeclared_var` приходятся всего на **10** исходников, поэтому несколько
разобранных программ двигают итог в разы.

**Как это читать.** Успех БЛОК 1 v2 в §1.1 **поднял** числа семантических ошибок,
не ухудшив ничего: ошибки были и раньше, но были спрятаны за отказом парсера.
Числа §1.1–1.7 нельзя сравнивать между сборками без указания знаменателя.

## 1.1. `=` вместо `==`

| | |
|---|---|
| **Число случаев** | **52** (популяция A), крупнейшая одиночная синтаксическая причина |
| **Что пишет модель** | `если список.количество = 0`, `если хранилище = пусто`, `если задача.идентификатор = идентификатор` |
| **Что принимает язык** | только `==`; одиночное `=` — присваивание, в условии даёт «Ожидается выражение, получено: =» |
| **Предложение** | **принимать `=` как `==` в позиции условия** |
| **Статус** | **реализовано** (2026-09-23): `=` читается как `==` в позиции условия |

Обоснование: модель устойчиво тянет `=` из Pascal/SQL, где это сравнение. Это не
случайная опечатка, а след другого языка, и он повторяется 52 раза. Стоимость
приёма — одна ветка в разборе условия; альтернатива (диагностика «в условии
нужно ==») тоже допустима, но оставляет отказ отказом.

## 1.2. Ранний / лишний `конец`

| | |
|---|---|
| **Число случаев** | **63**: 49 × «Ожидается 'модуль'» + 14 × «Ожидается начало следующего модуля или конец файла» (популяция A) |
| **Что пишет модель** | `процедура ДобавитьЗадачу(название, описание)` там, где парсер уже вне модуля; `вернуть пусто` после закрытия модуля |
| **Что принимает язык** | `модуль Имя` → процедуры → `конец`; всё после закрывающего `конец` — ошибка |
| **Предложение** | **диагностика с точной позицией лишнего `конец`**, а не «принимать процедуру после `конец`» |
| **Статус** | **реализовано** (2026-09-23, БЛОК 1 v2): диагностика называет строку лишнего `конец` и строку, где модуль уже закрыт |

Обоснование: принять процедуру после закрытия модуля — значит разрешить
неоднозначную структуру и потерять возможность отличить «модуль закрыт» от
«модель ошиблась». Правильный ответ здесь — сообщение вида «лишний `конец` на
строке N: модуль уже закрыт на строке M». Сообщение «Ожидается 'модуль'»
указывает не туда, где ошибка.

## 1.3. `:=` из Паскаля

| | |
|---|---|
| **Число случаев** | **20** (популяция A) |
| **Что пишет модель** | `пусть задача := система.объект.создать()`, `пусть список := система.массив.получить(...)` |
| **Что принимает язык** | `пусть x = ...`; `:` читается как аннотация типа, дальше ожидается имя типа, и разбор падает |
| **Предложение** | **алиас `:=` → `=`** |
| **Статус** | **реализовано** (2026-09-23): лексер сводит `:=` к `=` |

Обоснование: `:=` не конфликтует ни с одной существующей конструкцией — двоеточие
в языке встречается только в аннотации типа и в литералах объектов, где за ним
идёт имя типа, а не `=`. Разбор однозначен. Цена — одна ветка в лексере.

## 1.4. `конец` как имя переменной

| | |
|---|---|
| **Число случаев** | **8** (популяция A) |
| **Что пишет модель** | `суммировать_диапазон(начало, конец)`, `процедура сумма_диапазона(начало, конец)` |
| **Что принимает язык** | `конец` — ключевое слово; в позиции аргумента разбор даёт «Ожидается ')', получено: конец» |
| **Предложение** | **диагностика + подсказка канонического имени** (`конец_диапазона`, `верхняя_граница`) |
| **Статус** | **реализовано** (2026-09-23): `конец` — контекстный токен; объявление, поле и использование в выражении (`вернуть конец`) работают |

Обоснование: `конец` — самое естественное русское имя для «end», и модель будет
использовать его всегда. Это дефект выбора ключевого слова, а не поведение
модели. Полное решение (переименовать ключевое слово) ломающе и здесь не
предлагается; минимальное — не выдавать невнятное «Ожидается ')'», а говорить
«`конец` — ключевое слово, переименуй параметр» и подсказывать имя. В языке уже
есть неблокирующий вид `keyword_as_identifier`, но до него разбор не доходит.

## 1.6. `redeclare_var` — повторный `пусть`

| | |
|---|---|
| **Число случаев** | **82** (популяция A) — самая частая семантическая ошибка |
| **Что пишет модель** | `пусть x = 1`, затем снова `пусть x = 2`; чаще всего на `сообщение`, `цифра`, `строка`, `задачи`, `результат` |
| **Что принимает язык** | первое объявление — `пусть x = ...`, дальше только `x = ...` |
| **Предложение** | **правило в промпте кодогенерации**, а не ослабление языка |
| **Статус** | **правило добавлено в промпт** (2026-09-23); эффект **ожидает замера** — нужен новый прогон генерации (`docs/verification-debt.md` п. 6) |

Обоснование: компилятор уже формулирует правило точно («используй просто
`x = ...`»), то есть язык здесь ни при чём — правило просто не видно модели
заранее. Это правка промпта и few-shot, стоимость близка к нулю, и она не
затрагивает ни парсер, ни лексер.

## Стадия 2: предупреждение об устаревшем `конец`

План владельца по `конец` состоит из трёх стадий: **1** — принять `конец_X`
(БЛОК 1 v2, сделано), **2** — видеть legacy-закрытия числом, **3** — мигрировать
примеры и корпус (после выкладки 0.1). Здесь — Стадия 2.

**Язык не меняется.** `конец` по-прежнему принимается везде, где принимался:
Стадия 2 ничего не запрещает и не отказывает. Компилятор лишь умеет **сказать**,
что блок закрыт legacy-словом, и назвать канон.

| | |
|---|---|
| **Включение** | `CompileOptions.warnDeprecated` / флаг CLI `--warn-deprecated` (`osnova-compile` и `osnova compile`) |
| **По умолчанию** | **выключено**: корпус и примеры ещё на legacy-закрытиях, шум по умолчанию недопустим |
| **Вес** | информационное: `CompileResult.warnings` не влияет ни на `compilerSuccess`, ни на `BuildReport.success`; код возврата CLI — 0 |
| **Что называет** | блок и каноническое слово: «устаревшее закрытие «конец»: блок «процедура» в каноне v2 закрывается 'конец_процедуры'» |
| **Не срабатывает на** | `конец` в позиции имени (`пусть конец = 5`, `вернуть конец`) — это не закрытие |
| **В CI** | шаг `npm run report:deprecated-end` (информационный отчёт, добавлен в `npm run ci`) |
| **Долг (2026-09-23)** | **149** закрытий `конец` в **19** файлах корпуса (фикстуры + `reg-parity`) |
| **Статус** | **реализовано** (2026-09-23): оракул `src/compiler/deprecatedCloser.test.ts`, негативный контроль — 5 мутаций |

Шаг CI падает **только** если предупреждение сработало без флага: это означало бы,
что сломана развязка «по умолчанию молчит», и её надо ловить сразу, а не при
миграции. Ненулевой долг сам по себе отказом не является — корпус не мигрирован
по решению владельца, и это состояние Стадии 2, а не ошибка.

## БЛОК 3, пункт 9: файл = модуль

Пункт **9** плана (`memory/v2-goal.md` §2, «БЛОК 3 — ломающие, но важные»).
Здесь он приведён потому, что решение по нему принято на **измеренных** данных
корпуса, как и у пунктов §1.x выше, а не по замыслу.

| | |
|---|---|
| **Канон** | **файл = модуль**: один файл — один модуль, имя берётся из имени файла (`привет.osnova` → «привет») |
| **Число случаев** | **68** файлов `.osnova` в корпусе: шапка `модуль имя` — у **68**, `конец_модуля` — у **11**, **шапка без закрытия — у 57**; файлов без шапки — **0** |
| **Что пишет модель** | шапку пишет всегда — в корпусе нет ни одного файла без неё; 49 случаев §1.2 (2026-09-18) — «Ожидается 'модуль'» там, где шапки не было или она была не первой строкой |
| **Предложение** | шапка `модуль имя` **не обязательна**: имя модуля из имени файла. Legacy-форма принимается |
| **Статус** | **реализовано** (2026-09-25): оракул `src/compiler/fileAsModule.test.ts`, **23** проверки; канон — `docs/language-v2.md` §4 |

Развилка, которую решил замер. Буквальное прочтение «шапка `модуль имя` без
`конец_модуля` — ошибка» обрушило бы **57** файлов корпуса и **46** файлов
оракулов, то есть нарушило бы два критерия блока сразу («legacy принимается»,
«npm test — 0 падений»). Решение владельца: это **диагностика по флагу**
(`warnDeprecated` / `--warn-deprecated`, по умолчанию молчит — как Стадия 2), а
жёсткая ошибка оставлена ровно одна и обратного рода:

| запись | поведение |
|---|---|
| шапки нет | компилируется, имя — из имени файла (**канон**) |
| `модуль Имя … конец_модуля` | принимается, имя — из шапки (legacy) |
| `модуль Имя` без закрытия | принимается; **предупреждение** по флагу |
| `конец_модуля` без шапки | **ошибка** с точной причиной: закрытие без открытия |

Приём **совместим**: множество принимаемых программ только выросло, ни одна
прежде компилировавшаяся программа не отвергнута. Единственный отказ
(`конец_модуля` без шапки) был отказом и прежде — с сообщением «Ожидается
'модуль'», которое указывало не туда.

Self-host (`src/self-host/stage1-16`) **не мигрирован**: шапки у него есть,
`конец_модуля` не используется ни разу, и legacy-форма работает. Замер цены
миграции (`stage1.osnova`): компиляция успешна, имена процедур не меняются,
артефакт расходится **одной** строкой — `moduleName`; цена — 20 исходников и 20
артефактов, а описательные имена «Интерпретатор»/«Лексер»/«Кодоген» заменяются
на `stage1`…`stage16`.
