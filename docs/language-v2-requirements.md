# Требования к языку Основа v2 — по измеренным данным

**Статус: документ требований. Ни один пункт не реализован.**
**Дата:** 2026-09-19
**Источники чисел:** `docs/trace-failure-report.md` (замер по `runs/traces.jsonl`),
`.tmp/failure-kind-measure.md` (замер классификатора), `docs/token-cost-report.md`.

## Правило этого документа

Здесь только требования. Парсер, лексер и список алиасов **не тронуты**: до
первого работающего «hello» в QEMU язык не меняется. Каждый пункт — с числом,
с тем, что пишет модель, с тем, что язык принимает сейчас, и с предложением,
которое можно принять или отклонить отдельно.

### Три популяции, к которым относятся числа

Разные числа ниже посчитаны на разных наборах. Смешивать их нельзя, поэтому
каждый пункт указывает свою популяцию.

| популяция | объём | что это |
|---|---:|---|
| **A** | 943 исходника | перекомпиляция сохранённых исходников реальных задач — частоты видов ошибок |
| **B** | 100 прогонов | реальные отказы со статусом `repair_exhausted` — состав отказа |
| **C** | 946 прогонов | реальные задачи целиком — доля успеха |

Контекст: **79,5 %** трейсов — фикстуры (`посчитай сумму от 1 до 10` — 2419 раз,
`задача` — 737, `тест repair-цикла` — 216, `__test__partial__mock__` — 150,
`тест` — 111). На реальных задачах (популяция C) успех **88,4 %**,
`repair_exhausted` **10,6 %**, «собралось, но неверно» — **0,6 %**.

Состав реального отказа (популяция B): парсер **37 %**, исполнение **42 %**,
семантика **14 %**, кодоген **5 %**, лексер **3 %**.

## 1.1. `=` вместо `==`

| | |
|---|---|
| **Число случаев** | **52** (популяция A), крупнейшая одиночная синтаксическая причина |
| **Что пишет модель** | `если список.количество = 0`, `если хранилище = пусто`, `если задача.идентификатор = идентификатор` |
| **Что принимает язык** | только `==`; одиночное `=` — присваивание, в условии даёт «Ожидается выражение, получено: =» |
| **Предложение** | **принимать `=` как `==` в позиции условия** |
| **Статус** | не реализовано |

Обоснование: модель устойчиво тянет `=` из Pascal/SQL, где это сравнение. Это не
случайная опечатка, а след другого языка, и он повторяется 52 раза. Стоимость
приёма — одна ветка в разборе условия; альтернатива (диагностика «в условии
нужно ==») тоже допустима, но оставляет отказ отказом.

## 1.2. Ранний / лишний `конец`

| | |
|---|---|
| **Число случаев** | **63**: 49 × «Ожидается 'модуль'» + 14 × «Ожидается начало следующего модуля или конец файла» (популяция A) |
| **Что пишет модель** | `процедура ДобавитьЗадачу(название, описание)` там, где парсер уже вне модуля; `вернуть пусто` после закрытия модуля |
| **Что принимает язык** | `модуль Имя` → процедуры → `конец`; всё после закрывающего `конец` — ошибка |
| **Предложение** | **диагностика с точной позицией лишнего `конец`**, а не «принимать процедуру после `конец`» |
| **Статус** | не реализовано |

Обоснование: принять процедуру после закрытия модуля — значит разрешить
неоднозначную структуру и потерять возможность отличить «модуль закрыт» от
«модель ошиблась». Правильный ответ здесь — сообщение вида «лишний `конец` на
строке N: модуль уже закрыт на строке M». Сообщение «Ожидается 'модуль'»
указывает не туда, где ошибка.

## 1.3. `:=` из Паскаля

| | |
|---|---|
| **Число случаев** | **20** (популяция A) |
| **Что пишет модель** | `пусть задача := система.объект.создать()`, `пусть список := система.массив.получить(...)` |
| **Что принимает язык** | `пусть x = ...`; `:` читается как аннотация типа, дальше ожидается имя типа, и разбор падает |
| **Предложение** | **алиас `:=` → `=`** |
| **Статус** | не реализовано |

Обоснование: `:=` не конфликтует ни с одной существующей конструкцией — двоеточие
в языке встречается только в аннотации типа и в литералах объектов, где за ним
идёт имя типа, а не `=`. Разбор однозначен. Цена — одна ветка в лексере.

## 1.4. `конец` как имя переменной

| | |
|---|---|
| **Число случаев** | **8** (популяция A) |
| **Что пишет модель** | `суммировать_диапазон(начало, конец)`, `процедура сумма_диапазона(начало, конец)` |
| **Что принимает язык** | `конец` — ключевое слово; в позиции аргумента разбор даёт «Ожидается ')', получено: конец» |
| **Предложение** | **диагностика + подсказка канонического имени** (`конец_диапазона`, `верхняя_граница`) |
| **Статус** | не реализовано |

Обоснование: `конец` — самое естественное русское имя для «end», и модель будет
использовать его всегда. Это дефект выбора ключевого слова, а не поведение
модели. Полное решение (переименовать ключевое слово) ломающе и здесь не
предлагается; минимальное — не выдавать невнятное «Ожидается ')'», а говорить
«`конец` — ключевое слово, переименуй параметр» и подсказывать имя. В языке уже
есть неблокирующий вид `keyword_as_identifier`, но до него разбор не доходит.

## 1.5. Синонимы системных вызовов

| | |
|---|---|
| **Число случаев** | **41** `unknown_syscall` (популяция A); из них: `система.окно.вывод` 6, `система.хранилище.получить` 3, `система.хранилище.получить_элемент` 3, `система.результат.успех`/`.ошибка` 6, `система.строка` 3, `система.хранилище.сохранить` 2, `система.число.остаток` 2, `система.объект.создать` 2, `система.строка.срез` 2 |
| **Что пишет модель** | естественное русское имя вместо канонического |
| **Что принимает язык** | `система.лог.вывести`, `система.хранилище.прочитать`, `система.хранилище.записать`, `система.математика.остаток`, `система.строка.подстрока` |
| **Предложение** | **реестр синонимов**, а не синтаксис: `получить`→`прочитать`, `сохранить`→`записать`, `вывод`→`вывести`, `срез`→`подстрока` |
| **Статус** | не реализовано |

Обоснование: модель **почти не изобретает конструкции — она подставляет
синоним**. Настоящих выдумок ООП мало: `invented_syntax` — 17 против
`unknown_syscall` — 41. Значит лечить надо словарь, а не грамматику: реестр
синонимов не меняет язык и не открывает новых способов ошибиться.

## 1.6. `redeclare_var` — повторный `пусть`

| | |
|---|---|
| **Число случаев** | **82** (популяция A) — самая частая семантическая ошибка |
| **Что пишет модель** | `пусть x = 1`, затем снова `пусть x = 2`; чаще всего на `сообщение`, `цифра`, `строка`, `задачи`, `результат` |
| **Что принимает язык** | первое объявление — `пусть x = ...`, дальше только `x = ...` |
| **Предложение** | **правило в промпте кодогенерации**, а не ослабление языка |
| **Статус** | не реализовано |

Обоснование: компилятор уже формулирует правило точно («используй просто
`x = ...`»), то есть язык здесь ни при чём — правило просто не видно модели
заранее. Это правка промпта и few-shot, стоимость близка к нулю, и она не
затрагивает ни парсер, ни лексер.

## Что этим документом НЕ предлагается

- Не менять ключевые слова (`для_каждого`, `иначе_попытка`) — отдельное решение,
  см. `docs/token-cost-report.md`: выигрыш есть, но трогает канон и датасет.
- Не вводить VLIW-конструкции, регионы, эффекты в синтаксис.
- Не добавлять алиасы каких-либо слов сверх перечисленных в 1.3.
- Не менять семантику (`/`, `%`, `pop`).
- Не трогать парсер и лексер до первого работающего «hello» в QEMU.
