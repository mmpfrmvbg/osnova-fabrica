# Golden-приложение: Micro-CRM (список клиентов)

Приложение категории **crm** для golden-теста: агрегации по массиву объектов, условия с логическими **`и`** / **`или`**, работа с хранилищем. Использует только существующий рантайм-API (без новых invoke).

## Идентификация

- **id:** `osnova.micro_crm`
- **Категория:** `crm` (реестр приложений, `registry-v0.1.md`)
- **Манифест:** `src/tools/osnova-runtime/fixtures/micro_crm.osapp.yaml`
- **Модуль:** `micro_crm.osnova` → `micro_crm.osvbc.json`

## Точка входа для golden-теста

- **Процедура:** `run_golden(клиенты)`
- **Аргументы:** один массив объектов; каждый объект — поля `имя`, `баланс`, `статус` (например `"активен"`, `"закрыт"`, `"новый"`).

В манифесте заданы `entry.procedure: "run_golden"` и `entry.args`: массив из четырёх клиентов (А 10 активен, Б 20 активен, В 30 закрыт, Г 5 новый).

## Конструкции языка, которые проверяет

- **`для_каждого`** — обход массива событий в `запуск()` и обход массива клиентов во всех агрегирующих процедурах.
- **`и`** — составное условие в `баланс_активных`: «статус == "активен" и баланс > 0».
- **`или`** — составное условие в `количество_активных_или_новых`: «статус == "активен" или статус == "новый"».
- **Работа с объектами** — `система.объект.получить(к, "баланс")`, `система.объект.получить(к, "статус")`.
- **Хранилище** — запись результатов через `система.хранилище.записать` (ключи см. ниже).

## Процедуры модуля

| Процедура | Назначение |
|-----------|------------|
| `запуск()` | Окно, цикл по событиям через `для_каждого э в события`. |
| `подсчитать_баланс(клиенты)` | Сумма поля `баланс` по всем клиентам. |
| `количество_активных(клиенты)` | Счётчик клиентов с `статус == "активен"`. |
| `баланс_активных(клиенты)` | Сумма `баланс` только у клиентов с `статус == "активен" и баланс > 0`. |
| `количество_активных_или_новых(клиенты)` | Счётчик клиентов с `статус == "активен" или статус == "новый"`. |
| `run_golden(клиенты)` | Вызывает все четыре агрегации и записывает результаты в хранилище. |

## Ожидаемые ключи хранилища и значения (golden)

При запуске с тестовыми данными манифеста (4 клиента: А 10 активен, Б 20 активен, В 30 закрыт, Г 5 новый) после `run_golden(клиенты)` в хранилище приложения `osnova.micro_crm` должны быть:

| Ключ | Ожидаемое значение | Пояснение |
|------|--------------------|-----------|
| `total_balance` | `"65"` | 10 + 20 + 30 + 5 |
| `active_count` | `"2"` | А, Б |
| `balance_active` | `"30"` | 10 + 20 (только активные с балансом > 0) |
| `active_or_new_count` | `"3"` | А, Б, Г (активен или новый) |

Проверка выполняется в `goldenApps.ts` функцией `runMicroCrmApp()`: запуск по манифесту, чтение этих ключей, при расхождении — `throw Error(...)`.

## Зависимости API

- `система.окно`: создать_окно, показать, закрыть, получить_события
- `система.интерфейс`: текст (минимальный UI в `запуск`)
- `система.хранилище`: записать
- `система.массив`: длина, получить
- `система.объект`: получить
- `система.строка`: объединить (для записи числа в хранилище)
- `система.время`: спать

## Запуск

**Golden-тест (автоматически в `npm run osnova-golden:apps`):**
```bash
npm run osnova-golden:apps
```
Вызывается `runMicroCrmApp()`: запуск с `--manifest fixtures/micro_crm.osapp.yaml`, проверка хранилища.

**Вручную:**
```bash
npx tsx src/tools/osnova-runtime/cli.ts run \
  --manifest src/tools/osnova-runtime/fixtures/micro_crm.osapp.yaml \
  --ui cli
```

## Использование в LLM-пайплайне

Micro-CRM можно использовать как пример категории **crm**: генерация по спекам типа «список клиентов, фильтрация по статусу, суммарный баланс» с опорой на реестр языка (`для_каждого`, `и`/`или`, работа с объектами и хранилищем). См. `pipeline-v1.md`, `language-v2.md` и `osnova/language-schema.json`.
