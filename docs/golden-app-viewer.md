# Golden-приложение: File Viewer (ОСи)

Второе «реальное» OS-nova-апп для golden-теста рантайма ОСи: окно, файловый ввод/вывод, хранилище и статусная строка.

---

## Поведение

- **Окно** «File Viewer» 400×300.
- **Виджеты:**
  - Поле ввода пути к файлу (подсказка, например, «Путь к файлу»).
  - Кнопка «Открыть».
  - Текстовый статус под кнопкой.
  - Большая текстовая область с содержимым файла.
- **Первый запуск:**
  - Из `система.хранилище` читается ключ `last_path`.
  - Если ключ отсутствует или путь пустой:
    - В статусе отображается «Файл не выбран».
    - Текстовая область пуста.
  - Если путь есть:
    - Если `система.файлы.существует(last_path)` возвращает `false`:
      - Статус: «Файл не найден».
      - Текстовая область пуста.
    - Если `true`:
      - `система.файлы.прочитать_все(last_path)` загружает содержимое.
      - В текстовой области показываются первые N строк/символов (конкретный лимит можно описать в отдельной спеки, для golden-теста достаточно факта, что содержимое появляется).
      - Статус: «OK».
- **Кнопка «Открыть»:**
  - По клику приложение:
    - Берёт путь из поля ввода (через `система.интерфейс.получить_значение`).
    - Если строка пустая:
      - Статус: «Файл не выбран».
      - Текстовая область остаётся без изменений.
    - Иначе:
      - Проверяет `система.файлы.существует(путь)`:
        - Если `false`:
          - Статус: «Файл не найден».
          - Содержимое в области не меняется.
        - Если `true`:
          - Читает `система.файлы.прочитать_все(путь)`.
          - Записывает путь в `система.хранилище.записать("last_path", путь)`.
          - Обновляет текстовую область содержимым файла.
          - Статус: «OK».
- **Закрытие окна:**
  - При событии «закрытие» окна приложение вызывает `система.окно.закрыть` и завершает процедуру `запуск`, процесс выходит с кодом 0.

---

## Зависимости API

- `система.окно`: `создать_окно`, `показать`, `закрыть`, `получить_события`.
- `система.интерфейс`: `поле_ввода`, `кнопка`, `текст`, `область_текста`, `получить_значение`, `установить_значение`.
- `система.файлы`: `существует`, `прочитать_все`.
- `система.хранилище`: `прочитать`, `записать`.
- `система.массив`: `длина`, `получить` — перебор событий окна.
- `система.объект`: `получить` — чтение полей `тип`, `виджет_id` и т.п. у события.
- `система.строка`: `объединить` — при необходимости конкатенации строк (например, заголовков/сообщений).
- `система.время`: `спать` — при реализации «мягкого» цикла событий (как в TODO-приложении).

## Запуск

**С окном (полное поведение):**

```bash
npx tsx src/cli.ts run --manifest src/runtime/fixtures/file-viewer.osapp.yaml --ui window
```

- Откроется браузер с окном «File Viewer».
- При первом запуске без `last_path` статус «Файл не выбран», область пустая.
- Если заранее положить тестовый файл (например, в `~/Документы`) и ввести его путь, при клике «Открыть» статус станет «OK», а текстовая область покажет содержимое.
- При повторном запуске с тем же манифестом приложение читает `last_path` из хранилища и автоматически подставляет последний открытый путь.

**Без окна (проверка загрузки и цикла):**

```bash
npx tsx src/cli.ts run --manifest src/runtime/fixtures/file-viewer.osapp.yaml --ui cli
```

- Окно не открывается, `получить_события` возвращает `[]`.
- Golden-тест может запускать приложение в этом режиме только для проверки корректности загрузки манифеста и байткода.

## Ожидаемый артефакт для golden-теста

- **Манифест:** `src/runtime/fixtures/file-viewer.osapp.yaml`
  - `id: "osnova.viewer"`.
  - `entry.module: "viewer"`, `entry.procedure: "запуск"`.
  - `ui.kind: "window"`.
  - `permissions.files.read: ["~/Документы"]`, `write: []`.
  - `network.outbound: false`.
- **Байткод:** `src/runtime/fixtures/viewer.osvbc.json`
  - `moduleName: "viewer"`.
  - `procedures`:
    - `запуск(codeOffset=0)` — инициализация окна и виджетов, чтение `last_path` из хранилища, первый рендер статуса и текстовой области, основной цикл обработки событий.
    - `handle_event(codeOffset>0)` — обработка одного события:
      - если `тип == "закрытие"` → закрыть окно и выйти;
      - если `тип == "клик_виджета"` и `виджет_id` соответствует кнопке «Открыть» → вызвать `open_path`.
    - `open_path(codeOffset>handle_event)` — функция:
      - читает путь из поля ввода;
      - проверяет существование файла;
      - при успехе читает содержимое, обновляет хранилище и область; при ошибке обновляет статус.
  - Поле `code` может быть минимальным или пустым на этапе v0.1; golden-док фиксирует логическую ответственность участков кода, чтобы в будущем проверять реальный байткод по паттернам (например, наличие вызовов `система.файлы.существует` и `прочитать_все` в `open_path`).

## Связь со спецификацией invoke

File Viewer опирается на уже описанный системный API (`system-api-v1.md`).

- Файлы: `система.файлы.существует`, `система.файлы.прочитать_все`.
- Хранилище: `система.хранилище.прочитать`, `система.хранилище.записать`.
- GUI: `система.окно.*` и `система.интерфейс.*`.
- Вспомогательные операции с массивами/объектами/строками.

Таким образом, вместе с TODO-приложением File Viewer образует минимальный, но реалистичный набор golden-приложений, покрывающих:

- события и окно,
- хранилище между запусками,
- файловый ввод/вывод в песочнице ОСи.
