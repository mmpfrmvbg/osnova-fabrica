# CI/CD: контур, границы и запуск

> Источник истины — [`.gitverse/workflows/full-ci.yaml`](../.gitverse/workflows/full-ci.yaml).
> Этот документ объясняет, почему уровни устроены именно так и что считается
> доказательством, а не пересказывает YAML.

## Один контур, четыре уровня

| Уровень | Где | Что доказывает | Когда |
|---|---|---|---|
| **L1** | `ubuntu-latest`, Node 20 | lock ставится, код собирается, полный `npm run ci` зелёный | push, PR в `master`, ручной запуск |
| **L2** | self-hosted Windows + WSL | QEMU-e2k исполняет байты: `npm run gate:qemu` | push, ручной запуск |
| **L3** | живая E8C2 по SSH | кит совпал с эталоном на железе: 38/38 | push, ручной запуск |
| **release** | `ubuntu-latest` | тег `vX.Y.Z` совпал с `package.json`, пакет собран, L1/L2/L3 зелёные | тег `v*` |

PR-прогоны не получают секреты E8C2: L2 и L3 в PR пропускаются. L1 секретов не
требует.

## L1: полный, а не «быстрый» гейт

L1 не дублирует шаги вручную. Он вызывает тот же `npm run ci`, что и разработчик:
типы, тесты, lint, YAML-дрейф, документация, golden, reorder, spec, coverage.
Отдельно вызывается `npm run build`, потому что `ci` проверяет типы, но не
собирает `dist/`.

Перед этим `npm run check:ci` проверяет сам контур: workflow лежит в
`.gitverse/workflows/`, L2 не подменён на `ubuntu-latest`, L3 использует
`ci-run.sh`, release зависит от всех трёх уровней, в секретах нет запрещённого
префикса `GITVERSE_`, скрипты исполняемые и не содержат `|| true`, а в lock есть
пакеты, без которых `npm ci` на Node 20 падает.

## L2: почему Windows self-hosted

QEMU-тесты этого проекта запускают `C:\Program Files\WSL\wsl.exe` и ищут
`/root/qemu-build/qemu-e2k`. Это не переносится на облачный Linux без переписывания
тестов. Поэтому L2 честно требует раннер с метками:

```text
self-hosted, windows, x64
```

Пока раннера нет, job стоит в очереди, а release не запускается: зависимость
`release` от L2 намеренная, иначе тег мог бы стать релизом без проверки QEMU.

## L3: железо и секреты

L3 запускает `tools/e2k-hardware/ci-run.sh`, а не `run.sh` напрямую. Причина:
`run.sh` всегда возвращает 0 и печатает итог текстом. `ci-run.sh` разбирает итог и
требует одновременно:

```text
совпало == числу строк expected.tsv
расхождений == 0
файлов нет == 0
```

Любое несовпадение делает job красным. Перед прогоном кит пересобирается, а
`expected.tsv` сверяется с git: если генератор и манифест разошлись, это ошибка,
а не «свежая сборка».

Секреты (уровень репозитория):

| Имя | Смысл |
|---|---|
| `E2K_SSH_KEY` | приватный ключ к E8C2, не ключ GitVerse для git push |
| `E2K_HOST` | хост E8C2 без `ssh://` и порта |
| `E2K_USER` | пользователь E8C2 |
| `E2K_PORT` | SSH-порт E8C2 |
| `RELEASE_API_KEY` | токен GitVerse API с доступом к репозиториям, только для release |

Имя `GITVERSE_API_KEY` из примеров GitVerse использовать нельзя: префикс
`GITVERSE_` запрещён правилами имён секретов.

## Release: тег — это контракт

Release запускается только на `v*` и требует, чтобы версия из тега совпала с
`package.json`. Проверяются L1, L2 и L3, собирается `dist/osnova-fabrica.tgz`,
рядом кладётся `SHA256SUMS`, оба файла уходят в релиз.

Тег, который не совпал с версией, — красный job, а не релиз с чужим номером.

## Локально

```bash
sh scripts/ci-local.sh              # L1 полностью
sh scripts/ci-local.sh --qemu       # L1 + QEMU, нужен Windows/WSL
sh scripts/ci-local.sh --hardware   # L1 + E8C2, нужны E2K_* и SSH_KEY_PATH
sh scripts/ci-local.sh --all        # всё доступное
```

`ci-local.sh` ставит зависимости через `npm ci`, поэтому запускать его нужно в
чистом дереве или понимать, что `node_modules` будет пересобран.

## Диагностика

| Симптом | Причина | Действие |
|---|---|---|
| `npm ci` требует `@emnapi/*` | lock собран npm 11 / Node 24 | пересобрать lock через `npm@10`, не npm 11 |
| L2 висит в очереди | нет self-hosted Windows-раннера | зарегистрировать раннер с метками `self-hosted`, `windows`, `x64` |
| L3 красный на SSH | не тот ключ, порт 22 вместо 8194, хост с `ssh://` | проверить секреты; ключ E8C2, не GitVerse |
| L3 «расхождений N» | байты или вывод не совпали | смотреть артефакт `e8c2-report`, не перезапускать «до зелёного» |
| release не стартует | нет тега `v*` или L2/L3 не зелёные | сначала пройти все три уровня |

## Границы

- GitVerse читает `.gitverse/workflows/`; корневой `.gitverse-ci.yml` не
  используется.
- GitVerse также обрабатывает `.github/workflows/`; старые GitHub-workflow могут
  давать отдельные прогоны. Это не L1/L2/L3 этого контура.
- Облачный job ограничен 15 минутами; L1 укладывается в него полным `npm run ci`.
- Публичная витрина синхронизируется отдельно, через `scripts/sync-public.sh`, и
  не является зеркалом приватного дерева.
