# ОС-НОВА: Видение и Стратегия

**Версия:** 1.0  
**Дата:** 2026-03-21  
**Статус:** живой документ — редактируется только вручную

---

## Одна фраза

Платформа где весь возможный софт существует в единственном
экземпляре, собирается из компонентов и распространяется
через единый магазин приложений на языке Основа.

---

## Проблема которую мы решаем

Сегодня каждое приложение пишется с нуля.
CRM для стоматологии и CRM для автосервиса — это два разных
продукта, две команды, два бюджета. Хотя внутри 80% одинаково:
база данных, авторизация, таблицы, уведомления, отчёты.

Этот дубль — потеря. Для рынка, для пользователей, для денег.

---

## Что мы строим

**Магазин приложений** — оболочка (не полноценная ОС пока).
Пользователь скачивает приложения как в App Store / Google Play.

**Язык Основа** — единый язык на котором написан весь софт
в магазине. Русский синтаксис, жёсткие контракты, предсказуемая
компиляция. Один язык = компоненты совместимы между собой.

**Компонентный реестр** — каждая функция существует один раз:
- `auth` — авторизация
- `db` — база данных
- `ui.table` — таблица с данными
- `ui.form` — форма ввода
- `notifications` — уведомления
- `reports` — отчёты
- `calculator` — вычисления
- и так далее

**Фабрика** — система которая генерирует новый софт:
1. Смотрит что уже есть в реестре
2. Генерирует только недостающие компоненты
3. Компонует приложение из готовых блоков
4. Публикует в магазин

---

## Главная метрика
Покрытие = (приложения которые можно собрать сейчас)
/ (все возможные приложения)

text

Система сама измеряет покрытие и сама решает что писать дальше —
не потому что кто-то сказал, а потому что это максимально
увеличивает покрытие.

---

## Как фабрика решает что делать
Реестр компонентов
│
▼
Анализ: каких компонентов не хватает?
│
▼
Граф зависимостей: какой компонент разблокирует
больше всего новых приложений?
│
▼
Фабрика генерирует этот компонент
│
▼
N новых приложений становятся возможными
│
▼
Повторить

text

Никакого ручного управления. Только метрики и граф.

## Чего НЕТ в этом видении

- Нет "клиент заказывает приложение" — это B2C магазин, не аутсорс
- Нет уникального кода под каждого — только компоновка из реестра
- Нет ручного написания компонентов людьми — только фабрика
- Нет зависимости от конкретного LLM — фабрика работает с любым

---

## Текущий этап (2026)

Мы строим фабрику — станок который умеет генерировать
компоненты на языке Основа с высоким качеством.
Сейчас: фабрика учится генерировать отдельные программы
Следующий: фабрика генерирует переиспользуемые компоненты
После: фабрика компонует приложения из реестра
Финал: магазин приложений, фабрика работает автономно

text

Все текущие метрики (teachability, success_rate, sentinel_rate,
RFC-correctness) — это метрики качества станка.
Станок должен работать надёжно прежде чем строить на нём магазин.

## Северная звезда для агентов

Любое решение в системе оценивается одним вопросом:

> **Приближает ли это к тому чтобы фабрика могла
> сгенерировать любой компонент надёжно и без ошибок?**

Если да — делаем.
Если нет — откладываем.
