# Язык Основа v2.3.2 — спецификация

Канон языка определяется реализацией в `src/compiler/**` и `src/runtime/vm/**`.
Этот документ описывает только то, что подтверждено кодом.

## 1. Введение

Основа — русскоязычный язык для компиляции в байткод VM:

`исходник .osnova -> tokenize -> parse -> semantic -> codegen -> .osvbc -> VM`.

Целевая платформа проекта: стековая VM; архитектурный таргет проекта — VLIW/e2k.

## 2. Базовые элементы

### 2.1 Лексика

- Идентификаторы: кириллица/латиница, `_`, цифры после первого символа.
- **Имя не может совпадать с зарезервированным словом** (§2.2) — ни целиком, ни
  регистром: `пусть и = 1` не разбирается, компилятор отвечает «Ожидается
  выражение, получено: и». Проверено прогоном на живом примере корпуса
  (2026-09-26): имя `и` было выбрано для счётчика цикла по привычке к латинице, и
  программа не собралась — ошибка объяснимая, поэтому она названа здесь и в
  учебнике (`docs/tutorial/15-faq.md`). Опасны короткие русские слова: `и`,
  `в`, `не`, `из`, `есть`, `цикл`, `пусто`.
- Комментарии: `//` до конца строки и `/* ... */`.
- Алиасы для моделей (канон всё равно русский): `let`→`пусть`, `if`→`если`, `true`→`истина`, `&&`→`и`, `===`→`==` и др. (`LLM_KEYWORD_ALIASES`).
- Цепочечные сравнения `a < x < b` → `(a < x) и (x < b)`.
- `+` склеивает, если хотя бы один операнд строка.
- Токен `|` — разделитель вариантов перечня.
- Литералы:
  - числа: целые и десятичные;
  - строки: `"..."` с escape (`\n`, `\r`, `\t`, `\"`, `\\`);
  - булевы: `истина`, `ложь`;
  - null: `пусто`;
  - массив: `[ ... ]`;
  - объект: `{ ключ: значение, ... }`;
  - перечень: `Имя.вариант` (в VM — строка `"Имя.вариант"`).

### 2.2 Зарезервированные слова (implemented)

`модуль`, `процедура`, `тип`, `использовать`, `экспорт`, `из`, `пусть`, `если`,
`иначе`, `иначе_если`, `пока`, `попробовать`, `поймать`, `выбросить`,
`для`, `в`, `цикл`, `прервать`, `продолжить`, `конец`, `вернуть`,
`истина`, `ложь`, `пусто`, `и`, `или`, `не`, `тогда`, `когда`, `есть`.

**Алиасы** (принимаются, но канон — слева): `иначе_попытка` → `поймать`,
`для_каждого` → `для`, `for` → `для`, `catch` → `поймать`. Английские
подстановки — в реестре (`LLM_KEYWORD_ALIASES`).

> **Поправка 2026-10-09 (замер, а не пожелание).** Список выше перечисляет слова, у которых есть
> СЛУЖЕБНАЯ роль; он не запрещает их как **имена**. В позиции имени `конец` работает обычным именем
> (см. §11, «контекстный токен»): `тип Отрезок { начало: Точка, конец: Точка }`, `{ конец: 2 }`,
> `о.конец`. Эталон v2 (`src/compiler/parser.ts`, `isFieldNameToken`) держит это с самого начала;
> парсер v3 и исполняемая спецификация (`src/spec/osnova-spec.ts`) — с 2026-10-09
> (`этИмяПоля`: после `{`, `,` и `.` годится и ключевое слово). Измеренная ГРАНИЦА: имена **типа**
> (`тип конец { … }`) и **процедуры** (`процедура конец()`) ключевым словом отвергают обе
> плоскости; имя **переменной** и **параметра** эталон v2 принимает (`пусть конец = 5` → значение
> 10), v3 — пока нет: расхождение названо и закреплено тестом
> (`src/compiler-v3/astEquivalence.test.ts`, «ИЗВЕСТНОЕ РАСХОЖДЕНИЕ»).

## 3. Типы

### 3.1 Значения времени выполнения (VM `StackValue`)

- `number`
- `string`
- `boolean`
- `null`
- `Record<string, unknown>` (объект)
- `StackValue[]` (массив)

### 3.2 Аннотации типов в языке

- Поддержан синтаксис `тип Имя { поле: Тип, ... }` (запись).
- Поддержан перечень: `тип Имя = вариант1 | вариант2 | …`.
- Поддержан nullable-префикс: `?Тип`.
- Поддержана аннотация переменной: `пусть x: Тип = ...`.
- Поддержаны типы параметров: `процедура f(x: Тип)`.
- Поддержана аннотация возврата: `процедура f(x: Тип): Тип`.
- Тип возврата процедуры без аннотации выводится из `вернуть` (если все возвраты
  одного типа); вызов такой процедуры даёт её тип возврата.
- Литерал перечня: `Масть.пики` (квалифицированный; в байткоде — строка).
- На этапе `validateNamedTypesAndRewrite` (v2.1):
  - неизвестное поле у типизированной записи — ошибка;
  - несовпадение `Число`/`Строка`/`Логический`/перечень/запись/`[T]` — ошибка;
  - `вернуть` несовпадающего типа (против аннотации или вывода) — ошибка;
  - неизвестный тип поля / несуществующий тип — ошибка;
  - неаннотированные переменные остаются дырявыми (gradual).

### 3.3 Массив как тип

Отдельного ключевого слова `массив` в синтаксисе типа нет.
Массив вводится:

- литералом `[]`/`[a, b, c]`;
- аннотацией `[Тип]` в поле/`пусть`;
- системными вызовами `система.массив.*`.

### 3.4 Ещё нет в компиляторе

- контекстный `и` как имя после `пусть`.

### 3.5 Вызов: семантика исходника, не стека (v2.3)

Исходник задаёт, живёт ли результат:

- вызов как **выражение** (`пусть n = система.массив.длина(a)`, условие `если`) — одно значение;
- вызов как **инструкция** (`система.массив.добавить(a, x)`, `игра.очистить(...)`) — эффект, без значения.

Компилятор снимает неиспользованный результат (`pop`). VM после каждого `invoke` кладёт ровно одно значение (`null`, если обработчик ничего не вернул). Пользовательская процедура, которая дошла до `конец` без `вернуть`, тоже кладёт `пусто` (v2.3.2) — иначе `pop` после вызова-инструкции роняет стек. Мутирующие `система.массив.добавить` / `установить` / `удалить` по-прежнему возвращают `null`, не массив.

### 3.6 `когда` (v2.2)

Разбор перечня с исчерпыванием. Компилятор разворачивает в `если` / `иначе_если`.

```osnova
когда карта.масть
  есть Масть.пики
    вернуть 1
  есть Масть.черви
    вернуть 2
конец
```

Если не все варианты названы — ошибка, пока нет ветки `иначе`.

Горизонт школы: `.cursor/skills/osnova-lang/цель.md`.

## 4. Модульная система

**Файл = модуль (БЛОК 3, пункт 1).** Один файл — один модуль. Шапка
`модуль Имя` каноном больше не является и **не обязательна**: имя модуля берётся
из имени файла — `привет.osnova` → модуль «привет», `todo_service.osnova` →
модуль «todo_service» (снимается каталог и расширение `.osnova`, регистр
расширения не важен). Без имени файла (разбор безымянного источника) модуль
называется `вход`.

Имя файла переносится в имя модуля **как есть**, без преобразований: дефис в имени
файла станет дефисом в имени модуля. Именно поэтому имена файлов ограничены
(§13.3) — правило пока не реализовано, и до его ввода дефис в имени остаётся
опасным.

```osnova
процедура главная()
  вернуть 0
конец_процедуры
```

Legacy-форма **принимается**: шапка `модуль Имя` по-прежнему объявляет имя
модуля, и тогда имя берётся из неё, а не из файла. Закрытие при шапке
**необязательно** — `конец_модуля` или legacy-`конец`, либо ничего.

| запись | что это | поведение |
|---|---|---|
| шапки нет | **канон**: файл = модуль | компилируется, имя — из имени файла |
| `модуль Имя … конец_модуля` | legacy | принимается, имя — из шапки |
| `модуль Имя` без закрытия | legacy-толерантность | принимается; предупреждение по флагу |
| `конец_модуля` без шапки | **смешение**: закрытие без открытия | **ошибка** с точной причиной |

- Различие `конец_модуля` и одиночного `конец` в файле-модуле не косметическое:
  `конец_модуля` **называет** модуль, то есть утверждает «модуль объявлен
  шапкой», и в файле-модуле это утверждение ложно. Одиночный `конец` имени не
  называет и остаётся принимаемым legacy-закрытием (как и везде после БЛОК 1 v2).
- Шапка без закрытия — **предупреждение** (`warnDeprecated` /
  `--warn-deprecated`, по умолчанию выключено), а не ошибка: замер 2026-09-19 —
  из 68 файлов корпуса шапка есть у всех 68, а `конец_модуля` только у 11, то
  есть **57 файлов модуль не закрывают**. Ошибка здесь обрушила бы корпус.
- Приём **совместим**: программы, которые компилировались раньше, компилируются и
  теперь (шапка принимается). Новый отказ ровно один — `конец_модуля` без шапки;
  прежде он тоже был отказом, только с сообщением «Ожидается 'модуль'».
- **Пустой файл — пустой модуль.** Пустой источник, одни переводы строк или одни
  комментарии (оба вида) дают модуль с именем из имени файла и пустым телом:
  сборка успешна, диагностик нет. Прежде это был отказ **без единой диагностики**
  (модулей ноль, AST `null`, все фазы молчат) — отказ, по которому нельзя понять,
  что не так. Это следствие «файл = модуль», а не отдельное правило: у файла,
  который является модулем, пустое тело — законное тело. Постороннее слово в файле
  и `конец_модуля` без шапки по-прежнему отвергаются с диагностикой.
- **Импорт**: `использовать модуль Namespace из "path.osnova"`. Имя модуля
  импортируемого файла берётся из имени **этого** файла, а не входного.
- **Экспорт процедур**: `процедура экспорт имя(...)`.
- Типы из импортированного файла видны в текущем. Два разных файла с одним
  `тип Имя` — ошибка (оба пути в сообщении). Один файл, импортированный дважды
  (ромб), не дубликат. Два `тип Имя` в одном файле — ошибка.
- Ошибка разбора импортированного файла указывает этот файл и строку, не вход.
- `compileSource({ filename })` — имя входа: им же определяется имя модуля, когда
  шапки нет.
- Ограничения текущей реализации:
  - в одном исходном файле может быть несколько модулей — если у них есть шапки
    (`модуль A … модуль B …`); в файле-модуле (без шапки) модуль один;
  - импорт разрешен только в начале модуля (до процедур);
  - `тип` разрешен только до процедур;
  - точка входа программы выбирается из первого модуля в порядке объявления в файле.

Примечание: `compileSource` поддерживает межфайловые импорты через инлайн
экспортированных/внутренних процедур импортируемого модуля в единый AST.

## 6. Выражения

### 6.1 Базовые выражения

- Литералы: число, строка, `истина`, `ложь`, `пусто`.
- Переменная: `имя`.
- Бинарные операции: `+ - * / % div == != < <= > >=`.
  - **`+` склеивает строки.** Если хотя бы один операнд — строка, `+` даёт строку:
    `"Всего: " + 7` → `"Всего: 7"`, `"готово: " + истина` → `"готово: истина"`.
    Значения при склейке печатаются по-основски: логические — словами `истина` /
    `ложь`, `пусто` — словом `пусто`, массив и объект — в JSON. Отдельный вызов
    `система.строка.объединить(а, б)` делает то же самое, но принимает **ровно два**
    аргумента, поэтому для трёх частей его вкладывают друг в друга.
  - **`/` — ВЕЩЕСТВЕННОЕ деление, а не целочисленное.** Проверено прогоном
    (2026-09-15): `(3 * 20 + 2 * 6) / 5` даёт `14.4`, и IIR-ядро
    (`tests/dsp/kernels/iir.osnova`) на наивной записи вернуло `121.0656` вместо
    `119`. Историческая замена — через остаток:
    `(a - система.математика.остаток(a, b)) / b`; с БЛОК 2 для этого есть оператор.
  - **`div` — целочисленное деление, отсечение К НУЛЮ** (БЛОК 2, 2026-09-23):
    `10 div 3 = 3`, `(0 - 7) div 3 = -2`, `7 div (0 - 3) = -2`, делитель `0` —
    ошибка исполнения. Правило округления записано не «на глаз»: оно согласовано с
    `%` (тождество `a div b * b + a % b == a` выполняется при любых знаках) и
    совпадает с формой e2k `SDIVs` (руководство МЦСТ §10.3.3 — отсечение к нулю),
    поэтому понижение в неё не требует менять семантику. Floor дал бы в языке
    третье правило округления, которого не требует ни `/`, ни `%`.
    **Почему не `//`:** `//` — комментарий до конца строки, и `10 // 3` молча даёт
    `10` (замер по журналу: 3675 исходников, `//` после кода — 4 случая, все
    пояснения; `div`/`дел`/`цел_деление` — ноль). Русское `цел_деление` —
    **алиас** к `div` (`LLM_KEYWORD_ALIASES`), как `for` к `для`.
  - **`%` — остаток с усечением к нулю (знак результата — знак делимого).** Измерено
    прогоном (2026-09-15): `7 % 3 = 1`, `(0 - 7) % 3 = -1`, `7 % (0 - 3) = 1`,
    `(0 - 7) % (0 - 3) = -1`. Это семантика C/JS, а **не** Python: в Python `-7 % 3 = 2`.
    С `div`, округляющим к нулю, пара `div`/`%` согласована и при отрицательных
    операндах.
- Логические: `и`, `или`, `не` (в кодогене short-circuit для `и`/`или`).
- Скобки: `(expr)`.

### 6.2 Переменные и присваивание

- Объявление: `пусть x = expr` (опционально с типом: `пусть x: Тип = expr`).
- Присваивание: `x = expr`.
- **Алиас `:=`** (из Паскаля): `пусть x := expr` и `x := expr` эквивалентны `=`
  (пункт 1.3 требований: 20 случаев). Двоеточие в языке только в аннотации типа и
  в литералах объектов, где за ним идёт имя типа, поэтому разбор однозначен.
  В machine-readable каноне `::=` — **метаданные оператора `=`**
  (`operators[].aliases`), а не отдельный оператор: отдельная запись означала бы
  отдельный вид токена, а лексер сводит `::=` к `=`.
- Составное присваивание:
  - `x += expr`, `x -= expr`, `x *= expr`, `x /= expr`.

### 6.3 Объекты

- Литерал: `{ поле: expr, поле2: expr }`.
- Доступ: `obj.поле`.
- Присваивание полю:
  - `obj.поле = expr`
  - `obj.поле += expr` (и `-=`, `*=`, `/=`).

### 6.4 Массивы и sugar

- Литерал `[a, b, c]` парсится как AST `kind: "массив"`.
- В codegen массив-литерал разворачивается в:
  - `система.массив.создать`
  - серия `система.массив.добавить`.
- `arr[i]` парсится как вызов `система.массив.получить(arr, i)`.
- `arr[i] = v` парсится как вызов `система.массив.установить(arr, i, v)`.
- `объект.поле[i] = v` — то же, массив берётся из поля (`мир.поле[i] =`).
- `объект.поле[i].ключ = v` — запись в элемент-запись.
- `arr[i] op= v` разворачивается в
  `получить(arr, i) -> op -> установить(arr, i, result)`.

### 6.5 Вызовы

- Пользовательская процедура: `имя(...)`.
- Пространство имен / системный вызов: `namespace.имя(...)`, включая `система.*`.

## 7. Управляющие конструкции

**Закрывающее слово называет свой блок (БЛОК 1 v2).** Канон — `конец_<что>`;
legacy-`конец` остаётся и закрывает блок по контексту.

| Конструкция | Канон закрытия |
|---|---|
| `если`/`иначе_если`/`иначе` | `конец_если` |
| `пока` | `конец_пока` |
| `для` (алиас `для_каждого`) | `конец_для` (полная форма `конец_для_каждого`) |
| `цикл` | `конец_цикла` |
| `когда` | `конец_когда` |
| `попробовать`/`поймать` | `конец_попробовать` |
| `процедура` | `конец_процедуры` |
| `модуль` (legacy-шапка) | `конец_модуля` |

- **`=` как `==` в позиции условия** (пункт 1.1 требований: 52 случая): там, где
  ожидается **булево** выражение, — после `если`, `иначе_если`, `пока` — одиночный
  `=` читается как `==` (`если x = 5` ≡ `если x == 5`), включая вложенные вызовы в
  том же условии. Булевых позиций в языке ровно три (аудит `parseCondition`), и все
  три покрыты.
  **`когда` в их число не входит:** его голова — значение для сопоставления
  (AST-поле `scrutinee`, реестр `match_when` — «разбор перечня по вариантам»), а
  ветка `есть` обязана быть литералом перечня `Имя.вариант`
  (`compilerError`: «когда: в есть нужен литерал перечня Имя.вариант»), поэтому
  булева сопоставления в `когда` не существует и включать `=` там нечего.
  Вне условия `=` — присваивание; в выражении (например, в аргументе вызова) это
  ошибка (граница зафиксирована тестом).
- Несовпадение закрытия — ошибка: `конец_пока` не закрывает `если`
  («Закрытие не совпадает: блок «если» закрывается 'конец_если' или 'конец'»).
- Инвариант: программа с `конец` даёт **тот же байткод**, что с `конец_X`
  соответствующего блока (оракул `src/compiler/blockClosers.test.ts`).
- `конец` — **контекстный** токен, а не зарезервированное слово: в позиции имени
  он работает как обычное имя (`тип Объект = { конец: Число }`, `о.конец`,
  `процедура f(начало, конец)`).
  В выражении `конец` — тоже имя: `вернуть конец` возвращает переменную. Значение
  `вернуть` берётся с той же строки, пустой `вернуть` + `конец` следующей строкой —
  это пустой возврат и закрытие блока.
- `конец_файла` — вид токена, а не ключевое слово; слово `конец_файла`
  в исходнике блок не закрывает.
- Ветвления:
  - `если ...`
  - `иначе_если ...`
  - `иначе ...`
  - `конец_если` (или legacy `конец`)
  - `тогда` после условия — опционально.
- Циклы:
  - `пока условие ... конец_пока` (`тогда` опционально);
  - `цикл ... конец_цикла`.
- Перебор:
  - `для item в collection ... конец_для`
  - `для item, index в collection ... конец_для`
  - алиас старой формы: `для_каждого` (тот же разбор)
  - в codegen реализуется через `система.массив.длина` + `система.массив.получить`.
- Управление циклом:
  - `прервать`
  - `продолжить`.
- **`пока_не` — не конструкция** (решение владельца: не добавлять). В позиции
  конструкции даётся точное сообщение: «нет конструкции 'пока_не'; используйте
  'пока не x'». Слово остаётся законным именем (`пусть пока_не = 5`,
  `пока_не = 1`, `пока_не(...)`) — диагностика молчит, если за ним присваивание,
  вызов, поле, индекс или конец строки.

## 8. Исключения

- `попробовать ... поймать err ... конец_попробовать` (алиас: `иначе_попытка`)
- `выбросить значение`
- `поймать` опционален: блок можно закрыть сразу (нужно для
  `конец_попробовать`).
- **`попробовать`/`поймать` ловит только `выбросить`.** Это граница конструкции,
  а не пожелание: перехватывается то, что программа выбросила сама — включая
  `выбросить` внутри вызываемой процедуры. **Ошибка машины не перехватывается:**
  `10 div 0` останавливает программу с ошибкой исполнения, и `поймать` до неё не
  доходит (проверено прогоном, 2026-09-23). Поэтому делитель проверяют **до**
  деления, а не надеются на перехват:

  ```osnova
  если б == 0
    выбросить "делить на ноль нельзя"
  конец_если
  вернуть а div б
  ```
- В байткоде:
  - `try_begin`, `try_end`, `throw`
  - переход в catch-блок через patch offset.

## 9. Системные модули и вызовы

**Реестр синонимов (пункт 1.5 требований).** Модель почти не изобретает
конструкции — она подставляет синоним системного вызова. Лечится словарь, а не
грамматика: `SYSCALL_ALIASES` (`src/runtime/vm/invokeRegistry.ts`) сводит
известный синоним к канону там, где имя попадает в AST, — семантика,
кодогенерация и обе VM видят одно имя. Приём не меняет язык и не открывает новых
способов ошибиться.

**Замер, на котором стоит таблица** (2026-09-23): перекомпилированы **3607**
сохранённых исходников из `runs/traces.jsonl`; замер воспроизводим —
`npx tsx src/scripts/traceDiagnosticsReport.ts`. После первых четырёх синонимов
осталось **25** различимых имён; каноническая цель **доказана** для 18 (цель есть
в реестре И арность канона совпадает с арностью реального вызова в следе).

(«`получить` → `прочитать`») дал бы `syscall_argc`: следы важнее наброска.

**Не переписаны (канонической цели нет — выдумывать вызовы нельзя):**
`система.результат.успех`/`.ошибка`/`.неудача` (ждут типа `Результат`, БЛОК 3);
`система.объект.создать` и `система.типы.создать` (канон — объектный литерал и
объявление типа, а не вызов; у `типы.создать` уже есть точная подсказка
`invented_syntax`); `система.вызов.вызвать` (динамического вызова в языке нет);
`система.сеть.доступен`/`доступно` (проверки доступности в реестре нет);
`система.строка.символ` (нужна не замена имени, а преобразование аргументов);
`система.уведомления.показать`, `система.конвертация.целое32` (таких модулей и
операций в реестре нет); `система.хранилище.установить_поле` (уже имеет точную
подсказку `invented_syntax`); `система.строка` (усечённое имя — по нему одному
цель не определяется).

Карта — по **полному** имени: `система.массив.получить` и `система.сеть.получить`
— канонические имена, и сегментная замена `получить` → `прочитать` их бы сломала.
Неизвестный вызов по-прежнему даёт `unknown_syscall`. Эффект пополнения замерен тем
же замером: `unknown_syscall` **34 случая / 20 имён → 16 случаев / 9 имён**.

Системные вызовы — это host invoke (`op: "invoke"`), а не отдельные опкоды языка.

### 9.1 `система.массив.*`

- `создать()` -> новый массив.
- `добавить(arr, value)` -> добавляет элемент; возвращает `null` (не массив).
- `установить(arr, idx, value)` -> запись по индексу.
- `удалить(arr, idx)` -> удаление по индексу.
- `срез(arr, from, to)` -> новый подмассив.
- `длина(arr)` -> длина.
- `получить(arr, idx)` -> элемент или `null` вне диапазона (default VM).

### 9.2 `система.строка.*`

- `объединить`, `длина`, `содержит`, `начинается_с`, `заканчивается_на`,
  `подстрока`, `в_верхний`, `в_нижний`, `обрезать`, `заменить`, `разделить`, `найти`.
- В default VM реализованы все, кроме `найти` (для него нужен host invoke).

### 9.3 `система.хранилище.*`

- `записать`, `прочитать`, `удалить`, `ключи`, `ключи_с_префиксом`.
- В default VM есть in-memory реализация map-хранилища.

### 9.4 `система.время.*`

- Реестр invoke: `сейчас`, `метка`, `разобрать`, `форматировать`,
  `добавить_дни`, `разница_дней`, `спать`.
- В default VM реализованы:
  `метка`, `разобрать`, `форматировать`, `добавить_дни`, `разница_дней`.
- `сейчас` и `спать` требуют внешнего invoke-обработчика.

### 9.5 Прочие зарегистрированные invoke

- `система.лог.вывести`
- `система.файлы.*`
- `система.сеть.*`
- `система.окно.*`
- `система.интерфейс.*`
- `система.объект.получить`
- `система.json.*`
- `система.ввод.текст`

Все перечисленные имена известны VM через `invokeRegistry`.
Фактическая бизнес-реализация зависит от переданного `invoke` handler (или default VM).

## 10. Ограничения v2.3.2

- В одном исходном файле поддерживаются несколько `модуль ... конец` блоков.
- Импорт (`использовать`) только в начале модуля.
- `тип`-объявления только до процедур.
- Точка входа программы выбирается из первого модуля в порядке объявления в файле.
- Семантика вызовов пользовательских процедур внутри одного компилируемого
  (после expand import) AST: неизвестные вызываемые имена считаются ошибкой.
- Процедуры высшего порядка (передача процедур как значений) не поддержаны.

## 11. Программа из нескольких модулей

Один `.osnova` файл может содержать несколько модулей, каждый в форме
`модуль ... конец`. Модули объявляются последовательно, в порядке сверху вниз.
Точка входа программы выбирается из первого модуля в файле.

Пример:

```osnova
модуль Библиотека
процедура экспорт удвоить(x)
  вернуть x * 2
конец
конец

модуль Главный
использовать модуль Библиотека из "lib.osnova"
процедура главная()
  вернуть Библиотека.удвоить(21)
конец
конец
```

## 12. Semantic diagnostics

Семантический анализ возвращает `kind`-коды ошибок. Они делятся на blocking и
non-blocking.

**Источник правды — каталог `src/compiler/diagnosticCatalogue.ts`** (15 видов,
коды `OSN-SEM-001…015`). Таблица ниже — его отражение в каноне; сторож
`src/compiler/diagnosticCatalogue.test.ts` краснеет, если каталог и код разойдутся,
а также если вид, который компилятор реально порождает, в каталог не занесён.

**Повод к этой правке (2026-09-28).** Виды жили **тремя несогласованными
списками**: код компилятора (15), `src/compiler/semanticKinds.ts`
(6 блокирующих + 3 неблокирующих) и этот канон (6 + 5). Шесть видов —
`arg_count_mismatch`, `chained_compare`, `keyword_param`, `sentinel_pattern`,
`unknown_module`, `export_collision` — не входили **ни в один** список, то есть
были невидимы для всех, кто спрашивает «блокирует ли это сборку»
(`src/compiler/compiler.ts` — сборка `BuildReport`, `src/pipeline/gateChecker.ts`
— шлюз G2, `src/pipeline/orchestrator.ts`). Измерено: программа с неверным числом
аргументов процедуры собирается и в пайплайне не блокирует ничего.

### 12.1 Blocking kinds

Признак `blocking` каталога означает **вхождение в блокирующий список**, по
которому маршрутизирует пайплайн (`src/pipeline/gateChecker.ts` — шлюз G2,
`src/pipeline/orchestrator.ts`). Это описание **маршрутизации**, а не «сборка
успешна или нет» само по себе: разница между списком и судьбой сборки измерена
2026-09-28 пробой `.tmp/lead-verify-catalogue.ts` и независимо повторена
проверяющим. Измерение показало, что расходиться им нельзя, и с 2026-09-28 они не
расходятся ни у одного вида — правило ниже.

**Правило постановки признака (замер 2026-09-28): он обязан совпадать с судьбой
сборки.** Вид, при котором программа не собирается, идёт в блокирующий список —
иначе отказ не уходит в repair-цикл и печатается «советом». Прежде правило не
выполнялось у двух видов, и расхождение было закреплено перечнем «известных»;
перечень снят вместе с расхождением, а вместо него сторожа выводят правило из
исполняемой таблицы замеров (`src/compiler/diagnosticCatalogue.test.ts`,
`src/scripts/errorChannel.audit.test.ts`). Сегодня расхождений **ноль**.

| программа | вид | `BuildReport.success` | что происходит |
|---|---|---|---|
| `прервать` вне цикла | `break_outside_loop` — в списке **да** | **false** | отказ называют обе фазы: семантика видом, кодоген — «оператор 'прервать' допустим только внутри цикла» |
| `продолжить` вне цикла | `continue_outside_loop` — в списке **да** | **false** | то же |
| `1 < 2 < 3` | `chained_compare` — **вид не порождается** | **true** | цепочка — сахар §2.1: парсер разворачивает её в `(a < b) и (b < c)`, число верное (дискриминатор: 10) |
| `(1 < 2) = истина` | `chained_compare` — **вид не порождается** | true | сравнение результата сравнения с `истина` — законная программа; прежде называлась цепочкой ложно |

Отсюда правило чтения таблицы: колонка «в списке» говорит о **маршрутизации**
(пойдёт ли прогон в repair-цикл), а не о судьбе сборки; судьбу сборки держит
`BuildReport.success`, и он складывается из кода.

| код | вид | в списке | что значит |
|---|---|---|---|
| `OSN-SEM-001` | `unknown_syscall` | **да** | вызов несуществующего `система.*` syscall |
| `OSN-SEM-002` | `undeclared_var` | **да** | переменная используется без объявления через `пусть` |
| `OSN-SEM-003` | `unknown_procedure` | **да** | вызов неизвестной процедуры в модуле/namespace |
| `OSN-SEM-004` | `syscall_argc` | **да** | неверное число аргументов у системного вызова |
| `OSN-SEM-005` | `redeclare_var` | **да** | повторное объявление переменной через `пусть` |
| `OSN-SEM-006` | `invented_syntax` | **да** | вымышленные конструкции вне канона языка |
| `OSN-SEM-007` | `arg_count_mismatch` | нет — **вне списка, жив** | неверное число аргументов при вызове процедуры |
| `OSN-SEM-008` | `chained_compare` | нет — **недостижим** | цепочечные сравнения вместо явного `и` (сахар §2.1, вид не порождается) |
| `OSN-SEM-009` | `keyword_param` | нет — **недостижим** | параметр процедуры использует ключевое слово (отвергает парсер) |
| `OSN-SEM-010` | `keyword_as_identifier` | нет | ключевое слово используется как имя переменной |
| `OSN-SEM-011` | `sentinel_pattern` | нет — **вне списка, жив** | `пусть x = пусто` вне `попробовать` |
| `OSN-SEM-012` | `unknown_module` | нет — **вне списка, жив** | ссылка на модуль, который не найден среди доступных |
| `OSN-SEM-013` | `export_collision` | нет — **недостижим** | коллизия экспортируемых имён между провайдерами namespace |
| `OSN-SEM-014` | `break_outside_loop` | **да** | `прервать` вне тела цикла |
| `OSN-SEM-015` | `continue_outside_loop` | **да** | `продолжить` вне тела цикла |

**Списки потребителей: 8 блокирующих + 1 неблокирующий = 9 отнесённых из 15**
(2026-09-28). Сдвиг относительно прежних 6 + 3 назван: два вида перешли в
блокирующие по замеру судьбы сборки, неблокирующим остался
`keyword_as_identifier`. Расширить неблокирующий список — значит изменить
поведение `DiagnosticAgent`, `RepairEngineer` и схемы записей журнала: это решение
владельца, а не следствие уборки перечней.

**Состояние вида названо у каждого — «долга» больше нет** (решение владельца
2026-09-28, задача T12). Прежде шесть видов стояли с пометкой `debt` — «не отнесён
ни к одному списку»; это описывало нерешение, а не вид, и было снято. Теперь у
вида ровно одно состояние, и оно называет факт: **8 блокирующих + 1 неблокирующий
+ 3 неблокирующих вне списка + 3 недостижимых = 15**. Правило вывода списков:
состояние «блокирующий» → блокирующий список, «неблокирующий» → неблокирующий,
«неблокирующий-вне-списка» и «недостижимый» → ни туда, ни туда.

**Расширение неблокирующего списка отклонено — с ценой, а не по умолчанию.**
Три живых вида (`arg_count_mismatch`, `sentinel_pattern`, `unknown_module`) стоят
в состоянии «неблокирующий-вне-списка»: они достижимы и сборку проходят, но
потребителям не отданы. Цена отказа измерена (`.tmp/diag-consumers-probe.ts`):
отдать их — значит родить `DiagnosticAgent` **+3** записи (видимых видов 9 → 12 из
15, молча отброшенных 6 → 3) и положить `RepairEngineer` **+3** вида в промпт
ремонта (9 → 12). Это поведение замороженного пайплайна, поэтому решение о нём —
владельца. Замер до и после правки одним и тем же вызовом: **9 и 9** — поведение
потребителей не изменилось.

| вид | код | состояние | замер, которым оно доказано |
|---|---|---|---|
| `arg_count_mismatch` | `OSN-SEM-007` | неблокирующий-вне-списка | достижим (`вернуть вспом(1)` при `процедура вспом(а, б)`), сборка проходит; потребителям не отдан решением владельца |
| `sentinel_pattern` | `OSN-SEM-011` | неблокирующий-вне-списка | достижим (`пусть с = пусто`), сборка проходит |
| `unknown_module` | `OSN-SEM-012` | неблокирующий-вне-списка | достижим (`вернуть НетТакогоМодуля.функция()`), сборка проходит |
| `chained_compare` | `OSN-SEM-008` | **недостижим** | проверка снята 2026-09-28 (коммит `f4f5165`): цепочку разворачивает в `(a < b) и (b < c)` ПАРСЕР (сахар §2.1), и число верное — дискриминатор даёт 10; прежняя проверка била только по законным программам |
| `keyword_param` | `OSN-SEM-009` | **недостижим** | 33 из 33 неблочных ключевых слова в позиции параметра отвергает парсер — ветка в семантике мертва |
| `export_collision` | `OSN-SEM-013` | **недостижим** | четыре файловые формы коллизии не дают (три собираются молча, четвёртая отказывает `unknown_module`); ветка жива только через `analyzeProgram` с ручным `Program` |

**Коды мёртвых видов остаются зарезервированными навсегда** — `OSN-SEM-008`,
`009`, `013`: код выдаётся один раз и не переиспользуется, в журналах прошлых
прогонов он уже есть.

Отдельно от состояний стоит **замер** `buildRefused`: им называется расхождение
«сборка не проходит, а вид не блокирующий». Сегодня таких нет ни одного — оба
прежних носителя (`break_outside_loop`, `continue_outside_loop`) переведены в
блокирующие, и поле пусто у всех пятнадцати видов. Это не «поле без работы»: сторож
краснеет и на расхождение без записи, и на запись без расхождения.

### 12.2 Различие «ошибка» и «диагностика»

Слово «ошибка» в выводе означает **блокирующий** вид: он делает сборку
неуспешной. Неблокирующий вид печатается как **совет** (предупреждение) — сборка
при нём успешна. Это различие держит код: уровень записи берётся из состояния
вида в каталоге, а не назначается тем, кто печатает.

Правило стало верным **2026-09-28**: до этого `break_outside_loop` и
`continue_outside_loop` печатались советом, а программа с ними не собиралась —
слово расходилось с делом, и расхождение было закреплено перечнем «известных»
вместо красного сторожа. Теперь состояние совпадает с судьбой сборки у всех
пятнадцати видов (§12.1), и проверка это выводит, а не перечисляет.

### 12.3 Где ошибка: файл есть, строки пока нет

Семантическая ошибка называет **файл** (`SemanticError.file`, 2026-09-26): свои
процедуры — входной файл, встроенные при разворачивании импортов — файл, откуда
они пришли (`Procedure.origin`).

До этого поля не было вовсе, и ошибка внутри импортируемого модуля называлась
сборкой главного. Замер: у `apps/task-manager/main.osnova` шесть семантических
ошибок, и все шесть приходили без файла; `модуль 'ЗадачиПриоритеты' не найден`,
возникшая ВНУТРИ `tasks_core.osnova`, выглядела ошибкой `main.osnova` — по
сообщению нельзя было понять, какой файл править. Теперь она называет
`tasks_core.osnova`.

**Строки — долг, названный явно.** `SemanticError.line` объявлено, но **не
заполняется**: `AST` не несёт номеров строк вовсе. Протяжка строк — отдельная
работа с отдельным оракулом по набору конструкций, и смешивать её с этой правкой
нельзя. Оракул `src/compiler/semanticAttribution.test.ts` держит напоминание:
когда строки появятся, проверка «`line` ещё не заполняется» покраснеет и заставит
обновить канон и учебник, а не разойтись тихо.

### 12.4 Коды ошибок: одна личность на отказ

Вид ошибки — для кода; **код** — для машин: журналов, отчётов, счётчиков частот и
внешних инструментов. Пространство имён: `OSN-<ФАЗА>-<НОМЕР>`, где фаза — `LEX`
(лексер), `PAR` (парсер), `SEM` (семантика), `CG` (сборка/кодоген), `RT`
(исполнение). Фазы, у которых нет видов, несут один код на фазу: `OSN-LEX-001`,
`OSN-PAR-001`, `OSN-CG-001`.

Правила кодов:

1. **Выдаётся один раз и не переиспользуется.** Вид, ушедший из языка, оставляет
   код за собой: в журналах прошлых прогонов он уже есть.
2. **Новый вид берёт следующий свободный номер**, а не «красивый» по алфавиту.
3. **Выдумывать код нельзя.** Для вида, которого нет в каталоге, код не
   подставляется — это дефект каталога, и он обязан быть виден, а не замаскирован.

Отдельно стоит код `OSN-CG-002` — «отказ без диагностики». Он не вид ошибки, а
признание: компилятор умеет отказывать, не называя причины. Запись с этим кодом в
журнале означает **дефект компилятора**, а не ошибку программы.

### 12.5 Отказ не молчит

Канон уже называл отказ без диагностики худшим видом отказа
(`docs/language-changelog-v2.md`, пустой файл): по нему нельзя понять, что не так.
Теперь это не пожелание, а проверяемое свойство вывода: **любой отказ обязан
назвать причину хотя бы одной строкой**. Если модуль не собран, а ни одна фаза
причину не назвала, печатается строка с кодом `OSN-CG-002`.

Единый вывод живёт в `src/compiler/compileDiagnostics.ts` и используется всеми
точками входа команды `compile` (`src/cli.ts`, `src/cli/index.ts`,
`src/compiler/cliCompile.ts`). Повод: измерено, что до 2026-09-28 установленный
`osnova` (собранный из `src/cli.ts`) на семантической ошибке выходил кодом 1 с
**нулём строк** вывода, тогда как компилятор знал о ней всё — вид, файл и запись
журнала. Сторож — `src/compiler/compileDiagnostics.test.ts`, включая негативный
контроль (рабочая программа обязана молчать).

## 13. Канон перед публикацией: двенадцать пунктов и их статус

**Закон этого раздела.** Канон не пишется раньше проверки. У каждого утверждения
ровно один из двух статусов:

| статус | что значит |
|---|---|
| **проверено прогоном** | утверждение без оговорок |
| **не проверено** | пометка. Это постоянный честный статус, а не «временно» |

Третьего статуса нет. Оракул — `src/compiler/canon.test.ts` (**42** проверки;
негативные контроли — мутацией исходников, **9** мутаций, все краснят). Пробы —
`.tmp/canon-probes.ts`, `.tmp/canon-probes2.ts`, `.tmp/canon-probes3.ts`.
Машинная плоскость (`src/e2k/**`, `docs/e2k-*`, `docs/hardware-debt.md`) здесь
только **цитируется**: её числа измерены своими пробами.

### 13.1 Деление и остаток — проверено прогоном

- `/` — **вещественное** всегда, в том числе для целых: `7 / 2 = 3.5`.
- `div` — **целочисленное**, отсечение **к нулю**: `(-7) div 3 = -2` (не −3).
- `%` — остаток **со знаком делимого**: `7 % 3 = 1`, `(-7) % 3 = -1`,
  `7 % (-3) = 1`, `(-7) % (-3) = -1`. Тождество `a div b * b + a % b == a`
  выполняется при всех четырёх сочетаниях знаков.
- **Отрицательный ноль назван числом:** `(0 - 6) % 3` даёт `-0`. При этом
  `-0 == 0` истинно, `String(-0)` даёт `"0"` — во всех операциях языка неотличим
  от нуля. Это измеренный факт, а не деталь реализации.
- **Ноль в делителе — машинная ошибка, и она НЕ ловится** `попробовать`/`поймать`:
  перехват срабатывает на опкоде `выбросить`, а отказ арифметики приходит
  JS-исключением из тела интерпретатора. Это свойство, а не дефект: ошибка языка
  и отказ машины не смешиваются.
- **Ноль в делителе — ДВА правила, а не одно** (см. 13.6a): у деления и у остатка
  свои отказы и свои сообщения.
- **Трюк `(a - a % b) / b` вычищен — 13.1 выполнен** (2026-09-26, `f5b6c29`).
  Проверено гребом по `src/**`, `apps/**`, `tests/**`, `docs/**`: в коде выражения
  нет, `tests/dsp/kernels/iir.osnova` возвращает частное через `div`
  (`вернуть числитель div знаменатель`), шапка ядра описывает замену. Числа
  причины названы заново по README: **464 из 464** носителя, отказов **0** — было
  424 из 446 и 22 отказа, последним снят вещественный `IR.div` ядра `iir`.
  Единственное оставшееся вхождение текста трюка — `docs/hardware-debt.md`
  (запись измерения чужой плоскости, не код).

### 13.2 `пусть` — неизменяемость СВЯЗЫВАНИЯ — проверено прогоном

- `пусть имя = значение` — объявление, и оно **единственное** для этого имени.
- `имя = значение` — изменение **переменной**; это и есть изменяемость.
- **Неизменяемость касается связывания, а не значения.** Массив, связанный через
  `пусть`, **мутабелен**: `система.массив.добавить(м, 2)` работает и меняет
  длину. Глубокой неизменяемости в языке **нет** — и слово «неизменяемое» про
  `пусть` без этой оговорки лгало бы.
- Повторное `пусть` того же имени диагностируется (`redeclare_var`) и названо
  blocking в §12.1 — но сборка при этом **не отвергается**: `compilerSuccess`
  остаётся истинным, отказ ставит гейт пайплайна. Разница названа, потому что
  «ошибка» и «блокирующая диагностика» — не одно и то же.

### 13.3 Имена файлов — НЕ ПРОВЕРЕНО

Правило канона: строчные буквы, цифры, подчёркивание; начинать с буквы; дефис
запрещён; кириллица разрешена; ошибка обязана предлагать годное имя
(`todo-service.osnova` → «переименуйте в `todo_service.osnova`»).

**Измерено: правила НЕТ.** Принимаются все проверенные имена — с дефисом, с
заглавными, с цифрой в начале, с подчёркиванием, кириллицей. Отказа нет ни на
одно. Значит это **план**, а не описание языка: компилятор обязан научиться
отказывать и предлагать имя, и только тогда пункт станет «проверено».

**Где стоит дело** (2026-09-26). **Обе волны переименований закрыты:** волна A
(приложения) — `03af5e7` (`apps/osnova-todo/todo_service.osnova`) и `511ec61`
(`apps/task-manager/tasks_{core,priorities,filters,storage}.osnova`); волна B
(фикстуры `src/runtime/fixtures/**`: `cycle_*`, `ilp_*`, `crdt/*_merge`) — `9b1bc76`.
Нарушителей в репозитории не осталось. **Отказ в компиляторе можно включать** —
следующим шагом, с оракулом (принимается `todo_service.osnova`, отвергается
`todo-service.osnova` с текстом «переименуйте в …») и негативным контролем.
Пример в скобках выше — иллюстрация будущего сообщения, а не ссылка на
существующий файл: таких файлов в репозитории нет.

### 13.4 Синтаксис аннотаций типов — зарезервирован `: Тип` — проверено прогоном

- **Работает:** `пусть а: Тип = …`, `процедура ф(х: Тип)` и `процедура ф(х): Тип`
  (двоеточие после `)`).
- **`->` частью языка НЕ является** (2026-09-26): разбор падает — «Ожидается
  выражение, получено: >». Ни в зарезервированном виде, ни в каком-либо ином:
  зарезервирован **только** `: Тип`. Из канона `->` убран, чтобы не обещать
  синтаксиса, которого нет.
- **Имена типов регистрозависимы и конечны:** `Целое32`, `Число`, `Строка`,
  `Логический` (`src/compiler/compiler.ts#PRIMITIVE_FIELD_TYPES`). Написанное строчными `целое32`
  даёт «Тип не объявлен».
- **Аннотации ПРОВЕРЯЮТСЯ, а не «просто зарезервированы»:** несовпадение
  аннотации и значения даёт `Несовпадение типа (ф#0): ожидалось целое32,
  получено Число`. Канон обязан это признать, а не называть синтаксис мёртвым.
- Для книги формулировка «пока необязательные» остаётся верной: **опускать можно**.

### 13.5 Числа и матрица смешения — проверено прогоном

- `Число` — float64; `Целое32` — **аннотация, которая сводится к `Число`**
  (`src/compiler/compiler.ts#primitiveAlias`). Проверено не чтением кода, а равенством байткода программы
  с аннотацией и без неё.
- **Матрица смешения (измерена):** `Целое32 + Число = 7.5`, `Число + Целое32 = 7.5`,
  `Целое32 < Число` — истина при 5 и 5.5, `Целое32 / Целое32 = 3.5`,
  `Целое32 div Целое32 = 3`. **Аннотации в арифметике не участвуют вовсе.**
- **Обёртки при переполнении НЕТ — это измеренная правда языка** (2026-09-26),
  а не намерение: `2000000000 + 2000000000 = 4000000000`, `2147483647 + 1 = 2147483648`,
  `100000 * 100000 = 10000000000`, и аннотация `Целое32` обёртки не включает.
  Числа — float64, диапазон 32 бит не поддерживается ничем.
- **32/64-битные целые с обёрткой — НЕ РЕАЛИЗОВАНО** и в публикацию не входит:
  это отдельный проект. Паритет VM↔e2k по переполнению — **названный долг**, а не
  подразумеваемое свойство; на e2k обёртка есть свойство `adds`, на VM её нет.
- **`Целое64` — аннотация, сводящаяся к `Число`** (2026-09-26), тем же способом,
  что `Целое32`. Проверено **равенством байткода**, а не чтением списка типов:
  программа с аннотацией и без неё дают один байткод; `Целое64` и `Целое32`
  неразличимы по байткоду; обёртки нет (`2000000000 + 2000000000` под `Целое64`
  = 4000000000). Отдельной 64-битной арифметики **не существует** — «64» здесь
  означает разрядность объявленного намерения, а не арифметику.

### 13.6 Строки — ПРОВЕРЕНО, и считаются КОДОВЫЕ ТОЧКИ

- **Решение владельца 2026-09-28 (принято): длина и индексация строк — КОДОВЫЕ ТОЧКИ.**
  Не графемы, не байты UTF-8 и не единицы UTF-16. Исполнено в VM
  (`src/runtime/vm/stringUnits.ts`), оракул — `src/runtime/vm/stringCodePoints.audit.test.ts`
  (сетка 25 случаев против **Python** как независимого свидетеля, канал эталона пиннится
  `PYTHONIOENCODING=utf-8`; негативный контроль — возврат к `s.length` краснит и оракул, и
  привязки канона).
- **Что было до решения — измерено и оставлено историей** (2026-09-26): `система.строка.длина`
  считала **единицы UTF-16**, то есть JS `String.length`. Тогда канон говорил ровно то, что
  измерено: `длина("привет") = 6`, `длина("ёж") = 2`, но `длина("👍") = 2` при одной кодовой
  точке, а семья `👨‍👩‍👧` давала **8**. Замена 2026-09-28 (замер `.tmp/t19-units.ts`, до → после):
  `длина("🙂")` **2 → 1**, `длина("👨‍👩‍👧")` **8 → 5**, `подстрока("🙂", 0, 1)` было `"\ud83d"`
  (половина суррогатной пары, невалидный текст) → стало `"🙂"`, `подстрока("🙂x", 1, 2)` было
  `"\ude42"` → стало `"x"`, `найти("🙂x", "x")` **2 → 1**.
- **Для BMP расхождения между единицами нет** — поэтому переход не сломал ни одной программы
  корпуса и ни одного golden-теста: `привет` = 6, `ёж` = 2 в обеих единицах. Замер: в корпусе
  **0 файлов** с не-BMP символами, поэтому ни один `expected.txt` не несёт записанной длины в
  единицах UTF-16 (перегенерация не требуется).
- **Графемы каноном не считаются — подтверждено:** `👨‍👩‍👧` даёт **5** кодовых точек (три символа
  и два ZWJ), а не 1. Нормализация (NFC/NFD) тоже не выполняется: `е + U+0308 + ж` = **3**
  кодовые точки. Это те же числа, что у Python, и они же — обе границы решения.
- **Порядок строк — отдельный класс, и он тоже приведён к кодовым точкам.** По единицам UTF-16
  суррогаты (0xD800–0xDFFF) стоят **ниже** 0xE000–0xFFFF, а кодовые точки астральных символов —
  **выше**, поэтому `"🙂" > "\uFFFD"` было **ложью**, стало **истиной** (Python: истина). Сравнение
  идёт общим компаратором у обеих машин — стековой и регистровой (`orderedCompare`), иначе два
  исполнителя языка разошлись бы между собой.
- **Строки неизменяемы**, доступ O(n), кэш длины — деталь реализации: **не проверено**,
  отдельных измерений на эти три утверждения нет. Отдельно названо: на цели строка лежит
  **байтами UTF-8** (§3.47), а порядок байтов UTF-8 **совпадает** с порядком кодовых точек —
  значит сравнение на цели остаётся `memcmp`-ом, а вот `длина` в кодовых точках требует счёта
  (или кэша), и это цена решения, названная, а не спрятанная.
- **Решение владельца 2026-10-10 (принято): `с[и]` даёт ЧИСЛО — код символа**, а не строку из
  одного символа (это отменяет редакцию 2026-10-04, где `"абв"[0]` равнялось `"а"`). В VM
  исполнено: `система.строка.символ` живёт в `src/runtime/vm/stringChar.ts`, `символ("абв", 0) =
  1072`, выход за границу — НАЗВАННЫЙ ОТКАЗ (не `null`: `null` сложился бы с числом как ноль).
  Оракул VM — `src/self-host/stringIndex.test.ts` (различающая проба `с[0] + 100 = 1172`; до
  2026-10-04 здесь было `100`).
  - **Почему число, а не строка — из модели цели, а не из удобства.** На цели строка — это
    адрес статических байтов UTF-8, и **длина известна только на СБОРКЕ** (§3.47, §3.48):
    строковая операция обязана знать длину своего результата в момент сборки образа. `с[и]` же
    даёт **1–4 байта, известных только в рантайме**, — такой величины в модели цели нет. Второе
    представление строки («адрес + длина») владельцем **отклонено**, поэтому выбор был между
    «отказом навсегда» и «числом»: стало число.
  - **На цели исполнено (замер 2026-10-23).** `система.строка.символ` понижается таблицей
    кодов, собранной на **СБОРКЕ** из тех же статических байтов, по записи 8 байт на кодпоинт
    (младшим вперёд). Индекс — рантаймовый; выход за границу **в рантайме** даёт **−1**, а
    **константный** индекс за границей — отказ на сборке. Оракул — `src/e2k/stringSymbol.test.ts`
    (14 проверок), разбор — `docs/hardware-debt.md` §3.133.
  - **Расхождение с VM названо, а не спрятано:** у VM тот же случай — названный отказ с текстом,
    у цели — значение `−1` (у цели исключений нет). Это осознанная разница двух исполнителей, а
    не «одно из двух неверно».
  - **Чего это не значит:** таблица кодов — не разбор UTF-8 в рантайме, а тот же приём, что
    таблица продолжений у `длина`: сборка считает, рантайм читает по рантаймовому индексу.
    Годится, ПОКА строки статичны; когда строки придут из памяти, понадобится настоящий разбор
    байтов — это названный долг, а не сделанное.
  - **Следствие, найденное замером 2026-10-23: у v3 не оставалось способа взять ТЕКСТ.** `с[и]`
    даёт число, а трёхсегментное имя (`система.строка.подстрока`) канон v3 не разбирает (долг
    §3.105.3). Поэтому self-host-лексер (`src/self-host/lexer.osnova`), у которого лексема — ТЕКСТ
    токена из исходника, перестал выражаться: **5** проверок `src/self-host/lexer.test.ts` краснели
    «Несовпадение типа (с_токеном#1): ожидалось Строка, получено Число». Закрыто **встроенным словом
    v3** `подстрока(строка, начало, конец)` — арность 3, границы в КОДОВЫХ ТОЧКАХ, тем же приёмом,
    что файловые и коллекционные слова (`src/compiler-v3/parser.ts`, таблица `СТРОКОВЫЕ_СЛОВА`;
    реестр — `система.строка.подстрока`; оракул — `src/compiler-v3/nativePath.test.ts`: значение на
    обеих VM, плюс отказ «требует трёх аргументов»). **На ЦЕЛИ слово остаётся отказанным:** результат
    строковой операции обязан иметь длину, известную на СБОРКЕ, а срез по рантаймовому индексу её не
    имеет (§3.48) — то есть слово чинит VM-путь, а не снимает стену цели.
  - **Знаки в self-host-лексере сравниваются КОДАМИ, а не строками** (переписано 2026-10-23 под то же
    решение): было `с == "("` и `содержит с в цифры` — стало `с == 40` и `цифра(с)`/`буква(с)`/
    `знак_ли(с)` с таблицей кодов в шапке файла; текст знака берётся срезом исходника
    (`подстрока(исходник, поз, поз + 1)`). Оракул — `src/self-host/lexer.test.ts` (7 проверок,
    включая побитовую сверку с TS-лексером v3 `tokenizeV3` на пробе из 50+ токенов).

### 13.6a Ноль в делителе: два правила, а не одно — проверено частично

- **VM — проверено:** отказы различны и названы — `div` → «Integer division by
  zero», `/` → «Division by zero», `%` → «Remainder by zero».
- **e2k `SDIVs` при нуле — проверено чужой пробой** (`exc_div`; `src/e2k/e2kRealRun.ts`,
  `src/e2k/e2kDivisionForms.test.ts`).
- **e2k `SMODX` при нулевом делителе — НЕ ПРОВЕРЕНО.** Измерения нет; прогон
  требует QEMU-e2k и живёт в `gate:qemu`.
- **Знак остатка на e2k расходится с VM и с руководством:** `smodx` даёт
  `(-7) % 3 = 0`, тогда как МЦСТ §10.3.3 обещает остаток со знаком делимого (−1),
  а VM даёт −1. Измерено машинной плоскостью (`docs/hardware-debt.md` §3.21).
  **Паритет VM↔e2k по знаку остатка не подтверждён.**

### 13.7 Исключения — проверено на VM, на e2k НЕ ПРОВЕРЕНО

- `выбросить` и `попробовать`/`поймать` работают на VM: `выбросить "беда"` внутри
  `попробовать` перехватывается (проверено возвратом 777).
- **Машинная ошибка не перехватывается** (13.1) — это и есть граница между
  «ошибкой языка» и «отказом машины».
- **Отказ компиляции на границе процедуры в e2k-подмножестве — НЕ ПРОВЕРЕНО:**
  не реализовано. Формулировка канона (отказ называет процедуру и два выхода —
  поймать внутри или вернуть `Результат`) остаётся планом.
- `Результат[T]` — **отдельный проект, отложен решением владельца** до после
  публикации.

### 13.8 Память и арена — НЕ ПРОВЕРЕНО на уровне языка, совпадает с рантаймом массивов

- Канон: арена одна на программу, выделение монотонное, освобождение при выходе;
  `арена.сбросить()` допустим, только если ни одна ссылка не живёт; арена на
  процедуру с escape в арену вызывающего — план, требует кадра и ABI.
- `арена.сбросить()` в языке **нет** — ни как вызов, ни как проверка
  допустимости. Пункт «не проверено».
- Что **уже соответствует** канону: рантайм массивов на e2k выделяет монотонно —
  указатель кучи (`%b[15]`) растёт вверх и не освобождается
  (`src/e2k/arrayRuntime.ts#ARRAY_REGISTERS`, `src/e2k/elfMinimal.ts#SPILL_AREA_BYTES`). Это цитата чужой
  плоскости, своего измерения здесь нет.

### 13.9 Циклы — проверено прогоном (кроме `диапазон`)

- `для ч в коллекция` — **связывает ЭЛЕМЕНТ, а не индекс.** Различающий опыт:
  `для ч в [10, 20]` с накоплением даёт **30**; возврат `ч` на первой итерации
  даёт **10**. Это отвечает на вопрос канона, который «сейчас угадывается».
- **`диапазон(от, до, шаг)` НЕ СУЩЕСТВУЕТ** (измерено 2026-09-26):
  `процедура 'диапазон' не объявлена в модуле`. Решение владельца: **реализуется**,
  с оракулом на границы — пустой диапазон, шаг больше длины, отрицательный шаг,
  включительность верхней границы; каждое поведение закрепляется проверкой, а не
  решается по вкусу. Пока не реализовано — статус «не проверено».
- **Перебор строки не работает и МОЛЧИТ — это хуже отказа:** `для ч в "аб"`
  выполняет **ноль** итераций (результат — пустая строка). Решение владельца:
  отказ с точной причиной («строка не перебирается; переберите индексы»).
  Порядок работ — проба сегодняшнего поведения, потом изменение, потом оракул:
  молчаливый ноль итераций ошибкой не считается *сейчас*, но канон его не
  узаконивает.
- Числовой `для` не вводится — это решение, а не измерение.

### 13.10 Затенение — НЕ ПРОВЕРЕНО (диагностируется, но не запрещено)

- Канон: затенение запрещено, в том числе во вложенных блоках.
- **Измерено: запрета нет.** Затенение во вложенном блоке и затенение параметра
  дают `redeclare_var` — диагностику, при которой `compilerSuccess` остаётся
  истинным. То есть сейчас это совет, а не запрет.
- Пункт станет «проверено» только когда компилятор начнёт отказывать.

### 13.11 Заморозка как оракул в CI — НЕ СДЕЛАНО (ставится в конце)

Замороженный JSON: ключевые слова, написания терминаторов (`конец_процедуры` и
прочие), семантика операторов, правило имён файлов — плюс обязательная запись в
`docs/language-changelog-v2.md` при изменении.

**Не сделано намеренно:** замораживать движущийся список нельзя. По 13.3, 13.5,
13.6, 13.9 и 13.10 канон ещё будет меняться — заморозка встанет после этих правок.

### 13.12 Матрица статуса понижения на e2k

Три статуса: **VM** — работает на VM, на e2k не понижается; **e2k** — работает на
цели; **Нет** — не реализовано нигде.

| Возможность | VM | e2k | Основание |
|---|---|---|---|
| Числа и арифметика (`+ - * div %`) | **VM** | — | канон-оракул; понижение в e2k — чужая плоскость, здесь не измерялось |
| Строки (длина, подстрока, склейка) | **VM** | **НЕ ПРОВЕРЕНО** | измерения на цели нет |
| Целое32 с обёрткой | **Нет** | **НЕ ПРОВЕРЕНО** | на VM обёртки нет (13.5), измерено |
| Целое64 | **Нет** | **Нет** | типа нет вовсе (13.5) |
| Исключения (`выбросить`/`поймать`) | **VM** | **Нет** | отказ на границе процедуры не реализован (13.7) |
| `диапазон` | **Нет** | **Нет** | процедуры нет (13.9) |
| Арены (`арена.сбросить`) | **Нет** | **Нет** | в языке нет (13.8) |
| Библиотека (окна, сеть, интерфейс) | **VM** | **Нет** | реестр системных вызовов исполняется VM; на цели нет даже вывода числа |
| Массивы | **VM** | **VM** | монотонный рантайм кучи (`src/e2k/arrayRuntime.ts`) |

Матрица закрывает главный риск «библиотека обгоняет рантайм»: **окна, сеть и
интерфейс есть в каноне и работают на VM, а на e2k не понижены**. Столбец e2k
заполнен по чужим измерениям и там, где измерения нет, стоит «НЕ ПРОВЕРЕНО», а не
догадка.

### 13.13 Долги, названные числами

Долг без чисел — обещание, а не долг. Здесь только то, что **измерено** и
**сознательно не сделано**, с причиной и с условием закрытия.

**`osnova.task_manager` снят из реестра приложений** (`src/runtime/appRegistry.json`,
2026-09-26). Числа: `main.osnova` — **6** семантических ошибок, `tasks_core.osnova` —
**3** (в копии с дописанным импортом **5**), `filters`/`priorities`/`storage` —
чисто. Три названные причины:

1. `ЗадачиЯдро.создать` ожидает **4** аргумента, передано **3** — трижды;
2. `ЗадачиПриоритеты.серверный_приоритет` вызван **без импорта**, и такой
   процедуры нет: в `tasks_priorities.osnova` есть только
   `высокий`/`средний`/`низкий`;
3. `система.строка.объединить` вызвана с **3** и **24** аргументами при `argc` **2** —
   рантайм реализован на два и **обрезал бы JSON молча**.

Это не патч, а переделка модели задачи: `main` и ядро разошлись по арности.
Поэтому запись уходит из реестра, **файлы приложения остаются в дереве**, а
оракул `src/runtime/appRegistry.test.ts` держит пустоту реестра **объяснённой**
(`PENDING` с числами выше) и краснеет, если в реестре появится приложение,
которое не компилируется или чьего пути нет на диске. Запись возвращается в
реестр **тем же коммитом**, где приложение начинает компилироваться и проходить
`npm run golden`.

### 13.14 Память: `система.память.выделить` — граница и путь, НЕ свойство

- **Операция языка:** `система.память.выделить(байт): Число` — одна операция, реестр
  (`src/compiler/language-registry.ts`), схема (`docs/osnova/language-schema.json`, та же
  генерация), VM. **Адрес — это ЧИСЛА.** Отдельного типа `Адрес` в языке **нет** и не
  заводится: адрес складывается, сравнивается и печатается как число.
- **Формулировка модели памяти — «граница + путь», а не «свойство»** (решение владельца:
  слово «свойство» читается как «так и должно быть» и закрывает дверь к US):
  «Текущая модель памяти: **арена растёт, не возвращается**. Предел — **число** байт.
  Программы с длительной работой **обязаны укладываться**. **Следующий шаг: US (User
  Stack)** — автоосвобождение при выходе из процедуры.»
- **Исчерпание — отказ, а не тишина:** код выхода **231** и строка **«арена исчерпана:
  выделение сверх предела»** (одна и та же на цели и в VM).
- **Что проверено прогоном, а что нет.** В VM: арена растёт (10 выделений по 100 в цикле
  дают растущие адреса), исчерпание даёт **отказ с этой строкой** — проверено
  (`.tmp/t44-vm.ts`); предел VM — `VM_ARENA_LIMIT` = **65536** байт, и это условное число.
  **На цели понижения пока НЕТ:** операция объявлена в реестре и схеме, а понижение —
  следующий шаг (§3.87 `docs/hardware-debt.md`), поэтому запись помечена `experimental`, а
  не «работает». **Не проверено:** сквозная программа на модели, байты вывода, код 231 на цели.
