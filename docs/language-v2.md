# Язык Основа v2.3.2 — спецификация

Канон языка определяется реализацией в `src/compiler/**` и `src/runtime/vm/**`.
Этот документ описывает только то, что подтверждено кодом.

## 1. Введение

Основа — русскоязычный язык для компиляции в байткод VM:

`исходник .osnova -> tokenize -> parse -> semantic -> codegen -> .osvbc -> VM`.

Целевая платформа проекта: стековая VM; архитектурный таргет проекта — VLIW/e2k.

## 2. Базовые элементы

### 2.1 Лексика

- Идентификаторы: кириллица/латиница, `_`, цифры после первого символа.
- Комментарии: `//` до конца строки и `/* ... */`.
- Алиасы для моделей (канон всё равно русский): `let`→`пусть`, `if`→`если`, `true`→`истина`, `&&`→`и`, `===`→`==` и др. (`LLM_KEYWORD_ALIASES`).
- Цепочечные сравнения `a < x < b` → `(a < x) и (x < b)`.
- `+` склеивает, если хотя бы один операнд строка.
- Токен `|` — разделитель вариантов перечня.
- Литералы:
  - числа: целые и десятичные;
  - строки: `"..."` с escape (`\n`, `\r`, `\t`, `\"`, `\\`);
  - булевы: `истина`, `ложь`;
  - null: `пусто`;
  - массив: `[ ... ]`;
  - объект: `{ ключ: значение, ... }`;
  - перечень: `Имя.вариант` (в VM — строка `"Имя.вариант"`).

### 2.2 Зарезервированные слова (implemented)

`модуль`, `процедура`, `тип`, `использовать`, `экспорт`, `из`, `пусть`, `если`,
`иначе`, `иначе_если`, `пока`, `попробовать`, `поймать`, `выбросить`,
`для`, `в`, `цикл`, `прервать`, `продолжить`, `конец`, `вернуть`,
`истина`, `ложь`, `пусто`, `и`, `или`, `не`, `тогда`, `когда`, `есть`.

**Алиасы** (принимаются, но канон — слева): `иначе_попытка` → `поймать`,
`для_каждого` → `для`, `for` → `для`, `catch` → `поймать`. Английские
подстановки — в реестре (`LLM_KEYWORD_ALIASES`).

## 3. Типы

### 3.1 Значения времени выполнения (VM `StackValue`)

- `number`
- `string`
- `boolean`
- `null`
- `Record<string, unknown>` (объект)
- `StackValue[]` (массив)

### 3.2 Аннотации типов в языке

- Поддержан синтаксис `тип Имя { поле: Тип, ... }` (запись).
- Поддержан перечень: `тип Имя = вариант1 | вариант2 | …`.
- Поддержан nullable-префикс: `?Тип`.
- Поддержана аннотация переменной: `пусть x: Тип = ...`.
- Поддержаны типы параметров: `процедура f(x: Тип)`.
- Поддержана аннотация возврата: `процедура f(x: Тип): Тип`.
- Тип возврата процедуры без аннотации выводится из `вернуть` (если все возвраты
  одного типа); вызов такой процедуры даёт её тип возврата.
- Литерал перечня: `Масть.пики` (квалифицированный; в байткоде — строка).
- На этапе `validateNamedTypesAndRewrite` (v2.1):
  - неизвестное поле у типизированной записи — ошибка;
  - несовпадение `Число`/`Строка`/`Логический`/перечень/запись/`[T]` — ошибка;
  - `вернуть` несовпадающего типа (против аннотации или вывода) — ошибка;
  - неизвестный тип поля / несуществующий тип — ошибка;
  - неаннотированные переменные остаются дырявыми (gradual).

### 3.3 Массив как тип

Отдельного ключевого слова `массив` в синтаксисе типа нет.
Массив вводится:

- литералом `[]`/`[a, b, c]`;
- аннотацией `[Тип]` в поле/`пусть`;
- системными вызовами `система.массив.*`.

### 3.4 Ещё нет в компиляторе

- контекстный `и` как имя после `пусть`.

### 3.5 Вызов: семантика исходника, не стека (v2.3)

Исходник задаёт, живёт ли результат:

- вызов как **выражение** (`пусть n = система.массив.длина(a)`, условие `если`) — одно значение;
- вызов как **инструкция** (`система.массив.добавить(a, x)`, `игра.очистить(...)`) — эффект, без значения.

Компилятор снимает неиспользованный результат (`pop`). VM после каждого `invoke` кладёт ровно одно значение (`null`, если обработчик ничего не вернул). Пользовательская процедура, которая дошла до `конец` без `вернуть`, тоже кладёт `пусто` (v2.3.2) — иначе `pop` после вызова-инструкции роняет стек. Мутирующие `система.массив.добавить` / `установить` / `удалить` по-прежнему возвращают `null`, не массив.

### 3.6 `когда` (v2.2)

Разбор перечня с исчерпыванием. Компилятор разворачивает в `если` / `иначе_если`.

```osnova
когда карта.масть
  есть Масть.пики
    вернуть 1
  есть Масть.черви
    вернуть 2
конец
```

Если не все варианты названы — ошибка, пока нет ветки `иначе`.

Горизонт школы: `.cursor/skills/osnova-lang/цель.md`.

## 4. Модульная система

- Базовый синтаксис файла: `модуль Имя`.
- Поддержан импорт: `использовать модуль Namespace из "path.osnova"`.
- Поддержан экспорт процедур: `процедура экспорт имя(...)`.
- Типы из импортированного файла видны в текущем. Два разных файла с одним
  `тип Имя` — ошибка (оба пути в сообщении). Один файл, импортированный дважды
  (ромб), не дубликат. Два `тип Имя` в одном файле — ошибка.
- Ошибка разбора импортированного файла указывает этот файл и строку, не вход.
- `compileSource({ filename })` — имя входа для диагностики.
- Ограничения текущей реализации:
  - в одном исходном файле может быть несколько модулей;
  - импорт разрешен только в начале модуля (до процедур);
  - `тип` разрешен только до процедур;
  - точка входа программы выбирается из первого модуля в порядке объявления в файле.

Примечание: `compileSource` поддерживает межфайловые импорты через инлайн
экспортированных/внутренних процедур импортируемого модуля в единый AST.

## 5. Объявления

### 5.1 Процедуры

- `процедура имя(параметры) ... конец`
- Экспорт:
  - `экспорт процедура имя(...)` (через префикс перед `процедура`);
  - `процедура экспорт имя(...)`.
- Возврат:
  - `вернуть выражение`
  - `вернуть` (эквивалент возврату `null`).

### 5.2 Именованные типы

- `тип Имя { поле: TypeRef, ... }`
- `TypeRef`: `ИмяТипа` или `?ИмяТипа`.

## 6. Выражения

### 6.1 Базовые выражения

- Литералы: число, строка, `истина`, `ложь`, `пусто`.
- Переменная: `имя`.
- Бинарные операции: `+ - * / % div == != < <= > >=`.
  - **`+` склеивает строки.** Если хотя бы один операнд — строка, `+` даёт строку:
    `"Всего: " + 7` → `"Всего: 7"`, `"готово: " + истина` → `"готово: истина"`.
    Значения при склейке печатаются по-основски: логические — словами `истина` /
    `ложь`, `пусто` — словом `пусто`, массив и объект — в JSON. Отдельный вызов
    `система.строка.объединить(а, б)` делает то же самое, но принимает **ровно два**
    аргумента, поэтому для трёх частей его вкладывают друг в друга.
  - **`/` — ВЕЩЕСТВЕННОЕ деление, а не целочисленное.** Проверено прогоном
    (2026-09-15): `(3 * 20 + 2 * 6) / 5` даёт `14.4`, и IIR-ядро
    (`tests/dsp/kernels/iir.osnova`) на наивной записи вернуло `121.0656` вместо
    `119`. Историческая замена — через остаток:
    `(a - система.математика.остаток(a, b)) / b`; с БЛОК 2 для этого есть оператор.
  - **`div` — целочисленное деление, отсечение К НУЛЮ** (БЛОК 2, 2026-09-23):
    `10 div 3 = 3`, `(0 - 7) div 3 = -2`, `7 div (0 - 3) = -2`, делитель `0` —
    ошибка исполнения. Правило округления записано не «на глаз»: оно согласовано с
    `%` (тождество `a div b * b + a % b == a` выполняется при любых знаках) и
    совпадает с формой e2k `SDIVs` (руководство МЦСТ §10.3.3 — отсечение к нулю),
    поэтому понижение в неё не требует менять семантику. Floor дал бы в языке
    третье правило округления, которого не требует ни `/`, ни `%`.
    **Почему не `//`:** `//` — комментарий до конца строки, и `10 // 3` молча даёт
    `10` (замер по журналу: 3675 исходников, `//` после кода — 4 случая, все
    пояснения; `div`/`дел`/`цел_деление` — ноль). Русское `цел_деление` —
    **алиас** к `div` (`LLM_KEYWORD_ALIASES`), как `for` к `для`.
  - **`%` — остаток с усечением к нулю (знак результата — знак делимого).** Измерено
    прогоном (2026-09-15): `7 % 3 = 1`, `(0 - 7) % 3 = -1`, `7 % (0 - 3) = 1`,
    `(0 - 7) % (0 - 3) = -1`. Это семантика C/JS, а **не** Python: в Python `-7 % 3 = 2`.
    С `div`, округляющим к нулю, пара `div`/`%` согласована и при отрицательных
    операндах.
- Логические: `и`, `или`, `не` (в кодогене short-circuit для `и`/`или`).
- Скобки: `(expr)`.

### 6.2 Переменные и присваивание

- Объявление: `пусть x = expr` (опционально с типом: `пусть x: Тип = expr`).
- Присваивание: `x = expr`.
- **Алиас `:=`** (из Паскаля): `пусть x := expr` и `x := expr` эквивалентны `=`
  (пункт 1.3 требований: 20 случаев). Двоеточие в языке только в аннотации типа и
  в литералах объектов, где за ним идёт имя типа, поэтому разбор однозначен.
  В machine-readable каноне `::=` — **метаданные оператора `=`**
  (`operators[].aliases`), а не отдельный оператор: отдельная запись означала бы
  отдельный вид токена, а лексер сводит `::=` к `=`.
- Составное присваивание:
  - `x += expr`, `x -= expr`, `x *= expr`, `x /= expr`.

### 6.3 Объекты

- Литерал: `{ поле: expr, поле2: expr }`.
- Доступ: `obj.поле`.
- Присваивание полю:
  - `obj.поле = expr`
  - `obj.поле += expr` (и `-=`, `*=`, `/=`).

### 6.4 Массивы и sugar

- Литерал `[a, b, c]` парсится как AST `kind: "массив"`.
- В codegen массив-литерал разворачивается в:
  - `система.массив.создать`
  - серия `система.массив.добавить`.
- `arr[i]` парсится как вызов `система.массив.получить(arr, i)`.
- `arr[i] = v` парсится как вызов `система.массив.установить(arr, i, v)`.
- `объект.поле[i] = v` — то же, массив берётся из поля (`мир.поле[i] =`).
- `объект.поле[i].ключ = v` — запись в элемент-запись.
- `arr[i] op= v` разворачивается в
  `получить(arr, i) -> op -> установить(arr, i, result)`.

### 6.5 Вызовы

- Пользовательская процедура: `имя(...)`.
- Пространство имен / системный вызов: `namespace.имя(...)`, включая `система.*`.

## 7. Управляющие конструкции

**Закрывающее слово называет свой блок (БЛОК 1 v2).** Канон — `конец_<что>`;
legacy-`конец` остаётся и закрывает блок по контексту.

| Конструкция | Канон закрытия |
|---|---|
| `если`/`иначе_если`/`иначе` | `конец_если` |
| `пока` | `конец_пока` |
| `для` (алиас `для_каждого`) | `конец_для` (полная форма `конец_для_каждого`) |
| `цикл` | `конец_цикла` |
| `когда` | `конец_когда` |
| `попробовать`/`поймать` | `конец_попробовать` |
| `процедура` | `конец_процедуры` |
| `модуль` | `конец_модуля` |

- **`=` как `==` в позиции условия** (пункт 1.1 требований: 52 случая): там, где
  ожидается **булево** выражение, — после `если`, `иначе_если`, `пока` — одиночный
  `=` читается как `==` (`если x = 5` ≡ `если x == 5`), включая вложенные вызовы в
  том же условии. Булевых позиций в языке ровно три (аудит `parseCondition`), и все
  три покрыты.
  **`когда` в их число не входит:** его голова — значение для сопоставления
  (AST-поле `scrutinee`, реестр `match_when` — «разбор перечня по вариантам»), а
  ветка `есть` обязана быть литералом перечня `Имя.вариант`
  (`compilerError`: «когда: в есть нужен литерал перечня Имя.вариант»), поэтому
  булева сопоставления в `когда` не существует и включать `=` там нечего.
  Вне условия `=` — присваивание; в выражении (например, в аргументе вызова) это
  ошибка (граница зафиксирована тестом).
- Несовпадение закрытия — ошибка: `конец_пока` не закрывает `если`
  («Закрытие не совпадает: блок «если» закрывается 'конец_если' или 'конец'»).
- Инвариант: программа с `конец` даёт **тот же байткод**, что с `конец_X`
  соответствующего блока (оракул `src/compiler/blockClosers.test.ts`).
- `конец` — **контекстный** токен, а не зарезервированное слово: в позиции имени
  он работает как обычное имя (`тип Объект = { конец: Число }`, `о.конец`,
  `процедура f(начало, конец)`).
  В выражении `конец` — тоже имя: `вернуть конец` возвращает переменную. Значение
  `вернуть` берётся с той же строки, пустой `вернуть` + `конец` следующей строкой —
  это пустой возврат и закрытие блока.
- `конец_файла` — вид токена, а не ключевое слово; слово `конец_файла`
  в исходнике блок не закрывает.
- Ветвления:
  - `если ...`
  - `иначе_если ...`
  - `иначе ...`
  - `конец_если` (или legacy `конец`)
  - `тогда` после условия — опционально.
- Циклы:
  - `пока условие ... конец_пока` (`тогда` опционально);
  - `цикл ... конец_цикла`.
- Перебор:
  - `для item в collection ... конец_для`
  - `для item, index в collection ... конец_для`
  - алиас старой формы: `для_каждого` (тот же разбор)
  - в codegen реализуется через `система.массив.длина` + `система.массив.получить`.
- Управление циклом:
  - `прервать`
  - `продолжить`.
- **`пока_не` — не конструкция** (решение владельца: не добавлять). В позиции
  конструкции даётся точное сообщение: «нет конструкции 'пока_не'; используйте
  'пока не x'». Слово остаётся законным именем (`пусть пока_не = 5`,
  `пока_не = 1`, `пока_не(...)`) — диагностика молчит, если за ним присваивание,
  вызов, поле, индекс или конец строки.

## 8. Исключения

- `попробовать ... поймать err ... конец_попробовать` (алиас: `иначе_попытка`)
- `выбросить значение`
- `поймать` опционален: блок можно закрыть сразу (нужно для
  `конец_попробовать`).
- **`попробовать`/`поймать` ловит только `выбросить`.** Это граница конструкции,
  а не пожелание: перехватывается то, что программа выбросила сама — включая
  `выбросить` внутри вызываемой процедуры. **Ошибка машины не перехватывается:**
  `10 div 0` останавливает программу с ошибкой исполнения, и `поймать` до неё не
  доходит (проверено прогоном, 2026-09-23). Поэтому делитель проверяют **до**
  деления, а не надеются на перехват:

  ```osnova
  если б == 0
    выбросить "делить на ноль нельзя"
  конец_если
  вернуть а div б
  ```
- В байткоде:
  - `try_begin`, `try_end`, `throw`
  - переход в catch-блок через patch offset.

## 9. Системные модули и вызовы

**Реестр синонимов (пункт 1.5 требований).** Модель почти не изобретает
конструкции — она подставляет синоним системного вызова. Лечится словарь, а не
грамматика: `SYSCALL_ALIASES` (`src/runtime/vm/invokeRegistry.ts`) сводит
известный синоним к канону там, где имя попадает в AST, — семантика,
кодогенерация и обе VM видят одно имя. Приём не меняет язык и не открывает новых
способов ошибиться.

**Замер, на котором стоит таблица** (2026-09-23): перекомпилированы **3607**
сохранённых исходников из `runs/traces.jsonl`; замер воспроизводим —
`npx tsx src/scripts/traceDiagnosticsReport.ts`. После первых четырёх синонимов
осталось **25** различимых имён; каноническая цель **доказана** для 18 (цель есть
в реестре И арность канона совпадает с арностью реального вызова в следе).

| Пишут | Канон |
|---|---|
| `система.хранилище.получить` | `система.хранилище.прочитать` |
| `система.хранилище.сохранить` | `система.хранилище.записать` |
| `система.окно.вывод` | `система.лог.вывести` |
| `система.строка.срез` | `система.строка.подстрока` |
| `система.вывести`, `система.вывод.текст`, `система.окно.вывестиТекст` | `система.лог.вывести` |
| `система.окно.отобразить` | `система.окно.показать` |
| `система.окно.создать` | `система.окно.создать_окно` |
| `система.окно.ввод` | `система.ввод.текст` |
| `система.сеть.отправить` | `система.сеть.пост` |
| `система.строка.из`, `система.строка.изЧисла` | `система.строка.из_числа` |
| `система.хранилище.загрузить` | `система.хранилище.прочитать` |
| `система.хранилище.получить_элемент` | `система.массив.получить` |
| `система.хранилище.удалить_элемент` | `система.массив.удалить` |
| `система.хранилище.добавить` | `система.массив.добавить` |
| `система.число.остаток` | `система.математика.остаток` |

Три пары выбраны **по арности, а не по модулю в имени**: `хранилище.получить_элемент`,
`хранилище.удалить_элемент` и `хранилище.добавить` вызываются как
`(массив, индекс)` и `(массив, элемент)`. Набросок §1.5 требований
(«`получить` → `прочитать`») дал бы `syscall_argc`: следы важнее наброска.

**Не переписаны (канонической цели нет — выдумывать вызовы нельзя):**
`система.результат.успех`/`.ошибка`/`.неудача` (ждут типа `Результат`, БЛОК 3);
`система.объект.создать` и `система.типы.создать` (канон — объектный литерал и
объявление типа, а не вызов; у `типы.создать` уже есть точная подсказка
`invented_syntax`); `система.вызов.вызвать` (динамического вызова в языке нет);
`система.сеть.доступен`/`доступно` (проверки доступности в реестре нет);
`система.строка.символ` (нужна не замена имени, а преобразование аргументов);
`система.уведомления.показать`, `система.конвертация.целое32` (таких модулей и
операций в реестре нет); `система.хранилище.установить_поле` (уже имеет точную
подсказку `invented_syntax`); `система.строка` (усечённое имя — по нему одному
цель не определяется).

Карта — по **полному** имени: `система.массив.получить` и `система.сеть.получить`
— канонические имена, и сегментная замена `получить` → `прочитать` их бы сломала.
Неизвестный вызов по-прежнему даёт `unknown_syscall`. Эффект пополнения замерен тем
же замером: `unknown_syscall` **34 случая / 20 имён → 16 случаев / 9 имён**.

Системные вызовы — это host invoke (`op: "invoke"`), а не отдельные опкоды языка.

### 9.1 `система.массив.*`

- `создать()` -> новый массив.
- `добавить(arr, value)` -> добавляет элемент; возвращает `null` (не массив).
- `установить(arr, idx, value)` -> запись по индексу.
- `удалить(arr, idx)` -> удаление по индексу.
- `срез(arr, from, to)` -> новый подмассив.
- `длина(arr)` -> длина.
- `получить(arr, idx)` -> элемент или `null` вне диапазона (default VM).

### 9.2 `система.строка.*`

- `объединить`, `длина`, `содержит`, `начинается_с`, `заканчивается_на`,
  `подстрока`, `в_верхний`, `в_нижний`, `обрезать`, `заменить`, `разделить`, `найти`.
- В default VM реализованы все, кроме `найти` (для него нужен host invoke).

### 9.3 `система.хранилище.*`

- `записать`, `прочитать`, `удалить`, `ключи`, `ключи_с_префиксом`.
- В default VM есть in-memory реализация map-хранилища.

### 9.4 `система.время.*`

- Реестр invoke: `сейчас`, `метка`, `разобрать`, `форматировать`,
  `добавить_дни`, `разница_дней`, `спать`.
- В default VM реализованы:
  `метка`, `разобрать`, `форматировать`, `добавить_дни`, `разница_дней`.
- `сейчас` и `спать` требуют внешнего invoke-обработчика.

### 9.5 Прочие зарегистрированные invoke

- `система.лог.вывести`
- `система.файлы.*`
- `система.сеть.*`
- `система.окно.*`
- `система.интерфейс.*`
- `система.объект.получить`
- `система.json.*`
- `система.ввод.текст`

Все перечисленные имена известны VM через `invokeRegistry`.
Фактическая бизнес-реализация зависит от переданного `invoke` handler (или default VM).

## 10. Ограничения v2.3.2

- В одном исходном файле поддерживаются несколько `модуль ... конец` блоков.
- Импорт (`использовать`) только в начале модуля.
- `тип`-объявления только до процедур.
- Точка входа программы выбирается из первого модуля в порядке объявления в файле.
- Семантика вызовов пользовательских процедур внутри одного компилируемого
  (после expand import) AST: неизвестные вызываемые имена считаются ошибкой.
- Процедуры высшего порядка (передача процедур как значений) не поддержаны.

## 11. Программа из нескольких модулей

Один `.osnova` файл может содержать несколько модулей, каждый в форме
`модуль ... конец`. Модули объявляются последовательно, в порядке сверху вниз.
Точка входа программы выбирается из первого модуля в файле.

Пример:

```osnova
модуль Библиотека
процедура экспорт удвоить(x)
  вернуть x * 2
конец
конец

модуль Главный
использовать модуль Библиотека из "lib.osnova"
процедура главная()
  вернуть Библиотека.удвоить(21)
конец
конец
```

## 12. Semantic diagnostics

Семантический анализ возвращает `kind`-коды ошибок. Они делятся на blocking и
non-blocking.

### 12.1 Blocking kinds

- `unknown_syscall` — вызов несуществующего `система.*` syscall.
- `undeclared_var` — использование переменной без объявления через `пусть`.
- `unknown_procedure` — вызов неизвестной процедуры в модуле/namespace.
- `syscall_argc` — неверное число аргументов у системного вызова.
- `redeclare_var` — повторное объявление переменной через `пусть`.
- `invented_syntax` — вымышленные конструкции вне канона языка.

### 12.2 Non-blocking kinds

- `chained_compare` — цепочечные сравнения вместо явного `и`.
- `keyword_param` — параметр процедуры использует ключевое слово.
- `sentinel_pattern` — sentinel-инициализация `пусть x = пусто` вне try/catch.
- `unknown_module` — ссылка на модуль, который не найден среди доступных.
- `export_collision` — коллизия экспортируемых имен между провайдерами namespace.
