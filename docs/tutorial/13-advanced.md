# 13. Продвинутое: VLIW и e2k

Этот раздел — про то, во что превращается программа после компиляции. Для
повседневной работы он не нужен, но объясняет, почему у языка такое устройство и
почему часть вещей пока не работает.

## Коротко о VLIW

Обычный процессор выполняет инструкции по очереди. VLIW-процессор получает
**пакет** инструкций и запускает их за один такт. Что с чем можно объединить в
пакет, решает компилятор, а не процессор.

Значит, компилятору важно знать:

- какие вычисления независимы друг от друга и могут идти в одном такте;
- сколько тактов ждать результат каждой операции;
- в какой канал процессора попадает операция.

## Что делает проект

Байткод `.osvbc.json` — не машинный код. Дальше есть три слоя:

1. **Регистровая машина.** Тот же байткод переводится в регистровые инструкции и
   исполняется второй VM. Стековая и регистровая VM сверяются между собой: обе
   должны дать одинаковый результат.
2. **Планировщик.** Регистровые инструкции раскладываются по тактам и каналам —
   получаются пакеты для VLIW.
3. **Кодировщик e2k.** Пакеты превращаются в байты команд семейства Эльбрус и
   собираются в ELF-файл.

Проверить второй слой можно на своей программе. Собери её и запусти сверку:

```bash
npx tsx src/cli.ts parity ядро.osnova
```

Вывод будет примерно такой — обе машины считают одно и то же:

```text
[OK] ядро.osnova
  статус:          ok
  стековая VM:     25
  регистровая VM:  25
  шагов трассы:    1
  сверка:          совпало: 25 (трасса 1 шагов)
```

Планирование в пакеты показывает команда `schedule`, ей нужен байткод модуля с
одной процедурой:

```bash
npx tsx src/cli.ts schedule ядро.osvbc.json
```

На выходе — тот же модуль, но версии 2: вместо линейного списка инструкций в нём
пакеты с зависимостями.

## Программа для проверки

Вот файл `ядро.osnova`, на котором всё это видно. Он считает `3*3 + 4*4`:

```osnova
модуль ядро

процедура главная(): Число
  пусть а = 3
  пусть б = 4
  пусть с = а * а + б * б
  вернуть с
конец_процедуры

конец_модуля
```

Скомпилируй и сверь:

```bash
npx tsx src/cli/index.ts compile ядро.osnova
npx tsx src/cli.ts parity ядро.osnova
```

Ответ `25` придёт из двух независимых исполнителей.

## Что уже работает, а что нет

**Работает.** Кодировщик e2k-команд, минимальный ELF, системные вызовы `write` и
`exit` без libc, планировщик, сверка двух VM. Цифровые фильтры (FIR, IIR, БПФ,
свёртка, корреляция) собираются и исполняются в модели e2k — результат сверяется
с независимым эталоном, у FIR это `181`.

**Не работает.** В e2k-код переводится не весь язык: вызовы хост-функций
(`система.*`), часть операций с массивами и ветвлений пока остаются без
понижения. QEMU — модель, а не железо: часть выводов о процессоре проверяется
только на настоящей машине.

Если тебе нужен просто рабочий язык — этот раздел можно забыть. Всё, что было в
предыдущих разделах, работает на виртуальной машине и от e2k не зависит.
