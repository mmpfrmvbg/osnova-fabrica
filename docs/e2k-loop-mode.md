# Loop mode (`lm`, HS бит 10): что извлечено и что осталось

**Сеанс:** 2026-09-19 (шаг C). **Только чтение источников.**
**Правило:** каждое утверждение — источник (`файл:строка` или страница). Чего нет — «НЕТ В
ИСТОЧНИКЕ». Отдельный раздел — «ЧТО ОСТАЛОСЬ НЕ ИЗВЛЕЧЕНО»: там вещи, которые в источниках
**есть**, но не разобраны в этом сеансе. Смешивать их с «НЕТ В ИСТОЧНИКЕ» нельзя.

---

## 1. Что такое `lm` и где он живёт

| утверждение | источник |
|---|---|
| `lm` — бит 10 заголовочного слога HS | `qemu-e2k/qemu/target/e2k/syllab-format.h:20` — `FIELD_BIT(HS, lm, 10)` |
| в описании HS этот бит назван `loop_mode` | `elbrus-docs/README.md:195` — `10 \| loop\_mode \|` |
| **включение — псевдо-инструкция ассемблера**: `loop_mode` не операнд, а отдельная директива, которая ставит бит | `binutils-gdb/gas/config/tc-e2k.c:10292-10298` — `parse_loop_mode_args` делает `wc.lm = 1;` |
| `loop_mode` зарегистрирован как запись таблицы опкодов с этим разборщиком | `binutils-gdb/opcodes/e2k-opc.c:491` — `E2K_OPCODE_VEC_ENTRY (loop_mode, ISET_ALL_COMPAT_MASK, parse_loop_mode_args)` |
| дизассемблер и QEMU печатают признак открытым текстом | `binutils-gdb/opcodes/e2k-dis.c:1559` (`my_printf ("loop_mode")`); `qemu-e2k/qemu/target/e2k/disas.c:1093-1095` |

**Следствие для нас.** Loop mode — **свойство широкой команды целиком** (бит в её заголовке), а не
отдельная операция в слоте. Поэтому включить его можно только на команде, у которой уже есть
структура — то есть вопрос упирается в то, **что** эта команда несёт.

## 3. Как включается режим: переход состояния в QEMU

**ИСТОЧНИК: `qemu-e2k/qemu/target/e2k/tcg/translate.c:164-204`** — функция
`e2k_tr_update_and_check_lsr_state_for_new_wi(dc, lm)`. Из неё следует:

| утверждение | строка |
|---|---|
| режим **включается**, когда встречается команда с `lm = 1` | `:175-178` |
| режим **выключается**, когда встречается команда с `lm = 0` (кроме случая `mlock_detour`) | `:166-173` |
| при включении ищется **предыдущее определение LSR** до текущего адреса | `:184-191` (`e2k_find_previous_lsr_def`) |
| если определение найдено и оно **непосредственное** (`is_imm`), включается `is_lsr_mode` и счётчики читаются из LSR | `:193-204` |
| состояние переносится в флаги трансляции и восстанавливается из них | `:445`, `:98` |
| при сбросе процессора `is_in_loop_mode = false` | `cpu.c:425` |

**Что это значит.** Режим цикла **не самодостаточен**: он работает в связке с **предыдущим
определением LSR**. Команда с `lm` без определённого LSR в QEMU не даёт счётчиков.

## 4. `ALC` — настройка счётчиков цикла

| утверждение | источник |
|---|---|
| `ALC` — инструкция слога SS: «adjust loop counters», два поля `alcf` и `alct` | `llvm-project/llvm/lib/Target/E2K/E2KInstrInfo.td:77-78` — `def ALC : SSInst<(outs), (ins u8imm:$alcf, u8imm:$alct), "alc alcf=$alcf alct=$alct">;` |
| ассемблер разбирает `alc alcf=…, alct=…` в поля слога SS | `binutils-gdb/gas/config/tc-e2k.c:10309-10331` (`parse_alc_args`, `SET_FIELD (ss, alct, …)`, `SET_FIELD (ss, alcf, …)`) |
| `alc` зарегистрирован в таблице опкодов | `binutils-gdb/opcodes/e2k-opc.c:492` |
| декодер QEMU относит `alc` к «misc»-операциям слога SS | `qemu-e2k/qemu/target/e2k/decoder.c:908` — `decoded_ops->misc_ops[…].op = E2K_OP_ALC;` |
| дизассемблер печатает `ALC alcf=%u alct=%u` | `qemu-e2k/qemu/target/e2k/disas.c:219`; также `opcodes/e2k-dis.c:1862` — `my_printf ("alc alcf=%d, alct=%d", alc >> 1, alc & 0x1)` |
| **значение `alc = 0b11` (оба поля единицы) означает «корректировать всегда»** | `qemu-e2k/qemu/target/e2k/tcg/translate-misc.c:660-665` — `dc->instr_state.have_alc_always = (alc == 0b11);` |
| «всегда» влияет на передачу управления по предикату | `qemu-e2k/qemu/target/e2k/tcg/translate-ct.c:425`, `:627` — условия с `&& !dc->instr_state.have_alc_always` |
| `ALC` связан с MOVA/AAU-состоянием | `qemu-e2k/qemu/target/e2k/tcg/translate-mova.c:477` — проверка `have_alc_always && (aau_dirty_state != …)` |

## 5. MOVA и AAS-слог

| утверждение | источник |
|---|---|
| таблица `MOVA` из 8 записей: `MOVAB`, `MOVAH`, `MOVAW`, `MOVAD`, `MOVAQ`, `MOVAQP` | `qemu-e2k/qemu/target/e2k/opcode-tables.c:1744-1753` |
| MOVA декодируются **отдельно** от ALS и помечаются маской каналов | `qemu-e2k/qemu/target/e2k/decoder.c:769-797` (`mova_mask`, `mova_ops[ch]`) |
| число слогов MOVA в команде — 4 | `qemu-e2k/qemu/target/e2k/syllab-format.h:227` — `#define E2K_MOVA_NUM 4` |
| MOVA исполняются helper'ами (чтение/запись памяти) | `qemu-e2k/qemu/target/e2k/helper.h:512-517` (`e2k_exec_mem_MOVAB…MOVAQP`) |
| в binutils `MOVAB…MOVAQ` кодируются **слогом AAS**, а не ALS | `docs/e2k-opcodes-real.md:192`; `gas/config/tc-e2k.c:4635` (`parse_mova_args`), `:4657` (MOVAQ) |

**Чего здесь нет:** связи MOVA с loop mode в явном виде — какое поле LSR какой MOVA использует.
**НЕ ИЗВЛЕЧЕНО** (см. §7).

## 6. Асинхронная подкачка массивов — рядом, но не то же самое

| утверждение | источник |
|---|---|
| поле `bap` (начало подкачки массивов) — бит 28 слога SS | `elbrus-docs/README.md:208` |
| поле `eap` (конец подкачки) — бит 29 | `:207` |
| инструкции подкачки массивов исполняются **асинхронно** на устройстве доступа к массивам | `elbrus-docs/README.md:396` |
| адреса в подкачке должны **линейно зависеть от номера итерации** | руководство МЦСТ, §4.5, стр. 58 (`.tmp/elbrus-prog.txt:3071-3075`) |
| для подкачки есть отдельный вызов `ldisp` в `%ctpr2` | `elbrus-docs/README.md:312`, `:399` |

**Следствие.** Подкачка массивов и loop mode — **разные** механизмы, но оба требуют цикла, и оба
формируются компилятором. В нашей модели устройств APB уже описан (`src/vliw/e2kDevices.ts:47`), а
код подкачки не генерируется вовсе.

## 7. ЧТО ОСТАЛОСЬ НЕ ИЗВЛЕЧЕНО (есть в источниках, но не разобрано здесь)

Это не «НЕТ В ИСТОЧНИКЕ»: это честный список долга извлечения.

| что | где лежит | почему не закрыто здесь |
|---|---|---|
| **семантика счётчиков `vlc`/`pcnt`/`ecnt`/`lcnt` при исполнении**: что декрементируется, что означает `over` | `qemu-e2k/qemu/target/e2k/` — обработчики LSR (`cpu-sregs.h:253-262`, потребители в `tcg/*`) | потребители LSR в TCG-трансляции объёмны; для точного правила нужен отдельный разбор, а не догадка |
| **полная таблица «какие операции слога SS делает ALC»** | `qemu-e2k/qemu/target/e2k/tcg/translate-misc.c:567`, `:734` | разобрана только ветка `have_alc_always` |
| **связь MOVA ↔ LSR ↔ авто-инкремент адресов** | `tcg/translate-mova.c` (файл есть, 477+ строк) | не читался |
| **что печатает дизассемблер МЦСТ для MOVA в тексте** | `opcodes/e2k-dis.c` | не проверялось |
| **точные страницы руководства по loop mode** | руководство МЦСТ, стр. 58 (`.tmp/elbrus-prog.txt:3055-3070`) говорит о **программной конвейеризации** и «средствах управления режимами выполнения пролога и эпилога», но слова `loop_mode` в руководстве нет | поиск по «loop» в руководстве даёт разделы про конвейеризацию, а не про бит; связь бита с этим разделом **не доказана** |

## 8. ГИПОТЕЗА: выигрыш (требует замера на QEMU или железе)

**Ни одно число здесь не измерено.** Все величины ниже — оценки, основанные на уже измеренных
величинах проекта, и каждая обязана быть проверена замером прежде, чем попасть в план как эффект.

| оценка | основание | чем проверять |
|---|---|---|
| loop mode способен занять часть из **4000 пустых слогов** (81 % каналов в пяти ядрах) | замер шага 1: заполнено 920 из 4920 (`docs/brainstorm/05-step1-measurement.md`) | посчитать, сколько слогов в циклах ядер; сравнить с числом циклов |
| экономия «одной итерации» — это экономия **команд управления циклом** (сравнение + переход), а не тактов конвейера | переход в модели стоит 5 тактов (`src/e2k/latencyMap.ts:185`); предикатное сравнение — 1 такт ALU (`:156`) | прогон в QEMU: два варианта одного цикла, счётчик инструкций QEMU — **не такты железа** (`docs/hardware-debt.md:179`) |
| **ГИПОТЕЗА верхней границы:** экономия не больше числа команд, которые цикл тратит на управление | если цикл из 20 команд тратит 3 на управление, потолок — 15 % | тот же прогон |
| связь с 81 % пустых слогов **не доказана**: loop mode заполняет слоты только если в цикле есть независимая работа | прямого источника нет | сначала найти независимую работу (перестановка + снятие литеральных барьеров), потом мерить |

**Чего в источниках нет вовсе:** ни одной величины «сколько тактов экономит loop mode». Руководство
МЦСТ описывает механизм, но не даёт числа.

## 9. Что нужно, чтобы включить (карта, без реализации)
