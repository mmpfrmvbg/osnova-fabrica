# Возврат в порте QEMU/e2k: что исполняется, что охраняет утверждение и какой обход не трогает порт

**Дата:** 2026-09-20
**Зачем:** шаг 3 критического пути упёрся в порт: понижение `IR.ret` выдаёт `return %ctpr3`, и образ
с этой командой падает на утверждении `op_descr->is_al` (`translate-lookahead.c:318`, статус 134).
Здесь — разведка: что именно охраняет утверждение, какие формы возврата есть у порта, какой ход
исполняется в модели и какие ходы требуют решения владельца.
**Чем проверяется:** `src/e2k/e2kCallWindowQemu.test.ts` (шлюз `npm run gate:qemu`) — три исхода
возврата названы числами: 134, 9 и 99. Опыты-черновики — `.tmp/return-forms-probe.ts`,
`.tmp/return-works.ts`, `.tmp/return-bytes.ts`, `.tmp/assert-trigger.ts`, `.tmp/pack-check.sh`.
**Исходник порта не правился** — так решено владельцем; все выводы получены прогонами наших байтов.

## 1. Коротко

| ход | что в порте | замер |
|---|---|---|
| `return %ctpr3` (CS0) **одна** | **не переход**: порт пишет ctpr3 с `opc = RETURN` и продолжает | **падение на утверждении**, статус **134** |
| `ct %ctpr3` (SS) **одна**, без подготовки | переход по ctpr3; после `call` ctpr3 пуст (тег `CTPEW`) | **гостевое исключение**, статус **9** |
| `return %ctpr3` **и** `ct %ctpr3` подряд | подготовка, затем переход через `e2k_cpu_exec_ct_return` | **управление вернулось**, статус **99** |
| `disp %ctpr3, 1` + `ct %ctpr3` | переход по значению `disp` (opc = DISP, не RETURN) | прогон не завершился (`.tmp/return-forms-probe.ts`, опыт F) — **не результат** |

Итог: возврат в этой модели даётся **парой** из двух восьмибайтных команд. Обе команды совпали
побайтово с ассемблером МЦСТ (раздел 4), то есть это не самодельная кодировка, а измеренный ход.

## 2. Что охраняет утверждение

Утверждение стоит внутри цикла по AL-каналам и охраняет **инвариант порта**:

```
for( int ch = 0; ch < E2K_ALS_NUM; ch++ )            /* translate-lookahead.c:309 */
{
    if( (instr_decoded->al_mask & (1u << ch)) == 0 )
        continue;
    const E2KDecodedAlOp * op_decoded = &instr_decoded->al_ops[ch];
    const E2kOpDescr * op_descr = &e2k_operation_descrs[op_decoded->op];
    ...
    assert(op_descr->is_al);                          /* translate-lookahead.c:318 */
```

Читается так: **если порт решил, что в AL-канале есть операция, то её описание обязано быть AL-операцией**
(`E2kOpDescr.is_al`, `operations-descr.h:164-180`). Маска каналов берётся из поля `HS.al`
(`decoder.c:109`), а бит в маске ставится там, где порт нашёл операцию
(`decoder.c:616-619`, перед этим `assert((op != E2K_OP_NONE) && …)`).

**Наши байты тут ни при чём — это проверено, а не предположено.** Ассемблер МЦСТ на текст
`return %ctpr3` выдаёт ровно наши восемь байтов:

```
наш кодировщик: 01 40 00 00 00 00 00 f0
MCST as (WSL1, -mcpu=elbrus-v5): 01 40 00 00 00 00 00 f0
```

То же для SS-формы: `ct %ctpr3` → `01 10 00 00 20 0c 00 c0`. Обе строки — из
`.tmp/return-bytes.ts` и `.tmp/pack-check.sh`; `as` собирает в `/root/build-gas/gas/as-new`
(WSL1-дистрибутив `e2k`), байты читаются `od -An -tx1 -v`.

**Признак не удалось локализовать правкой порта — правка запрещена.** Что измерено вместо этого:
перебор вариантов **своих** байтов (`.tmp/assert-trigger.ts`) дал утверждение на всех восьми
вариантах — то есть по одним байтам задеть утверждение не удалось, а по **последовательности**
удалось (раздел 3). Это и есть честная граница разведки: механизм «почему пара проходит, а одна
команда нет» в исходнике не измерен.

## 3. Что порт на самом деле делает с `return`, `call` и `ct`

**`return %ctpr3` в порте — производитель ctpr3, а не переход.** Ветка `E2K_OP_RETURN` целиком
состоит из записи дескриптора и заканчивается `break`, прыжка в ней нет:

```
case E2K_OP_RETURN:                                  /* translate-ctp.c:110 */
    const uint8_t j = FIELD_EX32(instr_decoded->cs0, C0F, ctpr);
    assert(j == 3);                                   /* translate-ctp.c:115 */
    e2k_sreg_CTPR_t ctpr_new_val = E2K_SREG_INIT_CTPR;
    ctpr_new_val = FIELD_DP64(ctpr_new_val, CTPR, opc, E2K_CTPR_OPC_RETURN);  /* :122 */
    ctpr_new_val = FIELD_DP64(ctpr_new_val, CTPR, tag, E2K_CTPR_TAG_CTPPL );  /* :123 */
    tcg_gen_st_i64(tcg_constant_i64(ctpr_new_val), tcg_env, …);
    dc->ctpr_defs[j-1].def.is_ret = true;             /* :131 */
```

**`call` стирает все ctpr — возврат в ctpr3 он не кладёт.** В конце `e2k_cpu_exec_ct_CALL`:

```
e2k_sreg_CTPR_t ctpr_empty = 0;
ctpr_empty = FIELD_DP64(ctpr_empty, CTPR, tag, E2K_CTPR_TAG_CTPEW);
for( int k = 1; k <= E2K_CTPR_NUM; k++ )
    env->sregs.ctpr[k-1] = ctpr_empty;               /* translate-ct.c:1135-1138 */
```

**Переход делает `ct` (SS), и адрес возврата берётся из кадра вызова, а не из ctpr3:**

```
if( (j == 3) && (ctpr_opc == E2K_CTPR_OPC_RETURN) )
    return e2k_cpu_exec_ct_return(env);              /* translate-ct.c:875-877 */
```

```
e2k_sreg_IP_t e2k_cpu_exec_ct_return(CPUE2KState *env)      /* translate-ct.c:25 */
{
    const uint cwd_base_q = FIELD_EX32(env->sregs.cwd, CWD, base_q);
    const e2k_sreg_CR0_HI_t cr0_hi = env->cf.cr_pairs[cwd_base_q/2].cr0_hi;
    const e2k_sreg_IP_t next_ip = FIELD_EX64(cr0_hi, CR0_HI, ip);   /* :35 */
```

Отсюда и следствие: **последовательность возврата в этой модели — `return %ctpr3` (подготовка тега
`RETURN`) плюс `ct %ctpr3` (переход)**. Одна `ct` без подготовки идёт по пустому тегу `CTPEW`, и порт
поднимает гостевое исключение («exception handling is unimplemented», `helper_e2k_prep_ct_CT`,
`translate-ct.c:840-844`).

**Другие формы возврата: индекса, кроме третьего, нет.** Возврат привязан к `%ctpr3` не нашим
выбором, а проверками порта: ветка `E2K_OP_RETURN` требует `assert(j == 3)` (`translate-ctp.c:115`),
а `ct` с тегом `RETURN` и другим индексом отвергается —

```
else if( (ctpr_opc == E2K_CTPR_OPC_RETURN) && (j != 3) )     /* translate-ct.c:860-864 и :956-960 */
{
    e2k_cpu_set_have_exception(env);
    /* TODO: Set exc num exc_illegal_instr_addr. */
}
```

То есть перебрать «другой `%ctpr`» нельзя: формы возврата в порте ровно три — одна CS0 (одна не
исполняется), одна SS (одна не исполняется) и их пара. Подготовка `disp %ctpr3, <n>` вместо
`return %ctpr3` даёт тег `DISP`, а не `RETURN`, и `ct` уходит в общий путь перехода по значению
`disp` (опыт F в таблице раздела 4 — прогон не завершился, поэтому это **не результат**, а названная
причина, почему четвёртая форма не рассматривается как рабочая).

## 4. Замеры

Программа одна и та же: вызывающий делает `setbn`, кладёт метку, `disp` + `call wbs=4`, а после
вызова — выход кодом **99**; тело (вызванная процедура) пишет 42 в свой `%r7` и возвращается одним из
способов. «99» значит «управление вернулось И выход вызывающего после возврата проходит».
Адреса считаются по длине кодирования, тело начинается на 0x100068.

| тело процедуры | статус | адрес ловушки | вывод |
|---|---|---|---|
| `movts` + `return %ctpr3` | 134 | — | утверждение порта: `Assertion failed: op_descr->is_al … translate-lookahead.c:318` |
| `movts` + `ct %ctpr3` | 9 | 0x100078 | гостевое исключение; адрес назван портом на **следующей** команде после `ct` (сама `ct` на 0x100070) |
| `movts` + `return %ctpr3` + `ct %ctpr3` | **99** | — | управление вернулось; выход вызывающего прошёл |

Одиночные опыты (`.tmp/return-forms-probe.ts`) с программой из одной команды:

| программа | статус |
|---|---|
| `return %ctpr3` | 134 (утверждение) |
| `ct %ctpr3` (в начале программы) | 9, ловушка на адресе самой `ct` (0x100000) — адрес ловушки у порта зависит от места |

**Поправка к прежним записям.** В `docs/e2k-opcodes-real.md` §7.10 и `docs/hardware-debt.md`
§3.17–3.18 было записано: «системный вызов вызывающего ПОСЛЕ возврата падает с `syscall without proper
WD configuration`; геометрия окна не восстанавливается». **Эта запись неверна и снята**: она
наблюдалась тогда, когда возврата не было вовсе (порт падал на утверждении), и падение
приписывалось возврату. В опыте с парой выход вызывающего кодом **99** проходит, то есть геометрия
окна восстанавливается — `e2k_cpu_exec_ct_return` возвращает `WD` из кадра
(`translate-ct.c:56-67`: `size_q = psize_q + wbs`, `psize_q = wpsz`).

## 5. Ход, не трогающий порт

Понижение возврата выдаёт **две** команды вместо одной (16 байт вместо 8):

```
return %ctpr3        ; подготовка: тег RETURN в ctpr3 (translate-ctp.c:121-123)
ct %ctpr3, <cond>    ; переход: e2k_cpu_exec_ct_return (translate-ct.c:875-877)
```

Обе команды — те же байты, что у ассемблера МЦСТ; **одним словом они не пакуются**: `as` на две
строки `return %ctpr3` и `ct %ctpr3` выдаёт 16 байт (`.tmp/pack-check.sh`, опыт v3). То есть пара —
это две отдельные команды потока, а не одно широкое слово.

**Цена:** +8 байт на каждый возврат; байты ядер меняются, оракул байтов об этом обязан знать
(`src/e2k/e2kSyllables.test.ts` сверяет с `as` по образцам, а не по числу байт программы).

## 6. Чего разведка НЕ доказывает и что требует решения владельца

1. **Механизм обхода утверждения не найден.** Почему пара проходит, а одиночная CS0-команда задевает
   `assert(op_descr->is_al)` — по исходнику не измерено (перебор наших байтов утверждение не снимает,
   раздел 2). Это **долг разведки**, а не решение.
2. **Что делает пара на железе — не доказано.** ISA описывает `return %ctpr3` как сам возврат; в этой
   модели он лишь готовит ctpr3, и переход делает следующая `ct`. Если на железе возвращает уже
   `return`, то вторая команда недостижима (вреда нет, но это допущение, а не факт).
3. **Правка порта — предложение, а не действие.** Наименьшая правка, которая сделала бы одиночный
   `return` исполняемым: в `e2k_cpu_exec_ct_CALL` не стирать ctpr3 в пустой тег, а записывать в него
   дескриптор возврата с `next_ip` — так, как это уже делает ветка `E2K_OP_RETURN`
   (`translate-ctp.c:120-126`). Порядок тот же, что и в прежних долгах: **решение владельца**.
4. **Бюджет регистров вызываемой этим не лечится.** Пара возвращает управление, но окно вызываемой
   остаётся **восемь** регистров (`docs/hardware-debt.md` §3.17–3.18): `фильтр` FIR нужно 10,
   `свёртка` — 11 (см. §3.16). То есть шаг 4 упирается уже не в возврат, а в регистры.

## 7. Как повторить

```
npx vitest run --config vitest.qemu.config.ts src/e2k/e2kCallWindowQemu.test.ts
npx tsx .tmp/return-works.ts        # три исхода возврата в одной таблице
npx tsx .tmp/return-bytes.ts        # наши байты против as (нужен WSL-дистрибутив e2k)
& 'C:\Program Files\WSL\wsl.exe' -d e2k -- bash /mnt/d/PROJECTS/OSNOVA-FABRIKA/.tmp/pack-check.sh
```

Оракул в шлюзе называет все три исхода (134 / 9 / 99) и падает, если хотя бы один изменится: если
порт когда-нибудь начнёт возвращать одиночной командой, это будет видно как расхождение ожидания,
а не как «стало лучше».
