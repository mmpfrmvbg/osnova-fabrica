Выявлено из 39 repair_exhausted трейсов (19.03.2026):

## Тест 3: Процедура, пусть, присваивание, вызов с «вызвать»

**Источник:**

```основа
модуль тест3;

процедура старт() {
    пусть счётчик = 0;
    счётчик += 1;
    вызвать печать(счётчик);
}
```

**Токены (ключевые):**

- После `процедура старт ( ) {`: `KwПусть Identifier Assign IntLiteral Semicolon`
- Затем: `Identifier PlusAssign IntLiteral Semicolon`
- Затем: `KwВызвать Identifier LParen Identifier RParen Semicolon`

**AST:**

- `ProcedureDecl(name: "старт", params: [], body: Block)`
  - `LetStmt(name: "счётчик", init: IntLiteral(0))`
  - `AssignStmt(lhs: Identifier("счётчик"), op: "+=", rhs: IntLiteral(1))`
  - `CallStmt(call: CallExpr(callee: Identifier("печать"), args: [Identifier("счётчик")]))`

**Байткод (очерёдность):**

- `const i32 0` → `local.set 0` (счётчик)
- `local.get 0` → `const i32 1` → `add` → `local.set 0`
- загрузка аргумента, затем `call fi` (печать) или `invoke` при внешней процедуре

## Тест 4: Функция, если/вернуть, унарный «не»

**Источник:**

```основа
модуль тест4;

функция готов(флаг: Логический): Логический {
    если не флаг { вернуть ложь; }
    вернуть истина;
}
```

**Токены (ключевые):**

- `KwФункция Identifier LParen Identifier Colon Identifier RParen Colon Identifier LBrace`
- `KwЕсли KwНе Identifier LBrace KwВернуть KwЛожь Semicolon RBrace`
- `KwВернуть KwИстина Semicolon RBrace`

**AST:**

- `FunctionDecl(name: "готов", params: [ParamDecl("флаг", TypeAnn("Логический"))], returnType: TypeAnn("Логический"), body: Block)`
  - `IfStmt(condition: UnaryExpr(op: "не", operand: Identifier("флаг")), thenBlock: Block([ReturnStmt(BoolLiteral(false))]), elseBlock: null)`
  - `ReturnStmt(value: BoolLiteral(true))`

**Байткод (идея):**

- Тело: загрузка `флаг`, унарный not (или `eq` с false) → `jmp_if_not` на вторую ветку; `const.false` → `ret`; метка второй ветки: `const.true` → `ret`.

## Тест 6: совпадает / когда Успех, Неудача

**Источник:**

```основа
модуль тест6;

процедура разбор() {
    совпадает загрузить("файл") {
        когда Успех(данные) { вызвать применить(данные); }
        когда Неудача(ошибка) { вызвать вывести(ошибка.текст); }
    }
}
```

**Токены (ключевые):**

- `KwСовпадает Identifier LParen StringLiteral RParen LBrace`
- `KwКогда KwУспех LParen Identifier RParen LBrace KwВызвать ... RBrace`
- `KwКогда KwНеудача LParen Identifier RParen LBrace KwВызвать ... RBrace`

**AST:**

- `MatchStmt(subject: CallExpr(callee: Identifier("загрузить"), args: [StringLiteral("файл")]), clauses: [ WhenClause(pattern: { tag: "Успех", binding: "данные" }, body: CallStmt(...)), WhenClause(pattern: { tag: "Неудача", binding: "ошибка" }, body: CallStmt(...)) ])`

**Байткод (идея):** вызов `загрузить` → результат на стек; проверка тега (Успех/Неудача); ветвление по тегу; в ветках — вызовы `применить`/`вывести` с соответствующим аргументом.

## Тест 8: параллельно, регион, пакет (VLIW — lowering)

**Источник:**

```основа
модуль тест8;

процедура vliw() {
    параллельно {
        пусть а = 1;
    }
    регион р1 {
        пусть б = 2;
    }
    пакет {
        слот0: пусть с = 3;
```

**Токены (ключевые):**

- `KwПараллельно LBrace ... RBrace`
- `KwРегион Identifier LBrace ... RBrace`

- `ParallelStmt(body: Block([LetStmt("а", IntLiteral(1))]))`

**Байткод (v0.1 — lowering):** без специальных инструкций; три блока генерируются как обычная последовательность: `const i32 1` → `local.set`; `const i32 2` → `local.set`; `const i32 3` → `local.set`.

## Микротест: Строковые литералы с escape

**Источник:**

```основа
модуль микро_строки;

процедура пути() {
    пусть p = "C:\\путь\\файл";
    пусть q = "строка\nс переносом";
}
```

**Токены (лексер):**

- Один токен `StringLiteral` с `lexeme` / сырой формой, содержащей обратные слэши и кавычки как в источнике (или нормализованный escape). Декодированное значение первого литерала: `C:\путь\файл` (обратные слэши после `\\` — один символ `\`).
- Второй `StringLiteral`: значение `строка\nс переносом` после обработки escape — в середине символ перевода строки.

**Проверка:** лексер выдаёт ровно два токена вида `StringLiteral`; их `value` после разбора escape: `C:\путь\файл` и `строка` + `\n` (один символ) + `с переносом`. Экранированные последовательности `\\`, `\n` обрабатываются согласно спецификации лексера.

## Микротест: Результат / ?Тип, пусто, Успех/Неудача (без match)

**Источник:**

```основа
модуль микро_результат;

тип Ошибка { текст: Строка; }

функция может_пусто(): ?Строка {
    вернуть пусто;
}

функция вернуть_успех(значение: Строка): Результат<Строка, Ошибка> {
    вернуть Успех(значение);
}

функция вернуть_неудачу(путь: Строка): Результат<Строка, Ошибка> {
    вернуть Неудача(Ошибка{ текст: "нет файла" });
}
```

**Токены (ключевые):**

- `KwПусто` в теле первой функции; тип возврата `Question Identifier` (`?Строка`).
- Для `вернуть_успех`: тип возврата `Identifier Less Identifier Comma Identifier Greater` (`Результат<Строка, Ошибка>`), возврат `KwУспех LParen Identifier RParen`.
- Для `вернуть_неудачу`: тот же тип возврата, возврат `KwНеудача LParen Identifier LBrace Identifier Colon StringLiteral RBrace RParen`.

**AST:**

- `FunctionDecl(name: "может_пусто", returnType: TypeAnn(optional: true, name: "Строка"), body: Block([ReturnStmt(value: NullLiteral)]))`.
- `FunctionDecl(name: "вернуть_успех", returnType: TypeAnn(name: "Результат", typeArgs: [TypeAnn("Строка"), TypeAnn("Ошибка")]), body: Block([ReturnStmt(value: SuccessExpr(Identifier("значение")))]))`.
- `FunctionDecl(name: "вернуть_неудачу", returnType: TypeAnn(name: "Результат", typeArgs: [TypeAnn("Строка"), TypeAnn("Ошибка")]), body: Block([ReturnStmt(value: FailureExpr(ConstructorExpr("Ошибка", fields: [{ name: "текст", value: StringLiteral("нет файла") }])))]))`.

**Байткод (связь с Result/Option):**

- Для `вернуть пусто`: на стек кладётся значение Option/None; инструкция вида `const.null` (или аналог), затем `ret`. Тип возврата — optional/Result-вариант.
- Для `вернуть Успех(значение)`: значение параметра загружается на стек, формируется Result с тегом Успех (например, запись тега + полезной нагрузки), затем `ret`.
- Для `вернуть Неудача(Ошибка{ ... })`: в стек константы/поля структуры Ошибка; построение значения Result с тегом Неудача (запись тега + полей структуры), затем `ret`. В байткоде должно быть видно: создание структуры Ошибка, установка тега Неудача, возврат.

Цель микротеста — убедиться, что типчекер и бэкенд связывают `?Тип`, `пусто`, `Результат<...>`, `Успех` и `Неудача` с ожидаемыми представлениями в байткоде (const.null, теги результата, поля структур), даже без разбора через `совпадает`.

## Как использовать

1. **Лексер:** для каждого теста 1–9 и микротеста «Строковые литералы с escape» подать источник в `tokenize(source)`; сравнить последовательность `tokens[].kind` (и при необходимости `lexeme`/`value` для строк) с эталонной последовательностью токенов (игнорируя пробелы/комментарии).
2. **Парсер:** подать токены в `parse(tokens)`; проверить наличие ожидаемых узлов AST (например, по `kind` и ключевым полям: имена, типы, дочерние узлы).
3. **Компилятор:** после типчекера сгенерировать байткод; проверить наличие ожидаемых инструкций в нужном порядке (или подмножество/паттерн), для VLIW-теста — убедиться, что нет «магических» инструкций, только последовательный код. Микротест «Результат / ?Тип и пусто» проверяет связь Option/Result и `пусто`/`Неудача` с байткодом.
4. **Негативный тест 10:** убедиться, что парсер возвращает ошибку и не строит вызов как допустимый оператор.

Имена тестов (тест1 … тест10, микро_строки, микро_результат) можно использовать как идентификаторы сьютов в автоматических проверках фабрики.

## Тест VLIW-байткода v2

Эталон: **`src/tools/osnova-runtime/fixtures/vliw-example.osvbc.json`** (формат .osvbc version 2 с пакетами и зависимостями; см. `vliw-considerations.md`, п. 5.5).

**Валидация структуры:**

- `version === 2`, `vliwSlots === 4`.
- Процедура с именем `пример`: `argc === 0`, `localsCount === 2`.
- В процедуре присутствует поле **`deps`**: `deps.blocks` — массив диапазонов `{ start, end }`, `deps.edges` — массив пар индексов блоков; значения корректны (блоки в границах кода, рёбра по индексам блоков).

**Валидация пакета:**

- В массиве `code` есть элемент с **`packet: true`**.
- В нём массив **`slots`** из трёх инструкций (например: `local.get`, `const`, `add`).
- Поле **`deps`** пакета — массив из двух пар `[consumerSlotIndex, producerSlotIndex]` (например `[[2, 0], [2, 1]]`).

**VM-прогон:**

- Загрузить модуль из файла, вызвать процедуру **`пример`** (без аргументов).
