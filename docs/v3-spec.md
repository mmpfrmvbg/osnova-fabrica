# Основа: единственная спека языка (черновик)

> **Это единственная спека языка Основа.** Метка `v3` — **внутренняя**, обозначает текущую
> итерацию разработки. В продакшене — `docs/spec.md`, без метки. `src/spec/osnova-spec.ts` и
> `docs/language-v2.md` — **оракул предыдущей итерации (v2)**, reference (D21), не спека; retire —
> при продакшене. Расхождения v2↔v3 — осознанная эволюция (D59), не «две спеки».

**Дата:** 2026-11-08. **Статус:** черновик единственной спеки; D59. **Код не менялся.**
**Ветка:** `feat/lang-v2-block1`, вход `a9ccc407`.

`v2`/`v3` — внутренние метки итераций, **не отдельные языки**. Если v2 и v3 говорят разное,
актуально то, что сказано здесь; v2 — устаревший reference. Это не «v2 говорит одно, v3 другое»,
а «v2 устарело, v3 — актуально».

В реестре документ помечен `active` — это **рабочий фронт**, а не `scratch`-разведка: черновик
единственной спеки, по которому идёт AST 2.0. `scratch` был бы ложью о роли документа.

## 1. Актуальная лексика

Ключевые слова и формы:

```text
процедура действие если иначе «иначе если» пока вернуть пусть
конец если, конец пока, конец <имя>
модуль экспорт подключить как тип
Результат Успех Ошибка поднять
да нет пусто и или не нацело
```

Типы и знаки:

```text
Число Строка Логическое Пусто Список<...> Результат<..., ...> Ошибка
-> == != <= >= + - * % = : , . ? ( ) [ ] { } | // /* */
```

`модуль`, `экспорт`, `подключить`, `как`, `тип` — **зарезервированы** (см. §3), не входят в
v0.1-грамматику. `.`, `?`, `|`, `{`, `}` — пунктуация/резерв; `{}` **не** литерал `Ошибка` и не
struct literal в v0.1; `.` в AST 2.0 не используется.

`и`/`или`/`не` — ключевые. Текущий v3-парсер их знает: `src/compiler-v3/parser.ts#или`,
`src/compiler-v3/parser.ts#и`, `src/compiler-v3/parser.ts#не`; A3-verify 8/8 на живой E8C2 это
подтвердил. Отдельной правки A4a для них нет.

## 2. Убрано из актуальной лексики — навсегда

| Убрано | Почему | Где осталось |
|---|---|---|
| `защита`, `при ошибке` | скрытый переход = D4; `OSN-PAR-021` — финальный отказ | v2-оракул, A1.5-история |
| `Неудача` | синоним; одна форма на понятие | A1 (названное расхождение, A4a после L2) |
| `Может` | нет в AST/коде; Maybe — после v0.1 | v2-оракул |
| `типа` | ключ без грамматики | v2-оракул |
| `Словарь` (v0.1) | парсер не использует; библиотеки после | v2-оракул |
| `→` | только ASCII `->`; `OSN-PAR-026` | v2-оракул (81), черновик (1) |
| `число`/`строка` как литералы | это не литералы, а имена | внутренние token-kind v2-оракула |
| `попробовать`/`поймать`/`выбросить` | второй механизм ошибок | shared v2-путь (не трогается) |

`защита` — **не** «отложена до v0.2». Её нет ни в v0.1, ни в v0.2. A2/A2-block **не делать**.

## 3. Зарезервировано

| Форма | Когда | Что значит |
|---|---|---|
| `разбор`/`есть` | после v0.1 (D54) | разбор перечня `Тип.Вариант`, не общий pattern matching |
| `модуль`, `экспорт`, `подключить`, `как` | v0.2 (L3) | модули |
| `тип`, struct/record-синтаксис | v0.2 (L3) | структуры/перечисления |
| контракты D42 | AST 2.0 | `требует`/`обеспечивает`/`эффекты` — резерв, не v0.1 |
| `прервать`/`продолжить` | после v0.1 | управление циклом |
| `/` (точное деление) | после P3c | в v0.1 только `нацело` (целочисленное); `/` — названный отказ `OSN-LOW-001`, см. `docs/parser-protocol.md` §12 |

## 4. Модель ошибок — один путь

**`Результат<T, E>` — единственный механизм ошибок на границах.** Внутри процедуры допустимо
голое значение; ошибка, пересекающая границу, — только пара. Исключений в рантайме нет.

- **`Успех(значение)`** — конструктор успеха, ровно один payload.
- **`Ошибка(код, сообщение)`** — конструктор неудачи для `E = Ошибка`; ровно два аргумента:
  `код: Число`, `сообщение: Строка`. `Ошибка` — **встроенный тип**, не struct.
- **`Ошибка{...}`** — **нет**: это не struct literal. `Ошибка(1, "беда")` — вызов конструктора.
- **`поднять <выражение>`** — инструкция (не выражение): разворачивается в ветвь неудачи
  `Результат<T, E>` с payload `<выражение>`. В записи `поднять(значение)` скобки означают
  нагрузку, а не вызов функции; `х = поднять(ф()) + 1` — отказ разбора.
- **`пусть тег, нагрузка = вызов()`** — явный разбор пары; ничего скрытого.
- `Успех`/`Ошибка` допустимы только в процедуре, объявленной `-> Результат<T, E>`; вне —
  `OSN-PAR-022`. Неверная арность — `OSN-PAR-023`. `Ошибка{...}` — `OSN-PAR-024`.
- `Неудача` — **нет**. `защита` — **нет**. Второго пути нет.

## 5. `конец` — explicit

- `конец если`, `конец пока`.
- `конец <имя>` — имя процедуры/действия; обязано совпадать.
- Bare `конец` — **ошибка** `OSN-PAR-025`.
- `иначе если` — цепочка; **один** `конец если` на всю цепочку.

## 6. `->` — только ASCII

`->` — объявление возврата. `→` — **ошибка** `OSN-PAR-026`. Это breaking change для v2-текстов;
v2-оракул не переписывается.

## 7. Типы

- **`Число`** — int32, D52 (решение владельца 2026-11-09: int32, не int64; отказ на переполнение — контракт, кодоген — активный D4, случай 95).
- **`Строка`** — последовательность кодпоинтов, D1.
- **`Логическое`**, **`Пусто`**.
- **`Список<T>`** — список.
- **`Результат<T, E>`** — пара; ABI — два регистра (D2/§10.2).
- **`Ошибка`** — встроенный payload-тип: `код: Число`, `сообщение: Строка`.

### 7.1. `Списки` — D43a/D43b (минимальный API, 2026-11-09)

`Списки` — библиотека D43, а не языковая инструкция: вызовы квалифицированные, `Списки.X(...)`.
Проверка/разбор — `src/compiler-v3/parserV01.ts` (AST 2.1, событие `квалифицированный_вызов` 42/43);
понижение — таблица `src/e2k/arrayRuntime.ts` (D33-style: запись таблицы, не алгоритм VLIW).

| Вызов | Тип | Эффект | D43 |
|---|---|---|---|
| `Списки.пустой(ар)` | `Список<T>` | создаёт пустой список | аллокация через `ар` |
| `Списки.добавить(л, э, ар)` | `Список<T>` | **мутирует** `л`, возвращает тот же список | аллокация через `ар` |
| `Списки.длина(л)` | `Число` | читает длину | без аллокации |
| `Списки.взять(л, и)` | `Результат<T, Ошибка>` | читает элемент; выход за границу — `Ошибка` | без аллокации |
| `Списки.установить(л, и, з)` | `Список<T>` | **мутирует** `л`; требует `0 <= и < Списки.длина(л)`; выход за границу — ловушка `OSN-RT-010` | без аллокации, без арены, без `Результат` |

Все вызовы — ≤ 3 аргументов (D2). Арена явная (D43 §1); скрытой аллокации нет.
`Списки.добавить` без третьего аргумента — `OSN-PAR-032` (parserV01).

**Что реализовано в D43a.** `пустой` → `система.массив.создать` (арена отбрасывается),
`добавить` → `система.массив.добавить` + копия указателя в приёмник (возврат списка),
`длина` → `система.массив.длина`. Арена принимается и проверяется по арности, но **значение
арены пока не используется**: куча массивов на e2k — одна на точку входа (D12-2). Это названное
расхождение D43a, а не «арена уже работает»; арена-зависимая куча — следующий атом.

**Что реализовано в D43b.** `установить` → `система.массив.установить` + копия указателя в приёмник
(возврат списка для цепочки). Три аргумента (D2), арены нет, `Результат` нет. Границы проверяются
**отдельным проходом до раскладки** (`src/e2k/arrayBounds.ts`): сайт из 10 носителей —
`длина(л)`, `0 <= и`, `и < длина`, два условных перехода, `IR.array_bounds_trap` и сам вызов.
Ловушка — `sdivs 0/0` (архитектурное исключение `exc_div`), а не системный вызов: вызов из
вызываемой в модели не завершается, а D43b обязан работать на глубине 1. Нарушение любого края
уводит в ловушку `OSN-RT-010`, а не в запись по чужому адресу (D4).

**Замер D43b (модель).** Три пробы N=3: глубина 0 → **42**, глубина 1 (вызываемая пишет в список
вызывающего) → **42**, выход за границу (длина 2, индекс 5) → **исключение модели, код 9**, не
запись и не молчание. Само-красный контроль: без ключа `'Списки.установить'` краснеют 3/3.
Железо E8C2 в этом прогоне **не измерено** (SSH-доступ отклонён), поэтому равенство «модель =
железо» для D43b **не заявлено**; это названный долг, а не «совпало».

**Что НЕ реализовано в D43a/D43b.** `Списки.взять` разбирается и имеет тип `Результат<T, Ошибка>`,
но понижение отказывает **по имени**: пара `Результат` в горячем пути точки входа не влезает
(D49), а подменять её «голым» `система.массив.получить` значило бы вернуть тихую ложь (D4).
Это следующий атом, не «забыли».

- `пусть имя = выражение`

Затенение — **запрещено** (`OSN-PAR-027`). Канон v2 §13.10 — названный долг; проверка — A4a/после.

## 9. AST 2.0 — критический путь

Черновик `.tmp/parser-target.osnova` (764 строки) использует: `[` — 179, `+` — 254, `==` — 64,
`!=` — 1, `иначе если` — 3, `нацело` — 4, `пока` — 28, `если` — 123, `пусть` — 18, `вернуть` — 1,
`действие`/`процедура` — по 1, bare `конец` — 2, `→` — 1.

**Не использует:** struct literal (`{`/`}` — 0), `.` — 0, `защита` — 0, `Может` — 0, `типа` — 0,
`Словарь` — 0, `Неудача` — 0, `Успех` — 0.

Поэтому AST 2.0 = **операторы, списки, индексация, `иначе если`, `нацело`**; **без** struct
literal и `.`. Метка `2.0` — внутренняя (версия формата); в продакшене — `docs/ast-format.md` без
«2.0 vs 1.1».

## 10.1. Границы ФОРМЫ целевого понижения (замер 2026-11-10)

Три числа ниже — не долги и не дефекты, а **границы формы**: они следуют из устройства носителя,
проверены замером и обязаны учитываться при написании целевых программ (в том числе парсера P4).

| граница | число | чем измерена |
|---|---|---|
| **аргументов у вызова** | **≤ 3** | проба `.tmp/p4-split-feasibility.ts`: ветвь с 7 аргументами не отказывает, а **бросает** `EmitterRefusalError: call: аргументов 7, носитель несёт не больше 3` (`src/e2k/emitterShell.ts#EmitterRefusalError`, `MAX_CALL_ARGS`) |
| **элементов в литерале списка в точке входа** | **≤ 8** | `.tmp/p4-lists-sweep.ts`: 1×8 — ОК, 1×**16** — отказ раскладки (живы 18 при 10 свободных); 3×8 — ОК, 3×16 — отказ. Литерал — это `создать` + `добавить`, и каждый элемент занимает живую клетку |
| **свободных клеток точки входа при `%` в образе** | **9**, а не 10 | `%` — это `IR.rem`, он УСЛОВНО держит `%b[9]` (`REMAINDER_SCRATCH_REGISTER = 9`, `src/e2k/remainderRuntime.ts#REMAINDER_SCRATCH_REGISTER`); убрать `%`/`нацело` из точки входа — вернуть клетку |

**Следствия для P4.** (1) Состояние автомата (у черновика `поз, посл, режим, ошибка, н, тсост, кадры,
эсост`) **нельзя** передать параметрами — его место **список** (`состояние[0..7]`), и тогда вызов
укладывается в три аргумента. (2) Растущую ленту нельзя записать литералом длиннее 8 — только
операторами (`добавить` в точке входа, `установить` в вызываемой: `добавить` в вызываемой — названный
размерный отказ, см. `parser-protocol.md` §20). (3) `%`/`нацело` в точке входа стоит клетки бюджета:
в горячем пути их место — вызываемая.
