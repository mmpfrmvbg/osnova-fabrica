# QEMU-System-e2k: линия ЗАКРЫТА — стена внешняя (прошивка `e2k.bin`, долг перед МЦСТ)

**Дата:** 2026-10-03. **Статус: ЛИНИЯ ЗАКРЫТА** — системная модель собрана, замерена и доведена до
**входа в системный вызов**; дальше без МЦСТ пройти нечем (§6). Правок в исходники ветки — **одна**
(окно, §4.1), она лежит файлом рядом. Прошивка **не изобретается**, bootblock **не подделывается** —
решение владельца 2026-10-03, исполнено.

**Что закрыто и чем.** Путь «наш ELF → машина → наш код → `exit(2)` → вход в системный вызов» пройден
целиком и измерен на бинаре корпуса (§4). Стена — вход в syscall: в системном режиме это вход в
**ядро**, а `sdisp`, который его и делает, в ветке существует только под `CONFIG_USER_ONLY` (§5.2).

**Что просили.** «QEMU-System-EK2» — это `qemu-system-e2k`, **полносистемная** эмуляция
Эльбруса (машина + ядро), в отличие от **user-mode** `qemu-e2k`, которой измерены закреплённые
числа `src/e2k/**` и `src/vliw/**` (паспорт — `src/e2k/qemuModelPassport.ts`). Это два разных
эмулятора, и путать их нельзя: паспорт описывает только второй.

**Когда линия откроется снова (критерий, а не надежда):** появится публичная прошивка `e2k.bin`
или системные патчи ALT (QEMU 7.2), либо откроется доступ к живой машине/МЦСТ. Тогда — перемерить
числа §2/§4 и начинать с §6.

## 3. Машина: что в ней есть, а чего нет

| Что | Значение | Где |
|---|---|---|
| имя машины | `e2k` — `Generic E2K Machine (default)`; `-M help` показывает ровно её и `none` | `include/hw/e2k/e2k.h:223` |
| CPU по умолчанию | `e8c`, до 8 CPU (`-smp`) | `hw/e2k/e2k.c:297-308` |
| RAM | MLO `0x0`…2 ГиБ; вторая банка с `0x400000000` | `include/hw/e2k/memmap.h:23-46` |
| BIOS-область | `0x100000000`, 16 МиБ (сюда грузится `e2k.bin`) | там же |
| SIC, IO, PCICFG | `0x110000000`, `0x101000000`, `0x200000000` | там же, `hw/e2k/sic.c` |
| устройства | PCI (iohub → `iohub-pcibridge`), `escc-pci` (serial A/B) | `hw/e2k/e2k.c:224-250` |
| загрузка кода | `-kernel <ELF>` с `e_machine = EM_MCST_ELBRUS`: сегменты грузятся, PC = `e_entry` | `hw/e2k/e2k.c:147-179` |
| без `-kernel` | `qemu-system-e2k: no firmware provided` — нужна прошивка `e2k.bin` | замер 2026-10-03 |

Чего нет — и это не «мелочи», а прямые преграды (§5):

- **`initrd` не поддержан вовсе** — `/* TODO: load initrd */` (`hw/e2k/e2k.c:170`); устройств
  хранения (virtio-blk и любых дисков) у машины нет. Грузить rootfs нечем.
- **bootblock формируется, но гостю не отдаётся.** `generate_bootblock` (`e2k.c:104-145`) считает
  карту памяти и cmdline, но результат только присваивается полю состояния (`e2k.c:168`) и в
  память гостя не кладётся: ядро о RAM и cmdline не узнает.
- **консоль — не та, что ищет ядро Эльбруса.** Драйвер консоли МЦСТ `lmscon` в дереве есть
  (`hw/char/lmscon.c`), но его инициализация закомментирована (`hw/e2k/e2k.c:88-102`), а машина
  отдаёт `escc` (консоль машин Apple). Ядро Эльбруса ищет `lmscon`.
- прошивка `e2k.bin` публично не выложена ни МЦСТ, ни ALT.

## 4. Замер: что модель делает с НАШИМИ байтами

Взяты не «сферические» пробы, а бинари корпуса из `tools/e2k-hardware/bin` — те же ELF, что
идут на живую машину. Запись — `11-минимум-массива.elf` (ELF64, `EM_MCST_ELBRUS`, entry
`0x100000`, один `PT_LOAD`, эталон возврата **2**).

| Замер | Сборка без правок | Сборка с правкой окна (§4.1) |
|---|---|---|
| первая команда | наш `setbn rbs = 0x0, rsz = 0x7, rcur = 0x0` | то же |
| окно вызывающего (`wsz` из `-d cpu`) | **16** (это `size_q = 8`) | **24** (= `size_q = 12`) |
| окно вызываемой на входе в вызов | **8** | **16** (= `24 − 8`, ровно наша геометрия) |
| где встала | `0x100338` — до вызова | `0x100358` — **бандл `sdisp`/`ipd 3`/`call`, то есть вход в системный вызов** |
| исключение | **9** = `EXCP_WINDOW_BOUNDS` | **0** = `EXCP_ILLEGAL_OPCODE` |
| исход | `exit(1)` заглушкой обработчика | то же |

**Про `0` в строке исключения — это не «исключения не было».** Ноль здесь первый элемент
перечисления: `target/e2k/cpu.h:294-303` — `EXCP_ILLEGAL_OPCODE = 0`, `EXCP_PRIV_ACTION = 1`, …,
`EXCP_WINDOW_BOUNDS = 9`. Заглушка обработчика печатает именно `cs->exception_index`, поэтому
`not implemented 0` = «незаконный код операции». Различает не догадка, а **пара сборок на одном
ELF**: без правки тот же путь печатает **9**, с правкой — **0**; значит номер приходит от того,
ЧТО возбуждено, а не от отсутствия события.

**Что видно в регистрах на момент останова** (сборка с правкой, дамп `-d cpu` для окна вызываемой):

```
  r0 <00>0000000000000001   r1 <00>0000000000000002   r2 <00>0000000000111028   r3 <00>0000000000111028
  r4 <00>0000000000000000   r5 <00>0000000000000001   r6 <00>0000000000000008   r7 <00>0000000000111030
```

Это **наши значения и наш ABI**: номер вызова `exit` = **1** кладётся в оконный `r0`, код
возврата — в оконный `r1` (`src/e2k/syscallRuntime.ts#SYS_EXIT`, `SYS_EXIT = 1`), и в `r1` стоит
**2** — эталон записи `11`. То есть программа **досчитала** и выставила `exit(2)`; осталось
войти в системный вызов. Это второй независимый свидетель кодировщика: не user-mode модель
проверяет саму себя, а **настоящая машина** исполняет наши байты.

### 4.1. Правка окна (заход 1) — одна строка

`target/e2k/cpu.c#e2k_cpu_reset` задавал `env->wd.size = 16` (`size_q = 8`) — это геометрия
**до** нашей правки окна в user-mode. Образы корпуса объявлены под `size_q = 12` → `24`
(`src/e2k/qemuModelPassport.ts`, поле `window`; `src/e2k/windowGeometry.ts`). Правка приводит
системный сброс к той же геометрии:

```c
-    env->wd.size = 16;
+    env->wd.size = 24;
```

Файлом: `tools/qemu-e2k/system/osnova-local-system-window.patch`. Единицы — **регистры**
(`target/e2k/helper-tcg.h:56-57`: `env->wd.size = extract64(raw, WD_SIZE_OFF, …) / 8`), поэтому
`wd.size = 24`, а не 12. Правка **одна** — чтобы замер был чистым: «одна правка — одно число».

## 5. Преграды по слоям

1. **Окно процедур — ЗАКРЫТО нашей правкой (§4.1).** Было: в системном режиме геометрию окна не
   ставил никто (в user-mode её ставит порт), первый же `call` давал `EXCP_WINDOW_BOUNDS` (9).
   Стало: `wsz = 24`, вызываемая получает 16 — это исключение ушло.
2. **Вход в системный вызов — ЭТО И ЕСТЬ СТЕНА.** `sdisp` (то, что ставит тег `CTPSL` и делает
   `call` системным вызовом) реализован в ветке **только под `CONFIG_USER_ONLY`**
   (`translate.c:7560-7570`: `#else e2k_todo(ctx, "sdisp"); #endif`), причём и там он
   **подделывает** цель: `E2K_FAKE_KERN_START` + смещение, с пометкой «TODO: real sdisp target
   address». В системном режиме тег не выставляется, передача управления уходит в
   `do_branch`-заглушку (`// TODO: ldisp or sdisp; gen_excp_illopc();`) — отсюда
   `EXCP_ILLEGAL_OPCODE`. **В системном режиме вход в syscall = вход в ядро**, а ядра (и прошивки,
   которая его грузит) у нас нет и публично взять негде.
3. **Доставки исключений нет.** `e2k_cpu_do_interrupt` — заглушка с `exit(1)`; `raise_exception_ra`
   «глотает» только `EXCP_PROC_STACK_BOUNDS`/`EXCP_CHAIN_STACK_BOUNDS` и (под `CONFIG_USER_ONLY`)
   `EXCP_SYSCALL` (`target/e2k/helper.c:296-310`).
4. **rootfs грузить нечем:** `initrd` — `TODO`, дисковых устройств нет (§3).
5. **Прошивки нет, bootblock не передаётся, консоль не та** (§3).

## 6. Долги — по адресатам (линия закрыта, не провалена)

| долг | перед кем | что именно | чем снимется |
|---|---|---|---|
| **прошивка `e2k.bin`** | **МЦСТ** | публично не выложена ни МЦСТ, ни ALT; без неё машина умеет только `-kernel <ELF>`, а bootblock до гостя не доходит | публикацией прошивки **или** доступом к живой машине/МЦСТ |
| **системные патчи ALT (QEMU 7.2)** | **МЦСТ/ALT** | рабочий `qemu-system-e2k` (грузит ALT-образы) существует **только бинарём под e2k**; SRPMS не выложены, в public-гите ALT слова `e2k` в спеке нет | публикацией исходников или MR/issue через `git.openelbrus.ru` |
| **`sdisp` в системном режиме** | **системная модель** (не наш код) | под `CONFIG_USER_ONLY` он подделывает цель (`E2K_FAKE_KERN_START`); в системном режиме тег не ставится → `EXCP_ILLEGAL_OPCODE` | реализацией в порте **вместе с ядром**, иначе нечем: доставлять нечего |
| **паспорт-модуль и сторож** | **наша проверка** | числа этого дока (версия, `sha256` двух сборок, `sha256` патча, окно, исключения, адреса) держит **скрипт**, а не тест: ни одна проверка `src/e2k/**` живую системную сборку не спрашивает | паспортом-модулем + оракулом в шлюзе — заведено случаем **38** (`docs/verification-debt.md`, класс «дрейф артефактов») |

**Чего НЕ делать (решение владельца 2026-10-03, исполнено):** не изобретать свою прошивку, не
подделывать bootblock, не «дорисовывать» вход в ядро. Это стена внешняя, и обход её означал бы
измерение собственной выдумки вместо поведения платформы.

## 7. Как повторить (две команды)

```bash
# в WSL-дистрибутиве e2k, от root
bash tools/qemu-e2k/system/build-system.sh            # клон → chroot Alpine 3.14 → configure → ninja → сверка sha256
bash tools/qemu-e2k/system/build-system.sh --window   # то же + наша правка окна (патч из репозитория)
bash tools/qemu-e2k/system/probe-system.sh            # машины, прошивка, прогон корпусного ELF на ДВУХ сборках
```

Проба отдельно проверяет **инвариант «паспорт не тронут»**: `sha256`
`/root/qemu-build/qemu-e2k` = `4e37a37243189dec…` (значение читается из
`src/e2k/qemuModelPassport.ts`, а не держится руками). Замер 2026-10-03: совпал — сборка
системной модели user-mode модель не задела.
