# QEMU-прогон пяти DSP-ядер: не состоялся

**Дата:** 2026-09-15
**Статус: ПРОГОН НЕ СОСТОЯЛСЯ.** Причин две, и обе названы: **нечем запускать** (§1) и
**нечего запускать** (§2). Ни одна из них не «мы не успели»: обе — свойства окружения и
конвейера проекта, и обе проверяемы.

---

## 1. Нечем запускать: QEMU не собран

`qemu-e2k` не собран: в окружении нет POSIX-оболочки и C-инструментов (`sh`, `gcc`, `make`,
`meson`, `ninja`, `pkg-config`), а `configure` — shell-скрипт. Точная команда и точный ответ —
`docs/e2k-qemu-build.md` §2. Там же: шаг, на котором остановилось (запуск `configure`), и
перечень отсутствующих инструментов.

**Запасного пути нет:** в архиве МЦСТ собранного `qemu-e2k` тоже нет — среди `*.exe`/`*.so`
в дереве только `linux-user/*/vdso*.so` чужих архитектур (`docs/e2k-qemu-build.md` §1).

---

## 2. Нечего запускать: у проекта нет e2k-бинарника

Даже если бы QEMU был собран, `qemu-e2k <binary>` запускать нечего: конвейер проекта выдаёт
**поток команд**, а не исполняемый файл.

| чего не хватает | подтверждение |
|---|---|
| **ELF-обёртки** | артефакт конвейера — `format: "osnova-shell-image"` (`src/e2k/emitterOracle.ts:49`), это не ELF: ни `e_ident`, ни таблицы сегментов, ни точки входа |
| **машины ELF для e2k** | нужна `e_machine = 175`: `EM_E2K` (`qemu/include/elf.h:195`) = `EM_MCST_ELBRUS` (`binutils-gdb/include/elf/common.h:295`) — два источника дают одно число |
| **класса ELF** | загрузчик e2k ждёт `ELFCLASS64` и `EM_E2K` (`qemu/linux-user/e2k/target_elf.h:10-11`) |
| **компоновщика e2k** | кросс-binutils с `bfd/elf64-e2k.c`; не собран — C-компилятора в окружении нет |
| **стартового кода и libc** | нужен `_start`, вызов `exit` и хотя бы статическая libc под e2k; в архиве QEMU её нет |
| **ABI системных вызовов** | в e2k номер вызова и аргументы идут через **системные регистры**: `sys_num`, `arg1…arg6`, `sys_rval` в `target_elf_gregset_t` (`qemu/linux-user/e2k/target_elf.h`) — конвейер проекта такой последовательности не порождает |
| **таблицы системных вызовов** | 446 определений `TARGET_NR_` (`qemu/linux-user/e2k/syscall_nr.h`, «written manually based on arch/e2k/include/uapi/asm/unistd.h of linux src») |

**Что у проекта есть на самом деле:** 2 184 байта кодированного потока команд
(`docs/e2k-real-run.md` §2) — это **тело** программы без заголовков, без адресов загрузки и без
обращений к системе. Загрузчик `linux-user` такой поток не примет: он читает ELF-заголовок.

## 3. Что измерено вместо прогона (и что это доказывает)

| измерение | результат | где |
|---|---|---|
| инструкций пяти ядер понижено в операции e2k | 268 из 517 | `docs/e2k-real-run.md` §2 |
| round-trip понижённых инструкций через реальную кодировку | 268 сверено, расхождений 0 | там же |
| числа ядер при прогоне регистровой VM с семантикой e2k | **181 / 119 / 4 / 90 / 32** — совпали с независимым эталоном | `docs/e2k-real-run.md` §3 |
| предпосылки понижения на данных | нецелых операндов 0, усечений 32 бит 0 | там же |

**Чего это не доказывает:** что код работает на e2k. Проверены кодирование и согласованность
понижения; исполнение на эмуляторе не выполнено, на железе — тем более.

---

## 4. Что нужно сделать, чтобы прогон состоялся

| шаг | что даёт |
|---|---|
| 1. Собрать QEMU-e2k на Linux-хосте | появляется `qemu-e2k` (`docs/e2k-qemu-build.md` §4) |
| 2. Собрать кросс-binutils с e2k | появляется компоновщик, понимающий `e_machine = 175` |
| 3. Написать ELF-обёртку для потока команд | заголовок `ELFCLASS64` + `EM_E2K`, сегмент `PT_LOAD`, точка входа |
| 4. Написать стартовый код и `exit` | минимальный `_start` через системные регистры (`sys_num`), без libc |
| 5. Прогнать `qemu-e2k <binary>` | сравнить вывод с эталоном |

Только шаг 5 даёт ответ на вопрос «совпал ли вывод». Шаги 1–2 невозможны в этом окружении:
компилятора C нет. Шаги 3–4 — работа, которую **сейчас делать нельзя**: без шага 5 её нечем
проверить, а непроверенный ELF-писатель стал бы новой непроверенной опорой.

**Это и есть честная граница:** «QEMU-прогон не состоялся» — не отговорка, а следствие того,
что в окружении нет ни эмулятора, ни средств сборки бинарника.
