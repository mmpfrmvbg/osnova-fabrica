# QEMU-прогон: пяти DSP-ядер — не состоялся, минимального ELF — состоялся

**Дата:** 2026-09-15 (обновлено 2026-09-18).
**Статус.** Для **пяти DSP-ядер**: **ПРОГОН НЕ СОСТОЯЛСЯ** — «Нечего запускать» (§3): у конвейера
нет e2k-бинарника. Для **минимального ELF**: прогон состоялся, программа из пяти инструкций даёт
**код возврата 42** (§2.9, `docs/e2k-minimal-elf.md` §7) — при двух послаблениях со стороны хоста:
шим для `mmap` (WSL1 не знает `MAP_FIXED_NOREPLACE`) и правка полей `WD._d` в порте QEMU (§2.9).
**Без шима ПРОГОН НЕ СОСТОЯЛСЯ** и для минимального ELF: `guest_base` (§2.1, §2.5) — именно так его
видит живой зонд оракула.

---

## 1. Чем запускать: QEMU-e2k СОБРАН

`qemu-e2k version 11.0.1`, `/root/qemu-build/qemu-e2k`, дистрибутив `e2k` (WSL1, Alpine 3.24.1).
Как собрано и что этому мешало на Windows — `docs/e2k-qemu-build.md` §2.5.

**Запасного пути нет** (и он не понадобился): в архиве МЦСТ собранного `qemu-e2k` действительно
нет — среди `*.exe`/`*.so` в дереве только `linux-user/*/vdso*.so` чужих архитектур.

## 2. Что произошло при запуске: `guest_base` не размещается

### 2.1. Точный ответ

```
$ qemu-e2k .tmp/e2k-samples.elf
qemu-e2k: .tmp/e2k-samples.elf: Unable to find a guest_base to satisfy all guest address
mapping requirements
  0000000000000000-000000003fffffff
```

Ошибка выдаётся на **этапе загрузки образа**, до исполнения первой инструкции. Источник:
`linux-user/elfload.c:1095` (`probe_guest_base`), диапазон в сообщении — требуемый гостевой
резерв.

### 2.2. Перебор `-R` (резерв адресного пространства гостя)

| `-R` | требуемый диапазон | исход |
|---|---|---|
| по умолчанию | `0`…`0x3fffffff` | ошибка `guest_base` |
| `512M` | `0`…`0x1fffffff` | ошибка `guest_base` |
| `1G` | `0`…`0x3fffffff` | ошибка `guest_base` |
| `2G` | `0`…`0x7fffffff` | ошибка `guest_base` |
| `4G` | `0`…`0xffffffff` | ошибка `guest_base` |
| `8G`, `16G` | `0`…`0x1ffffffff`, `0`…`0x3ffffffff` | ошибка `guest_base` |

Размер резерва ни на что не влияет: разместить его в этом хосте не удаётся **ни при каком**
значении.

### 2.3. Контрольный эксперимент: дело не в QEMU и не в нашем ELF

| проверка | результат |
|---|---|
| тем же `configure`/`make` собран `qemu-x86_64` той же версии 11.0.1 | собран |
| статический бинарник x86-64 (`gcc -static`, `int main(void){return 0;}`) | запущен **напрямую**: код возврата 0 |
| он же под `qemu-x86_64` | код возврата **0** — user-mode QEMU в этом окружении **работает** |
| `qemu-e2k` на нашем ELF | ошибка `guest_base` (устойчиво) |

**Вывод:** препятствие не в QEMU (x86-64 цель работает) и не в нашем ELF (ошибка возникает
**до** чтения инструкций). Препятствие — **хост**: поиск гостевого резерва в linux-user стоит на
`MAP_FIXED_NOREPLACE` (`linux-user/elfload.c:792`), а этого флага в WSL1 нет (§2.5 — измерено,
`errno=95`). Требование e2k к адресному пространству (`TARGET_VIRT_ADDR_SPACE_BITS = 48`,
`target/e2k/cpu-param.h:12`) задаёт **размер** резерва, но непреодолимым его делает именно
отсутствующий флаг.

### 2.4. Прогон минимального ELF: та же причина, с контрольными опытами

Второй довод «не наш образ виноват» проверен **на образе, который мы контролируем целиком**:
собран минимальный ELF64 (`src/e2k/elfMinimal.ts`, `docs/e2k-minimal-elf.md` — заголовок,
один `PT_LOAD`, `.text` из трёх инструкций, `_start`).

```
$ qemu-e2k .tmp/e2k-minimal.elf
qemu-e2k: .tmp/e2k-minimal.elf: Unable to find a guest_base to satisfy all guest address
mapping requirements
  0000000000000000-000000003fffffff
(код возврата 0)
```

| контроль | результат | что доказывает |
|---|---|---|
| `qemu-e2k` на файле, который не ELF | `Error while loading …: Exec format error` | файл **читается и проверяется** — сообщение `guest_base` не «заглушка на всё» |
| `qemu-e2k` на `.tmp/e2k-minimal.elf` (наш минимальный ELF) | ошибка `guest_base` | причина не в конкретных заголовках нашего образа |
| `qemu-e2k` на `.tmp/e2k-samples.elf` (собран другой дорогой, до этого) | **та же** ошибка `guest_base` | причина не в дороге сборки образа |
| `qemu-x86_64` на своём бинарнике | код возврата 0 | user-mode QEMU в окружении работоспособен |

**Отдельно измерено:** при отказе загрузки `qemu-e2k` завершается **кодом 0**, а причину пишет в
stderr. Практическое следствие: судить о прогоне по коду возврата нельзя — отказ загрузки
выглядел бы как успех. Оракул (`src/e2k/elfMinimal.test.ts`) поэтому читает **и** stdout, **и**
stderr.

### 2.5. Точная причина уровня syscall: WSL1 не поддерживает `MAP_FIXED_NOREPLACE`

До этой проверки причина записывалась как «требования e2k к адресному пространству»
(`TARGET_VIRT_ADDR_SPACE_BITS = 48`). Это **не вся причина**: сам флаг, на котором стоит поиск,
в WSL1 не поддерживается, и тогда поиск не может удаться **ни при каком** хосте-адресе.

`probe_guest_base` (`linux-user/elfload.c:786-850`) проверяет свободен ли диапазон ровно так:

```c
/* linux-user/elfload.c:790-796 */
void *p = mmap((void *)addr, size, prot_none,
               MAP_ANONYMOUS | MAP_PRIVATE | MAP_NORESERVE | MAP_FIXED_NOREPLACE, -1, 0);
if (p == MAP_FAILED) {
    return errno == EEXIST ? 0 : -1;   /* 0 — «занято», -1 — «mmap не сработал» */
}
```

Оба пути (`pgb_dynamic` — перебор дыр, `pgb_fixed` — заданный `-B`) кончаются этой функцией.
Зонд на C (собран в том же WSL1) даёт:

| проверка | результат в WSL1 |
|---|---|
| `mmap(… MAP_FIXED_NOREPLACE)` 1 МиБ @ 1 ГиБ | **отказ `errno=95` (`ENOTSUP`, «Not supported»)** |
| `mmap(… MAP_FIXED_NOREPLACE)` 1 ГиБ @ 16 ГиБ | **отказ `errno=95`** |
| `mmap(… MAP_FIXED)` 1 ГиБ @ 16 ГиБ | запрошенный адрес получен (код возврата `0x400000000`) |
| `mmap` 1 ГиБ без адреса | адрес выдан (обычный `mmap` доступен) |
| `/proc/self/maps` | читается, 19 строк — то есть дело не в недоступности карты |

`MAP_FIXED_NOREPLACE` появился в Linux 4.17; WSL1 — **не ядро**, а слой трансляции системных
вызовов, и этого флага не знает. Первый же `mmap` возвращает `ENOTSUP`, `pgb_try_mmap` считает
кандидат непригодным, все кандидаты перебираются — и печатается §2.1.

**Отсюда два следствия, которые важнее самого прогона:**

1. **Дело не в e2k и не в нашем ELF.** Настоящее ядро Linux (≥ 4.17) даёт этот флаг, поэтому
   там тот же `qemu-e2k` и тот же ELF пройдут этап размещения. Это **не проверено здесь**
   (другого окружения нет), но причина отказа — отсутствующий флаг, а не разметка образа.
2. **Перебор `-B`/`-R` бессилен по построению.** `-B` уходит в `pgb_fixed` → тот же `mmap`
   с тем же флагом: `qemu-e2k -B 0x40000000` отвечает «requires virtual address space that is in
   use», и это то же самое `ENOTSUP`, только с другой формулировкой.

**Чего этот зонд НЕ доказывает:** что на ядре ≥ 4.17 прогон дойдёт до конца. Он доказывает
только, что этап `probe_guest_base` там перестаёт быть непреодолимым. Дальше начинается
исполнение e2k-кода, которого здесь никто не видел.

**Что из этого следует для выбора окружения:** WSL2 — это настоящий ядро Linux в лёгкой
виртуальной машине; в установленном на этой машине пакете ядро **6.6.87.2-1** (`wsl --version`,
измерено), то есть нужный флаг (Linux 4.17+) там есть. Отдельная установка Linux **не
обязательна**. Полноценный Linux-хост, виртуальная машина или чужая Linux-машина тоже подойдут —
требование одно: **ядро Linux ≥ 4.17**, а не «не-WSL».

### 2.7. Что это значит для постановки

Требование «прогнать на QEMU» упирается **не в сборку** (она сделана) и **не в кодировку**
(она подтверждена внешним дизассемблером), а в **хост**: в WSL1 нет системного вызова, на
котором стоит поиск гостевого резерва (§2.5, измерено). Годится **любое окружение с настоящим
ядром Linux ≥ 4.17** — WSL2, виртуальная машина или отдельная Linux-машина; проверка на таком
окружении здесь **не сделана**, потому что другого Linux-окружения нет, и так и записано.

Отдельная мелочь для переноса: собранный `qemu-e2k` — динамический ELF под **musl**
(`interpreter /lib/ld-musl-x86_64.so.1`, дистрибутив Alpine). В glibc-окружении его надо либо
пересобрать, либо тащить вместе с musl, либо переносить **весь rootfs** WSL1-дистрибутива в WSL2
(`wsl --export` → `wsl --import --version 2`) — тогда переносятся и binutils, и ассемблер, и QEMU.

### 2.8. Шим для `mmap`: преграда снята, и код **исполняется**

Преграда — в хосте, поэтому лечится на хосте. Небольшая библиотека подменяет `mmap` так, что
`MAP_FIXED_NOREPLACE` получает смысл, которого QEMU и ждёт: адрес запрашивается **подсказкой**
(без `MAP_FIXED`, ничего не затирается), затем сверяется с запрошенным; не совпал — страница
освобождается и возвращается `MAP_FAILED` с `errno = EEXIST` — ровно как поступило бы ядро.
Полный исходник — `src/scripts/e2kQemuExec.ts`; ключевая часть:

```c
    if ((flags & MAP_FIXED_NOREPLACE) == 0)
        return real_mmap(addr, length, prot, flags, fd, offset);

    void *p = real_mmap(addr, length, prot, flags & ~MAP_FIXED_NOREPLACE, fd, offset);
    if (p == MAP_FAILED) return p;
    if (p != addr) { munmap(p, length); errno = EEXIST; return MAP_FAILED; }
    return p;
```

Запуск: `LD_PRELOAD=<шим> qemu-e2k <elf>`. Результат на минимальном ELF:

```
qemu-e2k: qemu: exception at IP = 0x100020
qemu-e2k: qemu: exception handling is unimplemented - aborting
```

Эмулятор **исполнил** обе `movts` (адреса `0x100000` и `0x100010`) и остановился на `ct %ctpr1`
(`0x100020`). Запись «прогон не состоялся» остаётся верной для запуска **без** шима — именно его
проверяет живой зонд оракула (`src/scripts/e2kQemuRun.audit.test.ts`).

**Чем шим НЕ является:** он не меняет ни трансляцию e2k, ни семантику инструкций — только способ
узнать у хоста, свободен ли диапазон. Отличие от настоящего флага одно: проверка перестаёт быть
**атомарной**. На этапе загрузки linux-user однопоточный, а диапазон резерва остаётся замапленным,
поэтому окно мало — но это отличие, и оно записано.

**Что прогон с шимом уже дал** (подробности — `docs/e2k-minimal-elf.md` §4):

| измерение | результат |
|---|---|
| минимальный ELF: где остановка | `0x100020` — на `ct %ctpr1` |
| почему | `%ctpr` на входе нуль (`cpu-sregs.h:149`), ноль — тег `CTPEW`, `ct` по нему — исключение (`translate-ct.c:840-844`) |
| передача управления `disp` + `ct` | смещение 3 → остановка в ловушке на `0x100018`, смещение 2 → на `0x100010`: **адрес следует за смещением** |
| что это значит | наши байты CS0/SS **исполняются** по смыслу, а не только разбираются дизассемблером |
| `exit(42)` | **выполняется**: код возврата 42 (§2.9, `docs/e2k-minimal-elf.md` §7) |

Оракул исполнения — `src/e2k/e2kQemuExec.test.ts`: он сам собирает шим из исходника выше, гоняет
опыт с передачей управления (положительный и отрицательный контроль), проверяет, что **без** шима
прогон упирается в `guest_base`, и требует код возврата **42** от программы `exit(42)`
(`docs/e2k-minimal-elf.md` §7).

### 2.9. Правка порта: поля `WD._d` — и системный вызов доходит до `do_syscall`

После шима прогон **исполняется**, но системный вызов упирался в порт: `cpu_loop` читает номер
вызова из оконного `r0` (`cpu_loop.c:164-170`), а окно регистров оказывалось недоступным —
`qemu: syscall without proper WD configuration - aborting`.

Причина найдена в исходниках порта: геометрия окна задаётся полями `WD.size_q/psize_q/base_q`
(`linux-user/e2k/cpu_loop.c:301-303`), а оконные регистры читаются через `WD.size_d/base_d`
(`target/e2k/reg-index.h:64-79`). **Поля `_d` никто не пишет** — `e2k_cpu_exec_ct_return` строит
`WD` из `_q`-полей и на следующей строке читает `_d` (`translate-ct.c:71-73`), а
`e2k_cpu_exec_ct_CALL` строит `WD` с нуля (`:1076-1082`). Связь величин задана в порте:
`MAXNR_D = MAXNR_Q * 2` (`target/e2k/cpu.h:58`), то есть `_d` — та же геометрия в половинных
единицах.

Локальная правка (в самом порте, помечена `OSNOVA-LOCAL-PATCH`) — там, где пишутся `_q`-поля,
пишутся и `_d = 2 * _q`; в `init_main_thread` к `psize_q = 4`, `size_q = 8` добавляются
`psize_d = 8`, `size_d = 16`:

```c
    env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, size_q , 8);
    /* OSNOVA-LOCAL-PATCH: _d = 2 * _q (target/e2k/cpu.h:58) */
    env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, psize_d, 4 * 2);
    env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, size_d , 8 * 2);
```

Пересборка — инкрементальная (`ninja` в `/root/qemu-build`, 2 файла + линковка). **Семантика
инструкций не меняется**: восполняется начальное состояние окна, которое в реальной системе
задаёт ядро, а в linux-user — загрузчик.

Результат — программа `exit(42)` (пять инструкций, `docs/e2k-minimal-elf.md` §2) проходит целиком:

```
$ LD_PRELOAD=<шим> qemu-e2k .tmp/e2k-minimal.elf ; echo $?
42
```

Промежуточные измерения на этом пути (все — замеры, не догадки):

| шаг | что показал прогон | что из этого следовало |
|---|---|---|
| `call` с `wbs=0` | `exception at IP = 0x100028` | порт требует `psize_q ≤ wbs ≤ size_q`: `wbs=0` меньше `psize_q = 4` (`translate-ct.c:908-917`) |
| `call` с `wbs=4`, номер в `%b[0]` | `syscall without proper WD configuration` | ABI читает **оконный** `r0`, а `%b[0]` — это `rf.global[0]` (`reg-index.h:79` против `:117`) |
| номер в `%r0` (оконный) | `-strace`: `151 restart_syscall` | `call` сдвигает окно на `wbs`, поэтому писать надо в окно вызываемого: `%r8` при `wbs = 4` |
| `setbn rsz=4` + номер в `%r8`, довод в `%r9` | **код возврата 42** | окно вращаемых регистров при входе нулевое (`BR = 0`), его надо расширить `setbn` |

### 2.10. `write(1, "hello", 5)` + `exit(42)`: вывод, а не только код возврата

§2.9 довёл `exit(42)`, но не проверил то, ради чего syscall и нужен: **запись в stdout**. Собран
второй образ — `_start` без libc, который пишет строку через `write` и завершается
(`src/e2k/syscallRuntime.ts`); оракул — `src/e2k/e2kSyscallRuntime.test.ts` в шлюзе
`npm run gate:qemu` (на внешний ресурс, поэтому не в полном прогоне).

| звено | что измерено |
|---|---|
| адрес строки | литерал формы **0xdc** (16 байт), значение `0x100098` — дизассемблер МЦСТ печатает `movtd,0 _f64 0x100098, %dr10`, и значение сверяется с измеренной константой |
| вызов | `write = 4` в оконном `r0` (это `%r8` при `wbs = 4`), `fd = 1` в `%r9`, адрес в `%r10`, длина 5 в `%r11`, затем `sdisp %ctpr1, 0` и `call %ctpr1, wbs = 4` |
| окно | `setbn rbs = 0x0, rsz = 0x5, rcur = 0x0` — 12 регистровых единиц, нужно для `%r8`…`%r11` |
| **вывод** | **`QEMU stdout: "hello"`** — ровно те пять байт, что лежат в образе сразу за кодом |
| завершение | тот же образ с `exit(42)` возвращает **42**: окно восстановилось после `write` (код возврата `0` этого не различал бы) |

Требования окружения — те же, что в §2.5 и §2.8: WSL1, шим для `mmap`, правка полей `WD._d` в
порте. **Чего это не доказывает:** что так поведёт себя железо (QEMU — модель), что `rsz = 5`
обязателен (опыт с `rsz = 4` не ставился) и что иммедиат `sdisp` должен быть именно `0`
(ноль — измеренное значение, в постановке называлось `3`). Разбор по звеньям и негативный контроль —
`docs/e2k-syscall-abi.md` §5, `docs/e2k-real-run.md` §2.4.2.

| чего не хватает | подтверждение |
|---|---|
| **ELF-обёртки** | артефакт конвейера — `format: "osnova-shell-image"` (`src/e2k/emitterOracle.ts:49`), это не ELF. Для внешней проверки ELF писать пришлось — `src/scripts/e2kExternalObjdump.ts` (только код), и **минимальный ELF** — `src/e2k/elfMinimal.ts` (`docs/e2k-minimal-elf.md`) |
| **машины ELF для e2k** | **сделано**: `e_machine = 175` — `EM_E2K` (`qemu/include/elf.h:195`) = `EM_MCST_ELBRUS` (`binutils-gdb/include/elf/common.h:295`), машина `8c` в `e_flags` (`include/elf/e2k.h:114-115`) |
| **класса ELF** | **сделано**: `ELFCLASS64` + `EM_E2K`, как ждёт загрузчик (`qemu/linux-user/e2k/target_elf.h:10-11`) |
| **стартового кода, libc и системных вызовов** | **сделано для двух вызовов**: `_start` без libc пишет строку через `write` и завершается (§2.10), `exit(42)` возвращает 42 (§2.9). libc нет, таблица вызовов — **446** номеров (`qemu/linux-user/e2k/syscall_nr.h`), из них реализовано два |
| **ABI системных вызовов** | в e2k номер и аргументы идут через **системные регистры**: `sys_num`, `arg1…arg6`, `sys_rval` в `target_elf_gregset_t` (`qemu/linux-user/e2k/target_elf.h`) |

**Что у проекта есть:** 3 432 байта кодированного потока команд (`docs/e2k-real-run.md` §2) и
десять образцов, упакованных в ELF (`docs/e2k-external-validation.md` §4.2). Это **тело**
программы без заголовков, адресов загрузки и обращений к системе.

## 4. Что измерено вместо прогона (и что это доказывает)

| измерение | результат | где |
|---|---|---|
| инструкций пяти ядер понижено в операции e2k | 358 из 517 (было 346; `IR.jmp` понижен серией по двухпроходной раскладке) | `docs/e2k-real-run.md` §2 |
| round-trip понижённых инструкций | 358 сверено (370 команд e2k), расхождений 0 | там же |
| **смещение перехода сверено ассемблером МЦСТ** | **6 программ с `jmp` из 6** совпали побайтово; адреса меток совпали с адресами целей | `docs/e2k-external-as.md` §4 |
| **внешняя проверка дизассемблером МЦСТ** | **10 образцов из 10 совпали** | `docs/e2k-external-validation.md` §4.3 |
| **обратный ход: текст → байты ассемблером МЦСТ** | **24 образца из 24 совпали** | `docs/e2k-external-as.md` |
| **минимальный ELF прочитан дизассемблером и `readelf` МЦСТ** | разобран: 3 инструкции, 5 секций, символ `_start` | `docs/e2k-minimal-elf.md` §3 |
| **минимальный ELF ИСПОЛНЕН эмулятором (с шимом)** | остановка на `ct %ctpr1` (`0x100020`); обе `movts` прошли | `docs/e2k-minimal-elf.md` §4.1, §2.8 |
| **передача управления `disp` + `ct` проверена исполнением** | смещение 3 → `0x100018`, смещение 2 → `0x100010` (опыт + контроль) | `docs/e2k-minimal-elf.md` §4.3 |
| числа ядер при прогоне регистровой VM с семантикой e2k | **181 / 119 / 4 / 90 / 32** — совпали с эталоном | `docs/e2k-real-run.md` §3 |

**Чего это не доказывает:** что код исполнится на **железе** e2k и что программа завершится
`exit(42)`. Исполнение получено **в модели** (QEMU) и на отдельном опыте, а не на пяти ядрах:
ядрам по-прежнему нужен бинарник, а минимальному ELF — `sdisp` и оконный файл регистров (§3).

## 5. Что нужно, чтобы прогон состоялся

| шаг | состояние |
|---|---|
| 1. Собрать QEMU-e2k | **сделано** (§1, `docs/e2k-qemu-build.md` §2.5) |
| 2. Собрать кросс-binutils с e2k | **сделано** (`docs/e2k-external-validation.md` §4.1) |
| 3. Запустить QEMU на хосте, который размещает гостевой резерв e2k | **сделано на этом хосте шимом** (§2.8): `LD_PRELOAD` возвращает `MAP_FIXED_NOREPLACE` смысл, которого QEMU ждёт, и код исполняется. Без шима — **не выполнено**: WSL1 не размещает (§2.1–2.6); нужен хоть один вариант: шим, ядро Linux ≥ 4.17 (WSL2/VM/отдельная машина) |
| 4. Собрать `e2k-linux-as` (ассемблер) | **сделано**: `gas/config` собран, ассемблер принимает текст и совпал с кодировщиком на 24 образцах (`docs/e2k-external-as.md`); сделан и обратный ход — текст → байты |
| 5. Написать ELF-обёртку, стартовый код и системные вызовы | **сделано**: минимальный ELF64 с `_start` собран, разобран инструментами МЦСТ и **делает exit(42)** в модели (§2.9, `docs/e2k-minimal-elf.md` §7) |
| 6. Прогнать `qemu-e2k <binary>` и сравнить вывод с эталоном | **сделано для двух вызовов**: `write(1,"hello",5)` — stdout содержит `hello`, `exit(42)` — код возврата 42 (§2.10, `docs/e2k-syscall-abi.md` §5); пяти ядрам по-прежнему нужен бинарник (§3) |

Порядок: обычный Linux-хост (шаг 3) → стартовый код с настоящим вызовом (шаг 5) → прогон (шаг 6).
Шаг 4 (ассемблер) и первая половина шага 5 (ELF) **сделаны** — они дали то, что можно проверить
без прогона: двустороннюю сверку кодировки и разбор образа чужими инструментами.

## 6. Статусы

| утверждение | статус |
|---|---|
| QEMU-e2k собран (WSL1, 11.0.1) | **ФАКТ** (`docs/e2k-qemu-build.md` §2.5) |
| user-mode QEMU в этом окружении работоспособен | **ФАКТ**: `qemu-x86_64` запускает статический бинарник, код возврата 0 (§2.3) |
| `qemu-e2k` не размещает гостя на этом хосте | **ФАКТ**: `guest_base`, устойчиво при `-R` от 512 МБ до 16 ГБ (§2.1–2.2) |
| причина — отсутствие `MAP_FIXED_NOREPLACE` в WSL1, а не наш ELF | **ФАКТ**: зонд на C в том же WSL1 — `mmap(… MAP_FIXED_NOREPLACE)` → `errno=95` (ENOTSUP), при этом `MAP_FIXED` и обычный `mmap` адрес выдают, `/proc/self/maps` читается (§2.5). Флаг добавлен в Linux 4.17, WSL1 — слой трансляции, а не ядро |
| причина — требования e2k к размеру адресного пространства | **ФАКТ, но не решающий**: `TARGET_VIRT_ADDR_SPACE_BITS = 48` задаёт размер резерва; непреодолимым его делает отсутствующий флаг (§2.5) |
| у проекта есть e2k-бинарник пяти ядер | **НЕТ** (§3), но есть минимальный ELF с `_start` (`docs/e2k-minimal-elf.md`) |
| минимальный ELF **исполняется** эмулятором | **ФАКТ** (с шимом, §2.8): обе `movts` исполнены, остановка на `ct %ctpr1` в `0x100020` |
| байты CS0/SS (`disp`, `ct`) исполняются по смыслу | **ФАКТ**: опыт с передачей управления — смещение 3 → `0x100018`, смещение 2 → `0x100010` (§2.8; `src/e2k/e2kQemuExec.test.ts`) |
| `exit(42)` выполняется | **ФАКТ с шимом и правкой порта**: код возврата 42 (§2.9) |
| минимальный ELF валиден по заголовку и читается инструментами МЦСТ | **ФАКТ**: `objdump -f` → `elf64-e2k`, `elbrus-8c:64`; `objdump -d` разбирает три инструкции; `readelf -S` — 5 секций (`docs/e2k-minimal-elf.md` §3) |
| инструкции `_start` совпали с ассемблером МЦСТ | **ЧАСТИЧНО**: `movts` с литералом 42 и `ct` — побайтово; `movts` со значением 1 — измеренная разница форм (непосредственная `0xc1` у ассемблера против литерала `0xd4` у нас) |
| `exit(42)` выполняется минимальным ELF | **ФАКТ** (§2.9): пять инструкций, код возврата 42 |
| прогон на WSL2 или ином ядре Linux ≥ 4.17 | **НЕ ПРОВЕРЕНО**: ожидание из §2.5, а не замер — другого Linux-окружения на этой машине нет |
| вывод QEMU совпал с эталоном | **ФАКТ с шимом** (§2.8): stdout содержит `hello` — ровно те 5 байт, что записал наш код, и `exit(42)` возвращает 42 (§2.10). Для пяти ядер — **НЕТ**: бинарника нет |
