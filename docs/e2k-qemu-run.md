# QEMU-прогон пяти DSP-ядер: не состоялся

**Дата:** 2026-09-15
**Статус: ПРОГОН НЕ СОСТОЯЛСЯ.** Причина **одна** и она новая: QEMU **собран** (§1), но
`qemu-e2k` в этом окружении **не может разместить гостя** (§2) — `guest_base` не выделяется.
Прежняя причина «нечем запускать» снята сборкой в WSL. Вторая причина («нечего запускать» для
пяти ядер) осталась: у конвейера нет e2k-бинарника (§3).

---

## 1. Чем запускать: QEMU-e2k СОБРАН

`qemu-e2k version 11.0.1`, `/root/qemu-build/qemu-e2k`, дистрибутив `e2k` (WSL1, Alpine 3.24.1).
Как собрано и что этому мешало на Windows — `docs/e2k-qemu-build.md` §2.5.

**Запасного пути нет** (и он не понадобился): в архиве МЦСТ собранного `qemu-e2k` действительно
нет — среди `*.exe`/`*.so` в дереве только `linux-user/*/vdso*.so` чужих архитектур.

---

## 2. Что произошло при запуске: `guest_base` не размещается

### 2.1. Точный ответ

```
$ qemu-e2k .tmp/e2k-samples.elf
qemu-e2k: .tmp/e2k-samples.elf: Unable to find a guest_base to satisfy all guest address
mapping requirements
  0000000000000000-000000003fffffff
```

Ошибка выдаётся на **этапе загрузки образа**, до исполнения первой инструкции. Источник:
`linux-user/elfload.c:1095` (`probe_guest_base`), диапазон в сообщении — требуемый гостевой
резерв.

### 2.2. Перебор `-R` (резерв адресного пространства гостя)

| `-R` | требуемый диапазон | исход |
|---|---|---|
| по умолчанию | `0`…`0x3fffffff` | ошибка `guest_base` |
| `512M` | `0`…`0x1fffffff` | ошибка `guest_base` |
| `1G` | `0`…`0x3fffffff` | ошибка `guest_base` |
| `2G` | `0`…`0x7fffffff` | ошибка `guest_base` |
| `4G` | `0`…`0xffffffff` | ошибка `guest_base` |
| `8G`, `16G` | `0`…`0x1ffffffff`, `0`…`0x3ffffffff` | ошибка `guest_base` |

Размер резерва ни на что не влияет: разместить его в этом хосте не удаётся **ни при каком**
значении.

### 2.3. Контрольный эксперимент: дело не в QEMU и не в нашем ELF

| проверка | результат |
|---|---|
| тем же `configure`/`make` собран `qemu-x86_64` той же версии 11.0.1 | собран |
| статический бинарник x86-64 (`gcc -static`, `int main(void){return 0;}`) | запущен **напрямую**: код возврата 0 |
| он же под `qemu-x86_64` | код возврата **0** — user-mode QEMU в этом окружении **работает** |
| `qemu-e2k` на нашем ELF | ошибка `guest_base` (устойчиво) |

**Вывод:** препятствие не в QEMU (x86-64 цель работает), не в WSL как таковом и не в нашем ELF
(ошибка возникает **до** чтения инструкций). Препятствие — **требования целевой архитектуры e2k
к адресному пространству**, которые этот хост не удовлетворяет: у e2k
`TARGET_VIRT_ADDR_SPACE_BITS = 48` (`target/e2k/cpu-param.h:12`), и linux-user резервирует
гостевой диапазон целиком (`linux-user/elfload.c:1394-1400`).

### 2.4. Что это значит для постановки

Требование «прогнать на QEMU» упирается **не в сборку** (она сделана) и **не в кодировку**
(она подтверждена внешним дизассемблером), а в **хост**: WSL1 не даёт разместить гостевой резерв
e2k. На обычном Linux-хосте (не WSL1) тот же бинарь и тот же ELF запускаются — это
**не проверено здесь**, потому что другого Linux-окружения нет, и так и записано.

## 3. Нечего запускать: у проекта нет e2k-бинарника

Даже если бы `guest_base` разместился, `qemu-e2k <binary>` для **пяти ядер** запускать нечего:
конвейер проекта выдаёт **поток команд**, а не исполняемый файл.

| чего не хватает | подтверждение |
|---|---|
| **ELF-обёртки** | артефакт конвейера — `format: "osnova-shell-image"` (`src/e2k/emitterOracle.ts:49`), это не ELF. Для внешней проверки ELF писать пришлось — `src/scripts/e2kExternalObjdump.ts`, но он несёт **только код** |
| **машины ELF для e2k** | нужна `e_machine = 175`: `EM_E2K` (`qemu/include/elf.h:195`) = `EM_MCST_ELBRUS` (`binutils-gdb/include/elf/common.h:295`) |
| **класса ELF** | загрузчик e2k ждёт `ELFCLASS64` и `EM_E2K` (`qemu/linux-user/e2k/target_elf.h:10-11`) |
| **стартового кода, libc и системных вызовов** | нужен `_start`, вызов `exit` и таблица вызовов (446 номеров, `qemu/linux-user/e2k/syscall_nr.h`); в нашей кодировке **не реализованы управляющие слоги CS/SS**, которыми вызов и делается (`docs/e2k-real-run.md` §2) |
| **ABI системных вызовов** | в e2k номер и аргументы идут через **системные регистры**: `sys_num`, `arg1…arg6`, `sys_rval` в `target_elf_gregset_t` (`qemu/linux-user/e2k/target_elf.h`) |

**Что у проекта есть:** 2 184 байта кодированного потока команд (`docs/e2k-real-run.md` §2) и
десять образцов, упакованных в ELF (`docs/e2k-external-validation.md` §4.2). Это **тело**
программы без заголовков, адресов загрузки и обращений к системе.

## 4. Что измерено вместо прогона (и что это доказывает)

| измерение | результат | где |
|---|---|---|
| инструкций пяти ядер понижено в операции e2k | 268 из 517 | `docs/e2k-real-run.md` §2 |
| round-trip понижённых инструкций | 268 сверено, расхождений 0 | там же |
| **внешняя проверка дизассемблером МЦСТ** | **10 образцов из 10 совпали** | `docs/e2k-external-validation.md` §4.3 |
| числа ядер при прогоне регистровой VM с семантикой e2k | **181 / 119 / 4 / 90 / 32** — совпали с эталоном | `docs/e2k-real-run.md` §3 |
| предпосылки понижения на данных | нецелых операндов 0, усечений 32 бит 0 | там же |

**Чего это не доказывает:** что код исполнится на e2k. Кодировка подтверждена **внешним
дизассемблером**, исполнение не выполнено: эмулятор собран, но гостя не размещает (§2).

## 5. Что нужно, чтобы прогон состоялся

| шаг | состояние |
|---|---|
| 1. Собрать QEMU-e2k | **сделано** (§1, `docs/e2k-qemu-build.md` §2.5) |
| 2. Собрать кросс-binutils с e2k | **сделано** (`docs/e2k-external-validation.md` §4.1) |
| 3. Запустить QEMU на хосте, который размещает гостевой резерв e2k | **не выполнено**: WSL1 не размещает (§2); нужен обычный Linux-хост |
| 4. Собрать `e2k-linux-as` (ассемблер) | **не сделано**: `gas` был отключён; ассемблер дал бы **прямую** проверку «текст → байты» |
| 5. Написать ELF-обёртку, стартовый код и системные вызовы | **не сделано**: для этого нужны управляющие слоги CS/SS, которых в `e2k-real` нет |
| 6. Прогнать `qemu-e2k <binary>` и сравнить вывод с эталоном | **не выполнено** |

Порядок: обычный Linux-хост (шаг 3) → ассемблер (шаг 4, даёт ещё одну внешнюю проверку кодировки)
→ стартовый код (шаг 5) → прогон (шаг 6).
