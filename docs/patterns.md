# Паттерны архитектуры приложений на Основа

## Паттерн 1: Микромодуль

Когда использовать:
- Когда приложение имеет 2+ самостоятельные зоны ответственности (ядро, фильтры, приоритеты, хранилище).
- Когда код должен переиспользоваться между сценариями и тестами.

Пример:

```text
// tasks_core.osnova
модуль ЗадачиЯдро

процедура экспорт создать(заголовок, описание, приоритет)
  пусть ключ = система.строка.объединить("задача:", система.время.метка())
  пусть данные = система.строка.объединить(заголовок, "|")
  данные = система.строка.объединить(данные, описание)
  данные = система.строка.объединить(данные, "|активна|")
  данные = система.строка.объединить(данные, приоритет)
  система.хранилище.записать(ключ, данные)
  вернуть ключ
конец

процедура экспорт список()
  вернуть система.хранилище.ключи_с_префиксом("задача:")
конец

конец
```

```text
// main.osnova
модуль ТаскМенеджер
использовать модуль ЗадачиЯдро из "tasks_core.osnova"

процедура главная()
  пусть ключ = ЗадачиЯдро.создать("Задача", "Описание", "высокий")
  пусть все = ЗадачиЯдро.список()
  вернуть система.массив.длина(все)
конец

конец
```

Антипаттерн:
- Один монолитный модуль, где CRUD, фильтры, формат хранения и точка входа смешаны в одном файле.
- Отсутствуют `экспорт` и `использовать модуль ... из "..."` при разделении ответственности.

## Паттерн 2: Слой хранилища

Когда использовать:
- Когда формат записи в хранилище должен быть единым для всей системы.
- Когда нужно менять формат данных без правок бизнес-логики.

Пример:

```text
модуль ЗадачиХранилище

процедура экспорт сохранить(ключ, заголовок, описание, статус, приоритет)
  пусть данные = система.строка.объединить(заголовок, "|")
  данные = система.строка.объединить(данные, описание)
  данные = система.строка.объединить(данные, "|")
  данные = система.строка.объединить(данные, статус)
  данные = система.строка.объединить(данные, "|")
  данные = система.строка.объединить(данные, приоритет)
  система.хранилище.записать(ключ, данные)
  вернуть истина
конец

процедура экспорт загрузить(ключ)
  вернуть система.хранилище.прочитать(ключ)
конец

конец
```

Антипаттерн:
- Формат строки хранилища повторяется в каждом модуле.
- Бизнес-логика напрямую вызывает `система.хранилище.записать/прочитать` с разными форматами.

## Паттерн 3: Фильтрация через syscall'ы

Когда использовать:
- Когда фильтрация строится на текущих возможностях языка и системных вызовов.
- Когда нужно быстро реализовать отбор без расширения синтаксиса.

Пример:

```text
модуль ЗадачиФильтры

процедура экспорт по_статусу(ключи, статус)
  пусть результат = система.массив.создать()
  для_каждого ключ в ключи
    пусть данные = система.хранилище.прочитать(ключ)
    если система.строка.содержит(данные, статус)
      результат = система.массив.добавить(результат, ключ)
    конец
  конец
  вернуть результат
конец

процедура экспорт по_приоритету(ключи, приоритет)
  пусть результат = система.массив.создать()
  для_каждого ключ в ключи
    пусть данные = система.хранилище.прочитать(ключ)
    если система.строка.содержит(данные, приоритет)
      результат = система.массив.добавить(результат, ключ)
    конец
  конец
  вернуть результат
конец

конец
```

Антипаттерн:
- Фильтрация зашивается в UI-модуль.
- Требование "добавить новый синтаксис языка" для обычной фильтрации, решаемой через `система.строка.*` и `система.массив.*`.

## Паттерн 4: Точка входа

Когда использовать:
- Всегда для приложений из нескольких модулей.
- Когда нужно единое место запуска и связывания модулей.

Пример:

```text
модуль ТаскМенеджер

использовать модуль ЗадачиЯдро из "tasks_core.osnova"
использовать модуль ЗадачиФильтры из "tasks_filters.osnova"

процедура главная()
  пусть ключ = ЗадачиЯдро.создать("Задача", "Описание", "высокий")
  пусть все = ЗадачиЯдро.список()
  пусть активные = ЗадачиФильтры.активные(все)
  вернуть система.массив.длина(активные)
конец

конец
```

Антипаттерн:
- Нет отдельного `main.osnova`.
- Несколько разных процедур `главная` в одном приложении.
- Ядро, фильтры и запуск смешаны в одном модуле.
