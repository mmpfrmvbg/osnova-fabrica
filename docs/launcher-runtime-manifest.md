# Лаунчер, рантайм и манифест приложений Основа

Минимальный формат манифеста приложения и API рантайма, чтобы «как Steam, но для мира Основа» реально завёлся.

---

## 1. Формат пакета приложения `*.osvpk`

Пакет — **zip/тар** с фиксированной структурой:

- **Корень пакета:**
  - `manifest.json` — манифест
  - `code/` — байткод или исходники Основа
    - `main.osvbc` (или `main.osnova`)
    - остальные модули
  - `assets/` — ресурсы
    - `icon.png`
    - `locales/ru.json`
    - и т.п.

### Пример `manifest.json`

```json
{
  "id": "com.osnova.crm.basic",
  "name": "CRM: Базовая",
  "version": "1.0.3",
  "description": "Простая CRM для малого бизнеса",
  "author": "Фабрика",
  "entrypoint": {
    "module": "main",
    "function": "запуск"
  },
  "runtime": {
    "min_version": "0.1.0",
    "target": "win64"
  },
  "permissions": {
    "filesystem": ["documents/osnova-crm"],
    "network": ["api.osnova.cloud"],
    "storage": true,
    "notifications": true
  },
  "ui": {
    "type": "windowed",
    "default_width": 1200,
    "default_height": 800,
    "resizable": true
  },
  "distribution": {
    "hash": "sha256:....",
    "size_bytes": 12345678,
    "signature": "osnova-signature-..."
  }
}
```

- **`id`** — стабильный идентификатор пакета (аналог bundle ID).
- **`entrypoint`** — что вызывает рантайм: модуль и функция Основа.
- **`permissions`** — что лаунчер показывает пользователю и передаёт рантайму (можно валидировать).
- **`distribution`** — проверка целостности (для P2P).

## 2. Рантайм Основа под Windows

Один бинарь, например `osnova-runtime.exe`, который:

- принимает аргументы: путь к пакету (`.osvpk`) или `id` + `version`;
- валидирует манифест и подпись;
- монтирует пакет (как виртуальную ФС);
- создаёт процесс/контекст исполнения;
- даёт приложению **API-хост** (через FFI или встроенные модули языка).

### Минимальный API рантайма (логический)

С точки зрения Основа у приложения есть несколько «системных модулей»:

- `система.окно`
- `система.файлы`
- `система.время`
- `система.сеть`
- `система.хранилище`
- `система.лог`

#### Примеры сигнатур (на логическом уровне)

```основа
модуль система.окно {
    тип Окно {
        идентификатор: Целое64;
    }

    процедура создать_окно(заголовок: Строка, ширина: Целое32, высота: Целое32): Окно;
    процедура показать(окно: Окно);
    процедура закрыть(окно: Окно);

    процедура подписаться_на_события(окно: Окно, обработчик: ссылка процедура(Событие));
}

модуль система.файлы {
    функция прочитать_все(путь: Строка): Результат<Байт[], Ошибка>;
    функция записать_все(путь: Строка, данные: Байт[]): Результат<Ничто, Ошибка>;
    функция существует(путь: Строка): Логический;
}

модуль система.время {
    функция сейчас(): Целое64; // unix-тайм в мс
    процедура спать(мс: Целое32);
}
```

Рантайм внутри реализует эти модули на TS/Rust/C++ и мапит на WinAPI или кросс-платформенную библиотеку (SDL, Qt, Winit и т.д.).

## 3. Лаунчер «как Steam»

Обычное desktop-приложение:

- **UI-слой:**
  - авторизация/подписка;
  - список приложений из магазина (HTTP API);
  - управление установленными (локальный кэш).

- **Управление пакетами:**
  - хранит локальный каталог:
    - `apps/` (кэш скачанных `.osvpk`);
    - `index.json` (что установлено, какие версии).
  - умеет качать по:
    - HTTP (прямо с сервера);
    - P2P (через DHT/магнет-ссылки):
      - из каталога приходит `hash` + метаданные torrent/DHT;
      - лаунчер (или отдельный сервис) качает пакет, проверяет `hash`.

- **Запуск приложения:**
  - по кнопке «Запустить»:
    - находит `.osvpk` в локальном кэше;
    - запускает `osnova-runtime.exe --package path/to/app.osvpk`;
    - следит за процессом (логи, обновления).

---

## 4. Жизненный цикл приложения

1. **В магазине:**
   - хранится запись: `id`, `name`, `version`, `hash`, метаданные, скриншоты.

2. **Установка:**
   - лаунчер:
     - получает метаданные с сервера;
     - качает `.osvpk` по HTTP/P2P;
     - проверяет подпись и `hash`;
     - регистрирует в локальном каталоге.

3. **Запуск:**
   - лаунчер запускает рантайм с пакетом.
   - рантайм:
     - распаковывает;
     - валидирует `manifest.json` и `permissions`;
     - создаёт окружение (директории для данных, настройки);
     - вызывает `entrypoint` (модуль.функция) в Основа.

4. **Доступ к данным:**
   - приложение использует `система.файлы` / `система.хранилище` и видит только свой sandbox (например, `%APPDATA%/OsnovaApps/com.osnova.crm.basic/`).

5. **Обновление:**
   - лаунчер видит новую версию (по API магазина);
   - качает новый `.osvpk`, проверяет, обновляет запись;
   - старую версию может хранить или удалять (по политике).

## 5. Интеграция с фабрикой

- **Фабрика** при сборке приложения:
  - генерирует код Основа (по спекам);
  - компилирует его → байткод/IR;
  - собирает `manifest.json` (по шаблону/спеке);
  - пакует в `.osvpk`;
  - подписывает своим ключом;
  - публикует в магазин (HTTP API).

- **Модель «одна кнопка»:**
  - в spec:
    - описан тип приложения (desktop, окно, минимальные права);
    - сущности/экраны/бизнес-логика.
  - пайплайн:
    - `spec.yaml` → Основа-код → тесты → `.osvpk` → запись в каталог → доступно всем клиентам.

---

## 6. Минимальный шаг для MVP

Чтобы не утонуть, минимальный «первый живой эксперимент»:

- **Рантайм:**
  - консольный: только `система.лог`, `система.файлы`, простое окно без сложного UI.

- **Пакет:**
  - простой `.zip` с `manifest.json` и одним `main.osnova`.

- **Лаунчер:**
  - обычное окно с двумя кнопками:
    - «Установить/обновить пример-приложение»;
    - «Запустить».

- **Приложение:**
  - что-то простое — таск-лист или заметки, но **полностью на Основа**.

После этого уже можно:
- усложнять рантайм (окна, кнопки, формы);
- добавлять реальные категории приложений;
- подключать P2P и нормальный магазин.
