# RFC-001: try/catch avoidance через few-shot промпты

**Тип:** anti-rfc
**Статус:** phase_a
**Risk:** low
**Автор:** lang-agent
**Создан:** 2026-03-21
**Коммит Phase A:** 5347cb5

---

## Проблема

LLM генерирует JavaScript-синтаксис `try { } catch(e) { }` вместо
конструкции языка Основа `попробовать / иначе_попытка е / конец`.

Паттерн-триггер: `catchVar` (переменная-флаг вместо try/catch).

## Гипотеза

3+ few-shot примера в `buildOsnovaPrompt` + явные строки НЕЛЬЗЯ в repair-промпте
снизят частоту ошибки до <5% без изменения грамматики языка.

## Что сделано (Phase A)

- Добавлены 3 few-shot примера попробовать в `buildOsnovaPrompt.ts` (коммит 5347cb5)
- Добавлены антипаттерны `try/catch` и `throw new Error` в `buildOsnovaRepairPrompt`
- Добавлена секция «Типичные ошибки LLM» в `docs/language-v1.md` (коммит c914825)
- Добавлен repair-guard для return/redeclare/assign-before-let (коммит 2470407)

## Критерий закрытия

- [ ] 50+ canary-трейсов с задачами на обработку ошибок
- [ ] Частота `js_try_catch` < 5%
- [ ] `teachability_score` на категории errors ≥ 0.8

## Альтернативы рассмотрены

1. Изменить синтаксис — отклонено (нарушает стабильность)
2. Добавить компилятор-guard — избыточно до данных трейсов

## Решение после Phase A

Ожидание трейсов. Если гипотеза не подтвердится → эскалация PM с данными.
