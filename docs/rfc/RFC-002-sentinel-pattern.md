# RFC-002 / Anti-RFC A-6: sentinel pattern — пусто вместо ошибок

**Тип:** anti-rfc
**Статус:** draft
**Risk:** low
**Автор:** lang-agent
**Создан:** 2026-03-21

---

## Проблема

77 трейсов используют `== пусто` / `!= пусто` как сигнальный sentinel
вместо `попробовать/иначе_попытка`. Паттерн: LLM возвращает `пусто`
из процедуры при ошибке и проверяет его через `если результат == пусто`.

Это обходное решение — не ошибка синтаксиса, но degraded quality.
sentinel=104 — самый частый workaround_pattern в базе.

## Гипотеза

Few-shot примеры с явным `попробовать` для задач типа
"прочитать/найти/получить → обработать отсутствие" снизят sentinel
до <20% без изменения синтаксиса.

## Данные

- sentinel всего: 104
- sentinel без попробовать: 77
- sentinel + попробовать: 27 (корректное использование)
- Связь с repair_exhausted: первые 3 примера = exhausted

## Phase A (план)

- [ ] Добавить 3 few-shot примера в buildOsnovaPrompt:
      задача "найти элемент" → попробовать вместо sentinel
- [ ] Добавить в FORBIDDEN: sentinel как антипаттерн с примером
- [ ] Golden-тест: sentinel_vs_try — проверить что LLM выбирает попробовать
- [ ] Canary: 50 трейсов → замерить sentinel rate до/после

## Критерий закрытия

sentinel_count / total < 20% на 50+ трейсах после Phase A
