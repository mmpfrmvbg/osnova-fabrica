## Лексер языка «Основа» v0.1

> ⚠️ Исторический документ v0.1. Используется только как legacy-контекст.
> Канон языка для текущей разработки: `docs/language-v2.md` и `docs/osnova/language-schema.json`.

Этот документ описывает минимальную спецификацию лексера для языка `Основа`, исходя из текущей неформальной грамматики (`grammatika-v0.1`).

Цель: получить **детерминированный, простой для реализации лексер**, который:

- устойчиво работает с кириллицей и латиницей;
- чётко разделяет ключевые слова, идентификаторы и операторы;
- подходит как для компилятора, так и для фабрики (генерации/миграций кода).

---

## 1. Общие принципы

- Вход: поток Unicode-символов в кодировке UTF‑8 (или UTF‑16 для рантайма под Windows, но логика та же).
- Лексер работает в режиме **“максимального жадного матчинга”**:
  - для идентификаторов, чисел, строк, операторов из 2+ символов (например, `<=`, `>=`, `!=`).
- Пробелы, табы и переводы строк (кроме нужных для позиций ошибок) игнорируются на уровне токенов.
- Комментарии удаляются лексером и в парсер не попадают.

---

## 2. Классы символов

Определяем несколько базовых классов:

- `Letter` — любые буквы Юникода:
  - включает кириллицу (`А-Я`, `а-я`, `Ё`, `ё`) и латиницу (`A-Z`, `a-z`);
  - допускаются буквы с диакритикой (если встретятся) — для надёжности.
- `Digit` — `0-9`.
- `Underscore` — `_`.
- `Quote` — `"` (двойная кавычка).
- `Punct` — пунктуация и спецсимволы: `(){}[];,.:<>+-*/=%!&|?`.

Рекомендуется в реализации использовать стандартные флаги Юникода (`ID_Start`, `ID_Continue`) для идентификаторов, но в v0.1 достаточно правил ниже.

---

## 3. Комментарии и пробелы

- **Однострочный комментарий**:
  - начинается с `//` и продолжается до конца строки (включая `\r\n` или `\n`);
  - лексер возвращает один токен `Comment` или просто пропускает его (в большинстве случаев достаточно пропустить).
- **Многострочных комментариев** в v0.1 нет (можно добавить позже).
- **Пробельные символы**:
  - ` ` (space), `\t`, `\r`, `\n`, `\f`;
  - всегда игнорируются, кроме учёта позиции (строка/столбец) для отчёта об ошибках.

---

## 4. Идентификаторы и ключевые слова

### 4.1. Идентификатор

Идентификатор — это:

- первый символ: `Letter` или `Underscore`;
- последующие символы: `Letter` | `Digit` | `Underscore`.

Примеры валидных идентификаторов:

- `модуль`, `планировщик`, `Задача`, `Вектор3`, `x`, `позиция_юнита`, `_внутренний`.

### 4.2. Ключевые слова

После выделения последовательности символов по правилу идентификатора, лексер:

- проверяет её на совпадение со списком ключевых слов;
- если совпало — выдаёт токен вида `KwМодуль`, `KwФункция` и т.п.;
- если не совпало — обычный идентификатор `Identifier`.

Список ключевых слов v0.1 (согласован с `grammatika-v0.1`; `структура` не входит — зарезервировано).

**Реализовано в MVP-лексере** (`src/tools/osnova-compiler/lexer.ts`):

```text
модуль      процедура   пусть   если    иначе   пока   для_каждого   в   цикл   конец   вернуть
истина     ложь        пусто   и       или     не
```

- **`для_каждого`** — цикл по коллекции; после него ожидается имя переменной, затем **`в`**, затем выражение.
- **`в`** — ключевое слово в конструкции `для_каждого x в выражение`.
- **`и`**, **`или`** — бинарные логические операторы (short-circuit в парсере/кодогене).
- **`не`** — унарный оператор отрицания в выражениях; лексер выдаёт соответствующий токен, парсер использует в логических выражениях.

**Расширенный список (спека грамматики):**

```text
модуль      использовать    тип         процедура
функция     пусть           если        иначе
иначе_если  пока            для         каждого
совпадает   когда           вернуть     параллельно
предвыбор   пакет           слот        цикл
разворачивать регион       небезопасно актор
задача      канал           ожидать     ссылка
пусто       истина          ложь        не
Успех       Неудача         Результат   вызвать
открытый    закрытый        по          в
```

Особенности:

- ключевые слова чувствительны к регистру (`Успех` и `успех` — разные токены: второе будет идентификатором);
- допускается использование латинских идентификаторов (но в v0.1 не попадают в список ключевых слов).

## 5. Литералы

### 5.1. Числовые литералы

Минимальная версия (v0.1) поддерживает:

- **целые**: последовательность из одной или более цифр:
  - `0`, `42`, `123456`;
- **вещественные** (опционально, если нужно сразу):
  - `digit+ '.' digit+`:
    - `3.14`, `0.5`, `10.0`.

Суффиксы типа (`Целое32`, `Вещественное32` и т.п.) задаются **анотациями типов**, а не в самом литерале, поэтому в лексере их нет.

Токены:

- `IntLiteral(value: number | bigint, raw: string)`;
- `FloatLiteral(value: number, raw: string)` — если решишь сразу разделять.

### 5.2. Строковые литералы

Строка:

- начинается с `"` и заканчивается на ближайший непроэкранированный `"` в той же строке или последующих;
- поддерживаются escape-последовательности:
  - `\"`, `\\`, `\n`, `\r`, `\t`;
  - остальное можно трактовать как ошибка или как “буквальный символ после `\`”.

Пример:

```основа
пусть имя = "Артём";
пусть путь = "C:\\папка\\файл.кфг";
```

Токен:

- `StringLiteral(value: string, raw: string)`.

### 5.3. Логические литералы

`истина` и `ложь` входят в список ключевых слов и лексер выдаёт для них специальные токены:

- `KwИстина` / `KwЛожь` либо обобщённо `BoolLiteral(true/false)`.

---

## 6. Операторы и разделители

Лексер должен различать:

- **трёхсимвольные и двусимвольные операторы** (проверяются первыми, чтобы не слиться с одиночными):
  - `+=`, `-=`, `*=`, `/=`, затем `<=`, `>=`, `==`, `!=`;
- **одиночные операторы**:
  - `=`, `<`, `>`, `+`, `-`, `*`, `/`, `%`, `!`, `?`;
- В v0.1 составные присваивания **обязательны** (согласовано с парсером и грамматикой).
- **разделители**:
  - скобки: `(`, `)`, `{`, `}`, `[`, `]`;
  - пунктуация: `;`, `:`, `,`, `.`, `<`, `>` (для дженериков), `|`;
  - угловые скобки `<`/`>` в выражениях типов (`Список<Юнит>`) **лексер не различает по контексту**: это просто токены `Less` и `Greater`, парсер решает, это оператор или дженерик.

Рекомендуется завести перечисление вида:

- `TokenKind`:
  - `Plus`, `Minus`, `Star`, `Slash`, `Percent`,
  - `Assign`, `Equal`, `NotEqual`, `Less`, `LessEqual`, `Greater`, `GreaterEqual`,
  - `LParen`, `RParen`, `LBrace`, `RBrace`, `LBracket`, `RBracket`,
  - `Colon`, `Semicolon`, `Comma`, `Dot`, `Question`,
  - и т.д.

---

## 7. Ошибки и позиционирование

Каждый токен должен содержать:

- `start` (строка, столбец, абсолютный offset);
- `end` (аналогично).

При некорректных последовательностях:

- лексер выдаёт токен `Error` с описанием проблемы и диапазоном;
- компилятор/IDE могут подсветить эту область и продолжить разбор (best effort).

Примеры ошибок:

- незакрытая строка (`"` без пары);
- неизвестный символ (не попал ни в один из классов);
- недопустимый escape в строке.

## 8. Эскиз интерфейса лексера на TypeScript

Ниже — пример **формата интерфейса** лексера, не обязательно строго придерживаться именно его, но он даёт ощущение масштаба и структуры.

```ts
export enum TokenKind {
  Identifier,
  IntLiteral,
  FloatLiteral,
  StringLiteral,

  // Ключевые слова (пример, можно продолжить)
  KwМодуль,
  KwИспользовать,
  KwТип,
  KwПроцедура,
  KwФункция,
  KwПусть,
  KwЕсли,
  KwИначе,
  KwИначеЕсли,
  KwПока,
  KwДля,
  KwКаждого,
  KwСовпадает,
  KwКогда,
  KwВернуть,
  KwПараллельно,
  KwПредвыбор,
  KwПакет,
  KwСлот,
  KwЦикл,
  KwРазворачивать,
  KwРегион,
  KwНебезопасно,
  KwАктор,
  KwЗадача,
  KwКанал,
  KwОжидать,
  KwСсылка,
  KwПусто,
  KwИстина,
  KwЛожь,
  KwНе,
  KwУспех,
  KwНеудача,
  KwРезультат,
  KwВызвать,
  KwОткрытый,
  KwЗакрытый,
  KwПо,
  KwВ,

  // Операторы
  Plus,
  Minus,
  Star,
  Slash,
  Percent,
  Assign,       // =
  PlusAssign,   // +=
  MinusAssign,  // -=
  StarAssign,   // *=
  SlashAssign,  // /=
  Equal,        // ==
  NotEqual,     // !=
  Less,         // <
  LessEqual,    // <=
  Greater,      // >
  GreaterEqual, // >=

  // Разделители
  LParen,   // (
  RParen,   // )
  LBrace,   // {
  RBrace,   // }
  LBracket, // [
  RBracket, // ]
  Comma,    // ,
  Semicolon,// ;
  Colon,    // :
  Dot,      // .
  Question, // ?

  // Прочее
  EndOfFile,
  Error,
}

export interface Token {
  kind: TokenKind;
  lexeme: string;
  line: number;
  column: number;
  offset: number;
}

export interface LexerError {
  message: string;
  line: number;
  column: number;
  offset: number;
}

export interface LexerResult {
  tokens: Token[];
  errors: LexerError[];
}

export function tokenize(source: string): LexerResult {
  // Реализация лексера следует правилам из этого документа:
  // - пропускает пробелы и комментарии
  // - выделяет идентификаторы и мапит их на ключевые слова
  // - парсит числовые и строковые литералы
  // - распознаёт операторы и разделители
  // - собирает ошибки при некорректных последовательностях
  return { tokens: [], errors: [] };
}
```

## 9. Границы v0.1

То, что **точно входит** в v0.1:

- комментарии `// ...`;
- идентификаторы (кириллица/латиница/`_`) и полный список ключевых слов;
- целые литералы и строковые литералы;
- базовый набор операторов (`=`, `+`, `-`, `*`, `/`, сравнения);
- скобки и разделители;
- базовая система ошибок + позиционирование токенов.

То, что можно добавить в v0.2+:

- многострочные комментарии `/* ... */`;
- более богатые числовые литералы (суффиксы типов, экспоненты);
- “сырые” строки без экранирования;
- комбинированные операторы (`+=`, `&&`, `||` и т.п.).
