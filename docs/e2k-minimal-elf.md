# Минимальный ELF для e2k: `_start` без `exit(42)`

**Дата:** 2026-09-15 (ночь).
**Зачем:** у конвейера не было **ни одного** e2k-исполняемого файла, поэтому прогон в QEMU
(`docs/e2k-qemu-run.md`) упирался не только в хост, но и в отсутствие предмета запуска. Здесь
собран минимальный ELF64: заголовок, один сегмент `PT_LOAD`, `.text` из трёх инструкций и точка
входа `_start`. **Статус: ELF валиден по заголовку и разбирается инструментами МЦСТ, но
`exit(42)` им не выполняется** — два препятствия названы в §5, а не спрятаны.

**Правило то же, что и в `docs/e2k-syllables-real.md`:** у каждой величины — источник
`файл:строка`; байтовые примеры — **измеренные** (ассемблер МЦСТ, дизассемблер МЦСТ, `readelf`
из той же сборки binutils).

Код: `src/e2k/elfMinimal.ts`, оракул: `src/e2k/elfMinimal.test.ts`.

---

## 1. Заголовок ELF

| поле | значение | источник |
|---|---|---|
| `e_ident[EI_CLASS]` | 2 (`ELFCLASS64`) | загрузчик e2k ждёт `ELFCLASS64` и `EM_E2K` (`qemu/linux-user/e2k/target_elf.h:10-11`) |
| `e_ident[EI_DATA]` | 1 (`ELFDATA2LSB`) | порядок байтов e2k — младший вперёд (`qemu/target/e2k/syllab-format.h`, раскладка полей) |
| `e_type` | 2 (`ET_EXEC`) | статический исполняемый файл |
| `e_machine` | **175** (`EM_E2K`) | `qemu/include/elf.h:195` = `EM_MCST_ELBRUS` (`binutils-gdb/include/elf/common.h:295`) |
| `e_flags` | `0x13000000` | машина `bfd_mach_e2k_8c = 19` (`binutils-gdb/include/elf/e2k.h:114-115`) в старшем байте |
| `e_entry` | `0x100000` | **наше решение**: у linux-user загрузчика адрес свободный; `.text` начинается там же |
| `e_phoff` / `e_phnum` | `0x40` / 1 | один сегмент `PT_LOAD` |
| `e_shoff` / `e_shnum` / `e_shstrndx` | `0x1088` / 5 / 4 | null, `.text`, `.symtab`, `.strtab`, `.shstrtab` |
| `p_flags` | `R|X` (5) | код, не данные |
| `p_offset` / `p_vaddr` / `p_filesz` | `0x1000` / `0x100000` / `0x81` | образ одним сегментом |

Источник чисел системных вызовов: `qemu/linux-user/e2k/syscall_nr.h:9` — `TARGET_NR_exit 1`
(`exit_group` — 300, там же `:293`). Поэтому номер вызова в коде — **1**, а не 60.

## 2. Код: что именно лежит в `.text` (40 байт)

Инструкции — извлечёнными формами: литералы LTS и управляющий слог SS
(`docs/e2k-syllables-real.md`).

| адрес | байты (измерено) | что это | форма |
|---|---|---|---|
| `0x100000` | `11 00 00 04 00 d4 c0 60 00 00 00 00 00 00 01 00` | `movts,0 1, %b[0]` — номер вызова `exit` | ALF1 + LTS (16 байт) |
| `0x100010` | `11 00 00 04 01 d4 c0 60 00 00 00 00 00 00 2a 00` | `movts,0 42, %b[1]` — код возврата | ALF1 + LTS (16 байт) |
| `0x100020` | `01 10 00 00 20 04 00 c0` | `ct %ctpr1` (условие ALWAYS) | SS (8 байт) |

`0xd4` — ссылка на 16-битный литерал в старшей половине последнего слова
(`opcodes/e2k-dis.c:445-479`), `0x2a = 42` и `0x01` видны в байтах 14–15.

## 3. Внешняя проверка: инструменты МЦСТ

Сборка binutils с `--target=e2k-linux` — `docs/e2k-external-validation.md` §4.1.

### 3.1. Дизассемблер разбирает ELF целиком

```
$ objdump -f e2k-minimal.elf
e2k-minimal.elf:     file format elf64-e2k
architecture: elbrus-8c:64, flags 0x00000112:
EXEC_P, HAS_SYMS, D_PAGED
start address 0x0000000000100000

$ objdump -d e2k-minimal.elf
0000000000100000 <_start>:
  100000:  movts,0 _f16s 0x1, %b[0]
  100010:  movts,0 _f16s 0x2a, %b[1]
  100020:  ct %ctpr1
           ipd 3
```

Три инструкции — ровно те, что задуманы; `_start` — из таблицы символов.

### 3.2. `readelf` видит таблицу секций и символ

```
$ readelf -S e2k-minimal.elf
There are 5 section headers, starting at offset 0x1088:
  [ 1] .text     PROGBITS  0000000000100000  00001000  00000028  AX
  [ 2] .symtab   SYMTAB    0000000000000000  00001028  00000030  link 3 info 1 entsize 0x18
  [ 3] .strtab   STRTAB    0000000000000000  00001058  00000008
  [ 4] .shstrtab STRTAB    0000000000000000  00001060  00000021

$ objdump -t e2k-minimal.elf
0000000000100000 g     F .text  0000000000000028 _start
```

**Измеренная особенность:** `objdump -h` для этой цели печатает **только** `.text`
(так же ведёт себя и прежний `e2k-samples.elf`), тогда как `readelf -S` видит все пять секций.
Это поведение BFD цели, а не дефект наших заголовков: `readelf` и таблица символов читают те же
поля.

### 3.3. Ассемблер: две инструкции из трёх совпали побайтово, у третьей — измеренная разница форм

| текст | ассемблер МЦСТ | наш кодировщик | вывод |
|---|---|---|---|
| `movts,0 42, %b[1]` | `11 00 00 04 01 d4 c0 60 … 2a 00` (16 байт) | те же байты | **совпало** |
| `ct %ctpr1` | `01 10 00 00 20 04 00 c0` (8 байт) | те же байты | **совпало** |
| `movts,0 1, %b[0]` | `01 00 00 04 00 c1 c0 60` (8 байт) | `11 00 00 04 00 d4 c0 60 … 01 00` (16 байт) | **разные формы** |

Причина расхождения измерена: значение **0…15** ассемблер кладёт 4-битной **непосредственной**
формой (поле `0xc0 | N`, здесь `0xc1`), а наш кодировщик всегда использует **литерал LTS**
(`0xd4`). Обе формы разбираются дизассемблером МЦСТ (§3.1 — он печатает `_f16s 0x1` именно для
нашей), но по байтам и по длине это разные записи. Непосредственная форма в `e2k-real` не
реализована — это записано здесь, а не замазано равенством.

## 4. Прогон в QEMU: причина та же, что и раньше

`qemu-e2k version 11.0.1` собран (`docs/e2k-qemu-build.md` §2.5). Запуск минимального ELF:

```
$ qemu-e2k .tmp/e2k-minimal.elf
qemu-e2k: .tmp/e2k-minimal.elf: Unable to find a guest_base to satisfy all guest address
mapping requirements
  0000000000000000-000000003fffffff
(код возврата 0)
```

**Контрольные опыты** (нужны, чтобы утверждение «дело не в нашем ELF» было замером, а не
догадкой):

| опыт | результат |
|---|---|
| `qemu-e2k` на файле, который не ELF (`not-an-elf.bin`) | **другая** ошибка: `Error while loading …: Exec format error` — файл читается и проверяется |
| `qemu-e2k` на прежнем `e2k-samples.elf` (собран другой дорогой) | **та же** ошибка `guest_base` |
| `qemu-x86_64` той же сборки на своём бинарнике | код возврата 0 — user-mode QEMU в окружении работает |

**Что из этого следует:** до исполнения первой инструкции дело не доходит; `qemu-e2k` отвергает
**любой** e2k-образ в этом окружении (WSL1) из-за требований целевой архитектуры к адресному
пространству: `TARGET_VIRT_ADDR_SPACE_BITS = 48` (`qemu/target/e2k/cpu-param.h:12`),
`probe_guest_base` (`linux-user/elfload.c:1095`). Подробности и перебор `-R` — `docs/e2k-qemu-run.md` §2.

**Отдельно измерено:** при отказе загрузки `qemu-e2k` завершается **кодом 0** и пишет причину в
stderr. Из этого следует практическое: проверять прогон по коду возврата **нельзя** — отказ
загрузки выглядел бы как успех.

## 5. Почему это не `exit(42)`: два препятствия

| # | препятствие | источник |
|---|---|---|
| 1 | **Файл регистров.** ABI читает номер вызова из **оконного** `r0`, аргументы — из `r1`…`r8` | `qemu/linux-user/e2k/cpu_loop.c:160-182` |
| | полю слога оконный файл соответствует как `0x80|N` (`%rN`), а интерфейс `Operand` несёт только номер, то есть **базовый** файл (`0x00|N`, `%b[N]`) | `opcodes/e2k-dis.c:416-419` |
| | следствие: номер вызова этим ELF'ом кладётся в `%b[0]`, а ABI прочтёт `%r0` | — |
| 2 | **Сам вызов.** QEMU выполняет системный вызов, только когда передача управления идёт на `%ctpr` с тегом `CTPSL` | `qemu/target/e2k/tcg/translate-ct.c:1143-1145`; тег ставит `translate-ctp.c:174` |
| | как записать эту подготовку ассемблером МЦСТ — **НЕТ В ИСТОЧНИКЕ**: мнемоник `syscall`/`ctpsl` в таблице опкодов нет, `ipush` ассемблер отвергает, `ct` тег не ставит | измерено (см. ниже) |

Что именно измерено по второму препятствию (ассемблер МЦСТ, `-mcpu=elbrus-v5`):

| текст | ответ ассемблера |
|---|---|
| `syscall` | `Error: unknown instruction 'syscall'` |
| `ctpsl` | `Error: unknown instruction 'ctpsl'` |
| `ipush %ctpr1` | `Error: unknown instruction 'ipush'` |
| `ct %ctpr1, syscall` | `Error: end of line expected` |
| `ct %ctpr1` | собрано (тег `CTPSL` в выводе `objdump` отсутствует) |

Поиск по таблице опкодов МЦСТ (`opcodes/e2k-opc.h`, 4 271 запись) мнемоник с семантикой
«поставить тег системного вызова» тоже не даёт — отсюда **НЕТ В ИСТОЧНИКЕ**.

**Поэтому `ct %ctpr1` в §2 — обычная передача управления**, а не вызов. Программа не завершится
кодом 42, и тест требует, чтобы оба препятствия были названы (`elfMinimal.test.ts`, проверка
«препятствия названы, а не спрятаны»).

## 6. Что проверено, а что нет

| утверждение | статус |
|---|---|
| ELF валиден по заголовку (`e_machine`, класс, данные, машина) | **ФАКТ**: `objdump -f` → `elf64-e2k`, `elbrus-8c:64`, `start address 0x100000` |
| таблица секций и символов читается чужим инструментом | **ФАКТ**: `readelf -S` — 5 секций, `objdump -t` — `_start` |
| инструкции в `.text` — извлечённые формы, а не выдумка | **ФАКТ**: `movts` с LTS и `ct` совпали с ассемблером; третья — измеренная разница форм (§3.3) |
| дизассемблер МЦСТ читает этот ELF как программу | **ФАКТ**: §3.1 |
| **`exit(42)` происходит** | **НЕТ**: препятствия 1–2 (§5) не сняты |
| прогон в QEMU состоялся | **НЕТ**: `guest_base` (§4), причина — хост, а не образ |
