# Широкая команда e2k: извлечение формы

**Зачем.** Всё, что измерялось раньше (плотность 1.45, ILP, такты), измерялось на **оболочке**, а
не на реальном e2k. Главная гипотеза проекта — «VLIW-планировщик, соединённый с реальной
кодировкой e2k, даёт измеримый выигрыш на DSP-задаче» — требует, чтобы несколько операций лежали
в **одной** широкой команде e2k. Наш кодировщик (`src/e2k/e2k-real.ts`) до этого документа умел
ровно **один** слог ALS на команду, то есть одна команда = одна операция.

Документ фиксирует форму широкой команды **из источников** и замер ассемблером. Каждое
утверждение — со ссылкой `файл:строка`; чего в источнике нет — помечено **НЕТ В ИСТОЧНИКЕ**.

| | |
|---|---|
| дерево binutils | `.tmp/e2k-sources/binutils-gdb/` |
| дерево QEMU | `.tmp/e2k-sources/qemu-e2k/qemu/` |
| описание ISA | `.tmp/e2k-sources/elbrus-docs/README.md` |
| происхождение копий | `docs/e2k-sources-raw.md` |
| оракул этого документа | `src/scripts/e2kWideCommands.audit.test.ts` |

## 1. Что искали (метаправило: все формы)

Метаправило проекта — отрицательное утверждение делается только после поиска **всеми** формами,
которыми источник пользуется. Искали:

| форма поиска | что искали | где |
|---|---|---|
| русское слово | «широкая команда», «слог» | `elbrus-docs/README.md`, `gas/config/tc-e2k.c` |
| английское слово | `wide instruction`, `syllable`, `packet`, `bundle` | те же деревья |
| сокращение | `WI`, `HS`, `SS`, `ALS`, `ALES`, `CS`, `LTS`, `PLS`, `CDS` | `opcodes/e2k-dis.c`, `qemu/target/e2k/` |
| поле кодировки | `lng`, `mdl`, `nl`, `psize`, `wbs`, `nop` | `gas/config/tc-e2k.c`, `qemu/target/e2k/syllab-format.h` |
| мнемоника | `adds,0` / `adds,1` — номер канала в имени | `opcodes/e2k-opc.h` |

**Чего в источниках НЕТ (проверено этими формами):**

- слов `packet` и `bundle` — **нет ни одного вхождения** ни в одном из четырёх деревьев; в
  README термин ровно один: «wide instruction (широкая команда, ШК)» (`elbrus-docs/README.md:117`).
- поля `nl` и `psize` в описании **широкой команды** — **НЕТ В ИСТОЧНИКЕ** (в QEMU есть
  `psize_q`/`size_q`, но это размер **окна регистров** (`linux-user/e2k/cpu_loop.c:302-303`), а не
  длина команды).
- отдельного «директивы упаковки» — синтаксис задают **фигурные скобки** (§4).

## 2. Форма: что найдено

### 2.1. Команда — это контейнер слогов

| утверждение | источник |
|---|---|
| широкая команда состоит из **заголовочного слога** и нуля или более дополнительных слогов | `elbrus-docs/README.md:117`, `:123`, `:133` |
| она выровнена на **8 байт** и длиной до **16 слов (64 байта)** | `elbrus-docs/README.md:117` |
| слоги идут в фиксированном порядке: HS, SS, ALS0…ALS5, CS0, ALES2, ALES5, CS1, ALES0/1/3/4, AAS0…AAS5, LTS3…LTS0, PLS2…PLS0, CDS2…CDS0 | `elbrus-docs/README.md:137-147` |
| полуслоги ALES и AAS — полслова (2 байта), все прочие слоги — слово (4 байта) | `elbrus-docs/README.md:151` |

### 2.2. Границы команды задаёт `lng`

| утверждение | источник |
|---|---|
| `lng` — биты **6:4** заголовочного слога: «длина инструкции в единицах по 8 байт **минус 8 байт**» | `elbrus-docs/README.md:197` |
| в QEMU: `hs_instr_size = (hs_lng + 1) * 8`, и размер команды **обязан** совпасть с ним | `qemu/target/e2k/instr-bits.h:40-45` |
| в трансляции длина читается тем же выражением: `(FIELD_EX32(hs, HS, lng) + 1) * 8` | `qemu/target/e2k/tcg/translate.c:258-259` |
| в ассемблере: `hs->lng = (crnt_syll >> 1) - 1`, где `crnt_syll` — число **4-байтовых** слогов | `gas/config/tc-e2k.c:9577` |
| перед этим ассемблер требует чётного числа слогов (`gas_assert ((crnt_syll & 0x1) == 0)`) и ругается, если слогов больше 16: «wide instruction requires %d syllables which exceeds the maximal supported size of 16 ones» | `gas/config/tc-e2k.c:9554-9557`, `:9576` |

Итог: **8 байт × (lng + 1)** — это внешняя граница команды. Внутри слоги размечаются не `lng`, а
битами присутствия (§2.3) и «средней точкой» (§2.4).

### 2.3. Биты присутствия слогов (заголовочный слог)

| биты | что означает | источник |
|---|---|---|
| 26…31 | наличие ALS0…ALS5 (по одному биту на канал) | `elbrus-docs/README.md:176-181`; `qemu/target/e2k/syllab-format.h:29` (`al`, 31:26) |
| 20…25 | наличие ALES0…ALES5 | `elbrus-docs/README.md:182-187`; `syllab-format.h:28` (`ale`, 25:20) |
| 19:18 | **число** слогов PLS | `elbrus-docs/README.md:188`; `syllab-format.h:27` (`pl`, 19:18) |
| 17:16 | **число** слогов CDS | `elbrus-docs/README.md:189`; `syllab-format.h:26` (`cd`, 17:16) |
| 15 | наличие CS1 | `elbrus-docs/README.md:190`; `syllab-format.h:25` (`c1`, 15) |
| 14 | наличие CS0 | `elbrus-docs/README.md:191`; `syllab-format.h:24` (`c0`, 14) |
| 12 | наличие SS (слог-заглушка) | `elbrus-docs/README.md:193`; `syllab-format.h:21` (`s`, 12) |
| 9:7 | `nop` | `elbrus-docs/README.md:196`; `syllab-format.h:19` (`nop`, 9:7) |
| 3:0 | «средняя точка» (middle pointer) | `elbrus-docs/README.md:198`; `syllab-format.h:17` (`mdl`, 3:0) |

Слогов ALS в команде может быть до **6**: `#define E2K_ALS_NUM 6`
(`qemu/target/e2k/syllab-format.h:219`).

### 2.4. Порядок упаковки: середина и конец

| правило | источник |
|---|---|
| SS, ALS\*, CS0 идут за HS **подряд, без пропусков**, в порядке возрастания номера | `elbrus-docs/README.md:153-154`; `opcodes/e2k-dis.c:104-113` (цикл `i = 0…5`, `hs & (1 << (26 + i))`) |
| «средняя точка» `mdl` = индекс последнего слога первой группы (число слов до неё минус один) | `gas/config/tc-e2k.c:9365-9366` — `hs->mdl = (crnt_syll - 1)` |
| ALES2/ALES5 занимают **целое слово**, старшая половина — первый из присутствующих | `elbrus-docs/README.md:156-159` |
| ALES{0,1,3,4} и AAS\* начинаются со слова, на которое указывает «средняя точка» | `elbrus-docs/README.md:163` |
| LTS\*, PLS\*, CDS\* разбираются **с конца** команды | `elbrus-docs/README.md:166`; `qemu/target/e2k/instr-bits.h:191-215` |
| остаток слов между серединой и концом отдаётся LTS | `elbrus-docs/README.md:168` |
| число слогов CDS и PLS пишется в HS (биты 17:16 и 19:18), а не флагами | `elbrus-docs/README.md:167` |

### 2.4.1. Слог управления в широкой команде (измерено 2026-09-27)

Слог управления (`CS1`, а не отдельная команда) встаёт **после** слогов ALS и **до** полуслогов
ALES0/1/3/4; в счёт «средней точки» он входит. Измерено `as-new -mcpu=elbrus-v5`
(`.tmp/osnova-wide-control-probe.ts`), разбор — `docs/hardware-debt.md` §3.33:

| текст МЦСТ | байты (hex) | HS: `lng` / `mdl` / `al` / `ale` / `cs` |
|---|---|---|
| `ldw,2 %db[14], %db[12], %db[10], mas=0x7` | `12 80 00 10 0a 0c 0e 66 00 c0 01 60 00 00 00 00` | 1 / 2 / 4 / 0 / 2 |
| `{ adds,0 …; ldw,2 … mas=0x7 }` | `13 80 00 14 03 02 01 10 0a 0c 0e 66 00 c0 01 60` | 1 / 3 / 5 / 0 / 2 |
| `{ muls,0 …; ldw,2 … mas=0x7 }` | `23 80 10 14 … 00 c0 01 60 00 00 c0 01 00 00 00 00` | 2 / 3 / 5 / **1** / 2 |

Последняя строка и есть проверка порядка: у `muls` полуслог ALES0 оказался **за** слогом управления,
а не перед ним. Признак присутствия — бит 15 (`c1`) поля `cs`; добивка до чётного числа слогов
считает и второй слог (третья строка — 6 слов, `lng = 2`). Наш кодировщик собирает эти байты
побайтово (`src/e2k/e2k-real.ts` — `wideCommandBytes`, паковка — `src/e2k/widePacker.ts`, оракул —
`src/e2k/e2kWideControl.test.ts`).

### 2.5. Выравнивание до чётного числа слогов

Ассемблер **добивает** команду до чётного числа 4-байтовых слогов:

```
/* Finally, given the total number of LTS*, PLS* and CDS*
   syllables we align on a double syllable boundary. */
if ((crnt_syll + lts_cntr + pls_cntr + cds_cntr) & 0x1)
    crnt_syll++;
```

`gas/config/tc-e2k.c:9488-9492`. Это и есть «выровнена на 8 байт» из README: команда с нечётным
числом слогов получает **пустое слово** (оно видно в байтах, §5).

### 2.6. Какие операции допускают несколько копий в одной команде

Номер канала — часть мнемоники (`adds,0`, `adds,1`, …). Допустимые каналы — поле шаблона
операции:

| утверждение | источник |
|---|---|
| `adds` разрешён во **всех шести** каналах: `{1, 1, 1, 1, 1, 1}` | `opcodes/e2k-opc.h:19-20` |
| `movts`/`movtd` — только в четырёх: `{1, 1, 0, 1, 1, 0}` (каналы 2 и 5 запрещены) | `opcodes/e2k-opc.h:644`, `:664`; `docs/e2k-address-loading.md` §2 |
| две операции в **один** канал — отказ ассемблера: «attempting to place several instructions into ALC%u» | `gas/config/tc-e2k.c:8667-8668` |
| декодер QEMU обходит **все** каналы: `for (ch = 0; ch < E2K_ALS_NUM; ch++)` по битам `HS.al` | `qemu/target/e2k/decoder.c:109-116` |
| то есть несколько ALS одной команды **исполняются** (не только разбираются) | вывод из `decoder.c:109-116` + `qemu/target/e2k/tcg/translate.c:264-267` (разбор всех слогов в одну `E2KDecodedInstr`) |

## 3. Как ассемблер собирает широкую команду

| утверждение | источник |
|---|---|
| широкую команду задают **фигурные скобки** `{ … }` | `gas/config/tc-e2k.c:10153-10164` (`if (c == '{') start_wide_command ()`) |
| `}` закрывает команду: `end_wide_command ()` | `gas/config/tc-e2k.c:10195-10199` |
| команда из **одной** инструкции может обойтись без скобок — тогда её закрывает начало следующей строки | `gas/config/tc-e2k.c:10147-10151` («A wide command consisting of just one instruction may very well do without curly brackets»), `:10203-10209` |
| пустая команда `{}` трактуется как `nop` | `gas/config/tc-e2k.c:10165-10169` |
| «средняя точка» ставится после HS, SS, ALS\*, CS0, CS1 | `gas/config/tc-e2k.c:9364-9366` |
| длина: `lng = (слогов / 2) - 1` | `gas/config/tc-e2k.c:9576-9577` |

## 4. Проверка ассемблером (замер)

`/root/build-gas/gas/as-new -mcpu=elbrus-v5`, дизассемблер `/root/build/binutils/objdump` (тот же
инструментарий, что в `docs/e2k-external-as.md` и `docs/e2k-address-loading.md`). Байты — из
`objcopy -O binary -j .text`. Проба: `.tmp/wide-probe.ts`, разбор — `.tmp/wide-dis.ts`.

### 4.1. Байты (измерено)

| # | ассемблерный текст | байт | байты (hex) |
|---|---|---|---|
| 1 | `adds,0 %b[1], %b[2], %b[3]` | 8 | `01 00 00 04 03 02 01 10` |
| 2 | без скобок, две строки `adds,0` и `adds,1` | 16 | `01 00 00 04 03 02 01 10 01 00 00 08 03 02 01 10` — **две команды** по 8 байт |
| 3 | `{ adds,0 … ; adds,1 … }` | 16 | `12 00 00 0c 03 02 01 10 03 02 01 10 00 00 00 00` — **одна команда** |
| 4 | `{ adds,0; adds,1; adds,2 }` | 16 | `13 00 00 1c 03 02 01 10 03 02 01 10 03 02 01 10` |
| 5 | `{ adds,0; adds,1; adds,2; adds,3 }` | 24 | `24 00 00 3c 03 02 01 10 03 02 01 10 03 02 01 10 03 02 01 10 00 00 00 00` |
| 6 | `{ adds,0; … adds,5 }` | 32 | `36 00 00 fc 03 02 01 10 03 02 01 10 03 02 01 10 03 02 01 10 03 02 01 10 03 02 01 10 00 00 00 00` |
| 7 | `{ adds,0; subs,1 }` | 16 | `12 00 00 0c 03 02 01 10 03 02 01 12 00 00 00 00` |
| 8 | `{ adds,0; adds,0 }` (один канал дважды) | — | **ОТКАЗ**: `Error: attempting to place several instructions into ALC0` |

### 4.2. Что видно в заголовочном слове

| случай | HS (hex) | `lng` = (HS>>4)&7 | `mdl` = HS&0xf | `al` = (HS>>26)&0x3f |
|---|---|---|---|---|
| одна `adds,0` | `01 00 00 04` | 0 → 8 байт | 1 | 1 (ALS0) |
| две `adds` в скобках | `12 00 00 0c` | 1 → 16 байт | 2 | 3 (ALS0+ALS1) |
| три `adds` | `13 00 00 1c` | 1 → 16 байт | 3 | 7 (ALS0…ALS2) |
| четыре `adds` | `24 00 00 3c` | 2 → 24 байта | 4 | 15 (ALS0…ALS3) |
| шесть `adds` | `36 00 00 fc` | 3 → 32 байта | 6 | 63 (ALS0…ALS5) |

Всё сходится с источником: `lng` = (слов / 2) − 1 (1 команда = 2 слова → 0; 3 слова → 1; 4 слова
→ 1; 5 слов → 2 после добивки до 6; 7 слов → 3 после добивки до 8), `mdl` = число слов до средней
точки − 1, `al` — биты присутствия.

**Цена в байтах (измерено):** 1 операция — 8 байт; 2 — 16; 3 — 16; 4 — 24; 6 — 32. То есть
**байты на операцию**: 8.0 / 8.0 / **5.33** / 6.0 / **5.33**. Выигрыш в байтах начинается с
**трёх** операций в команде; упаковка двух операций даёт не байты, а **одну команду вместо двух**
(одна команда — одно место выдачи, а не два).

### 4.3. Разбор дизассемблером МЦСТ

```
  100000: adds,0 %b[1], %b[2], %b[3]
  100010: adds,0 %b[1], %b[2], %b[3] adds,1 %b[1], %b[2], %b[3]
  100020: adds,0 %b[1], %b[2], %b[3] adds,1 %b[1], %b[2], %b[3] adds,2 %b[1], %b[2], %b[3]
  100030: adds,0 … adds,1 … adds,2 … adds,3 …
  100050: adds,0 … adds,1 … adds,2 … adds,3 … adds,4 … adds,5 …
```

Слоги **одной** команды печатаются **одной строкой** через пробел (ср. `docs/e2k-opcodes-real.md`
§5: формат печати слога — `opcodes/e2k-dis.c:1134`). Адрес строки — начало команды; следующая
строка начинается через её длину (`+8`, `+16`, `+24`, `+32` байт).

### 4.4. Чего замер НЕ доказывает

- что так поведёт себя **железо**: ассемблер и дизассемблер — инструменты МЦСТ, но не Эльбрус;
- что QEMU **исполнит** многослоговую команду: из источника следует только разбор всех слогов
  (`qemu/target/e2k/decoder.c:109-116`). Прогон поставлен и **пройден** — см. §5.1: обе операции
  одной команды исполнены, а зависимые операции в одной команде дают неверный результат;
- что две операции в одной команде **независимы**: зависимость — свойство программы, а не формы;
  ассемблер её не проверяет (в замере обе `adds` пишут в один регистр `%b[1]` — ассемблер собрал
  это без замечаний).

## 5. Что это даёт на DSP-задаче (измерено)

Группировщик — `src/e2k/widePacker.ts`; оракулы — `src/e2k/widePackets.test.ts` (раскладка и
внешняя сверка), `src/e2k/e2kWideQemu.test.ts` (исполнение в модели),
`src/e2k/e2kWideFir.test.ts` (замер по ядрам).

### 5.1. Исполняет ли QEMU широкую команду — да

| опыт | что сделано | результат |
|---|---|---|
| **различающий** | две независимые `adds` в одной команде; код возврата по очереди берёт **первая** и **вторая** операция | `exit` вернул **12** и **8** — исполнены **оба** слога. Одного опыта не хватило бы: он не отличил бы «исполнен первый слог» от «исполнены оба» |
| **эквивалентность** | тот же код линейно (команда на инструкцию) и пакетами | код возврата совпал: **12** |
| **негативный контроль (дефект 6.2)** | две **зависимые** операции насильно в одну команду (`encodeWideGroup` в обход проверки зависимостей) | код возврата **5** вместо **13**: модель читает источники **параллельно**, вторая операция видит старое значение. Это и есть обоснование правила «RAW внутри широкой команды недопустим» — замер, а не предположение |

### 5.2. Байты совпали с ассемблером МЦСТ

`src/e2k/widePackets.test.ts`: **6 наборов из 6** совпали с `as-new -mcpu=elbrus-v5` побайтово —
`add+add`, `add+add+add`, `add+sub`, `mul+mul` (полуслоги ALES делят слово), `mul+add`,
`mul+mul+add`. Кодировщик широкой команды выдаёт **то же**, что ассемблер.

### 5.3. Замер по пяти ядрам (измерено, зафиксировано оракулом `e2kWideFir.test.ts`)

| ядро | носителей IR | понижено команд | команд линейно | пакетов | байт линейно | байт пакетами |
|---|---|---|---|---|---|---|
| fir | 111 | 87 | 87 | **67** | 864 | **824** (−4.6%) |
| iir | 91 | 70 | 70 | **53** | 688 | **648** (−5.8%) |
| fft | 105 | 79 | 79 | **49** | 744 | **672** (−9.7%) |
| convolution | 110 | 94 | 94 | **72** | 888 | **848** (−4.5%) |
| correlation | 100 | 82 | 82 | **62** | 776 | **736** (−5.2%) |

Материал группировки — в основном **пересылки**: в понижённом потоке FIR `movts` — 64 команды, а
всей арифметики (`adds` 5, `subs` 2, `muls` 1) — **8 из 87**. Арифметика не упаковывается
пачками, потому что стоит в цепочках зависимостей (операнды `muls` заполняются `movts`
непосредственно перед ним), а литеральные `movts` — вообще барьеры: у них слог LTS, а не ALS.

### 5.4. Почему полного прогона FIR в QEMU нет — точная причина

Из 111 носителей IR ядра FIR **24 не понижаются**: `IR.invoke`, `IR.ret`, `IR.call`. Это не
мелочь: `IR.invoke` — обращения к массивам (память), `IR.call`/`IR.ret` — вызовы, и весь счёт
ядра идёт через них. Кодировщик e2k умеет слог ALS, литералы и передачу управления;
**обращений к памяти и процедур в нём нет**, поэтому:

- собрать «FIR целиком» в байты **нечем**: 24 носителя не имеют формы e2k у нас;
- прогон «FIR = 181» требует памяти (загрузка отсчётов), цикла и вызова — работы, которой в этом
  сеансе не делалось;
- замер §5.3 сделан на **понижённой части** потока: 87 команд из 111 носителей.

### 5.5. Ответ на вопрос сеанса

**Гипотеза «VLIW-группировка, соединённая с реальной кодировкой e2k, даёт измеримый выигрыш на
DSP-задаче» подтверждена ЧАСТИЧНО, и граница названа.**

Что подтверждено замером:

- форма широкой команды **найдена** (§1–§4); кодировщик широкой команды совпал с ассемблером МЦСТ
  **побайтово, 6 наборов из 6**;
- **исполнение** широкой команды в модели **подтверждено различающим опытом**: обе операции одной
  команды исполнены, а зависимые операции в одной команде дают неверный результат — правило
  группировки обосновано замером, а не предположением;
- на понижённых потоках пяти ядер группировка даёт **команд на 23–38% меньше** (87→67, 105→49) и
  **байтов на 4.5–9.7% меньше**.

Чего не хватает для полного ответа: **на самой DSP-задаче выигрыш не измерен**. Причина точная:
ядро FIR целиком не собирается нашим кодировщиком — 24 носителя из 111 (память и вызовы) без
формы e2k. То есть **не «форма не найдена» и не «группировка не работает», а считать в e2k пока
нечем**: нет обращений к памяти и вызовов.

Следующий шаг (в порядке важности): `ld`/`st` (память), затем `call`/`ret`, затем прогон ядра
целиком и сравнение с эталоном 181.
