# Внешняя валидация кодировки e2k через онлайн-сервисы

**Дата:** 2026-09-15 (вечер)
**Зачем:** кодировка e2k извлечена из четырёх открытых описаний и проверена round-trip
(`docs/e2k-real-run.md`), но **внешней** проверки нет: ни MCST-objdump, ни QEMU в этом окружении
не собраны — нет компилятора C (`docs/e2k-qemu-build.md` §2). Здесь собраны попытки получить
внешнюю проверку **онлайн**, без установки Linux, QEMU и binutils.

**Правило этого документа:** каждое утверждение — с датой, адресом и полученным ответом.
Отрицательный результат — тоже результат, и он записывается так же подробно, как положительный.

---

## 1. Compiler Explorer (godbolt.org)

**Проверено:** 2026-09-15, HTTP-запросами из этого окружения (Node `fetch`).

| что запрошено | ответ |
|---|---|
| `https://godbolt.org` (HEAD) | **200** — сервис доступен |
| `https://godbolt.org/api/compilers` (Accept: application/json) | **200**, `application/json` — **6 277 компиляторов**, **93 языка** |
| `https://godbolt.org/api/languages` | **200** — **97 языков** (некоторые языки без компиляторов) |
| `https://godbolt.org/api/compilers/e2k` | **200** и тело `[]` |
| `https://godbolt.org/api/compilers/elbrus` | **200** и тело `[]` |
| `https://godbolt.org/api/compilers/e2k-gcc` | **200** и тело `[]` |
| `https://godbolt.org/api/compilers/lcc` | **200** и тело `[]` |
| `https://godbolt.org/api/compilers/assembly` | **200** — **158 ассемблеров** (AArch64, ARM, x86, …); среди них e2k нет |

**Отдельная проверка по форме «ассемблер».** Если компилятора e2k нет, ассемблер e2k всё равно
дал бы внешнюю проверку: он собирал бы инструкцию в байты, и наши байты можно было бы сверить с
его выводом. Список из 158 ассемблеров проверен тем же поиском — **ни одного e2k**.

**Поиск по формам** (метаправило проекта: искать по всем формам, которыми предмет может быть
назван) — по полям `id`, `name`, `compilerType`, `instructionSet` всех 6 277 записей:

| форма поиска | найдено |
|---|---|
| `e2k` | 0 |
| `elbrus` / `эльбрус` | 0 |
| `mcst` | 0 |
| `vliw` | 0 |

**Наборы инструкций, которые сервис знает** (перечень целиком, для сопоставления):
`amd64 6502 aarch64 llvm arm32 avr ebpf python ptx beam hppa hook kvx loongarch m68k mips
mrisc32 msp430 mpy wdc65c816 powerpc perl riscv32 riscv64 s390x sparc c6x vax wasm32 xtensa
spirv java dex ez80 sh evm x86 z180 z80 eravm`. **e2k в этом перечне нет.**

### 1.1. Найденная ловушка: код ответа не является критерием

`/api/compilers/e2k` отвечает **200**, а не 404: тело — пустой массив. Проверка «сервис ответил
200 на запрос компилятора e2k, значит компилятор есть» дала бы **ложное «найден»**. Критерий —
только поиск по полному списку компиляторов. Это записано здесь потому, что ловушка
воспроизводима и её легко принять за успех.

### 1.2. Результат

> **НЕТ КОМПИЛЯТОРА e2k НА COMPILER EXPLORER**

Ни одного компилятора под e2k/Эльбрус сервис не предоставляет (проверено 2026-09-15).
Следствие: **внешняя валидация кодировки через онлайн-компилятор невозможна** — компилировать
нечем.

## 2. Что сделано вместо проверки (и что проверено на самом деле)

### 2.1. Конвейер запроса к Compiler Explorer проверен — на доступном компиляторе

Чтобы «нет компилятора e2k» не превратилось в «неизвестно, сработал ли бы запрос вообще»,
конвейер отправки исходника проверен на **доступном** компиляторе:

| шаг | результат |
|---|---|
| выбран компилятор C с архитектурой `amd64` из `/api/compilers/c` | `caocc320` (x86-64 AOCC 3.2.0) |
| `POST /api/compiler/caocc320/compile` с `int f(int a,int b){return a+b;}` и `-O2` | **200**, `code: 0`, **164 строки** ассемблера |
| отдельно проверено, что сервис честно сообщает об ошибке компилятора | `cc65_217` + `-O2` → `code: 1`, `stderr: "cc65: Unknown option: -O2"` |

**Что это доказывает:** клиент (`src/scripts/compilerExplorer.ts`) разговаривает с сервисом и
разбирает ответ. **Чего это не доказывает:** ничего про e2k — компилятора e2k нет, и запрос к
нему не отправлялся.

### 2.2. План проверки (записан, но не выполнен)

Если компилятор e2k появится, порядок такой: (3.1) отправить ассемблерную форму образца
(`adds,0 %r1, %r2, %r3`) как исходник; (3.2) если сервис принимает только C/C++ — собрать
минимальную функцию с той же операцией при `-O2` и найти в выводе соответствующую инструкцию;
(3.3) сравнить её код операции с нашим. **Ни один из шагов не выполнен** — компилятора нет,
а проверять нечем.

## 3. Альтернативные онлайн-сервисы

Проверено 2026-09-15 теми же HTTP-запросами из этого окружения. Искались сервисы, которые
принимают **байты** (дизассемблер) или **ассемблерный текст** (ассемблер) и поддерживают e2k.

| сервис | что это | ответ 2026-09-15 | e2k |
|---|---|---|---|
| `godbolt.org` (Compiler Explorer) | онлайн-компилятор и ассемблер | **200**: 6 277 компиляторов, 158 ассемблеров | **нет** (§1) |
| `onlinedisassembler.com` (ODA) | онлайн-дизассемблер на LLVM MC | **502** — сервис отвечает ошибкой | нет; и в upstream LLVM цели e2k нет (e2k — отдельный форк) |
| `disasm.pro` | онлайн-дизассемблер (x86, ARM, MIPS…) | **недоступен**: таймаут 45 с | — |
| `dogbolt.org` | декомпилятор-эксплорер (gcc, clang, Ghidra…) | **200**, упоминаний e2k в разметке нет | нет |
| `retdec.com` | проект RetDec (публичный онлайн-сервис закрыт) | **200** — это страница проекта, не сервис | нет |
| `wandbox.org` | онлайн-компилятор | **200**, e2k нет | нет |

Поиск сервисов по формам («online disassembler Elbrus e2k», «онлайн дизассемблер Эльбрус»,
«compiler explorer Elbrus e2k») дал только страницы про сами компьютеры «Эльбрус» и их
программное обеспечение — **ни одного сервиса с поддержкой e2k**.

### 3.1. Ручная сверка по документации МЦСТ — проверена, не помогает

Документ МЦСТ в репозитории есть (`docs/elbrus-prog-1.2_2024-02-28.pdf`), и он проверен
**целенаправленно**: 208 страниц, 350 272 символа извлечённого текста, поиск по формам.

| форма поиска | вхождений | что это на самом деле |
|---|---|---|
| `формат команды` | **0** | — |
| `опкод`, `opcode` | **0** | — |
| `слог ALS` | **0** | — |
| `код операции` | 2 | стр. 154–155: про **подготовку перехода** (`disp`, `return`), а не про поле команды |
| `битовое поле` | 4 | стр. 30, 141, 143: битовые поля **языка C**, а не кодировки |
| `ALES` | 6 | ложные срабатывания внутри `FSCALEs`, `PFMULs` |

**Вывод:** битовой раскладки команды руководство не содержит — совпадает с прежним извлечением
(`docs/e2k-encoding-raw.md` §1.7). Ручная сверка по этому документу кодировку не подтверждает.

### 3.2. Результат

> **ОНЛАЙН-ДИЗАССЕМБЛЕР ДЛЯ e2k НЕ НАЙДЕН**

Ни один из проверенных онлайн-сервисов не поддерживает e2k/Эльбрус (проверено 2026-09-15).

## 4. Внешняя проверка ПОЛУЧЕНА: наши байты через MCST-objdump

**Результат: 10 образцов из 10 совпали с дизассемблером МЦСТ** (проверено 2026-09-15).
Это первая **внешняя** проверка кодировки: байты читает чужой код, написанный МЦСТ, а не наша
реализация.

### 4.1. Как получен дизассемблер (путь, который сработал)

| шаг | что сделано | что выяснилось |
|---|---|---|
| WSL | `wsl --version` из `C:\Program Files\WSL\wsl.exe` | **WSL 2.6.3.0 уже установлен** пакетом `MicrosoftCorporationII.WindowsSubsystemForLinux` (2.6.3.0, состояние Ok), служба `WslService` работает; заглушка `System32\wsl.exe` про установленный дистрибутив не знает |
| обновление 2.7.14 | скачивание `Microsoft.WSL_2.7.14.0_x64_ARM64.msixbundle` (495 МБ) | **не понадобилось и не удалось**: обрыв `ECONNRESET`. Установленная 2.6.3 работает |
| дистрибутив | `wsl --install -d Ubuntu --no-launch` | **не удалось**: `Wsl/InstallDistro/0x80072efe` (обрыв соединения при скачивании) |
| дистрибутив (обход) | скачан `alpine-minirootfs-3.24.1-x86_64.tar.gz` (3 698 422 байта) и выполнен `wsl --import e2k D:\wsl\e2k … --version 2` | **`--version 2` не удался**: `Wsl/Service/RegisterDistro/CreateVm/HCS/ERROR_INVALID_DATA` — создание виртуальной машины на этом хосте не проходит |
| дистрибутив (рабочий путь) | тот же образ, `--version 1` | **получилось**: WSL1, `Linux … 4.4.0-22543-Microsoft`, Alpine 3.24.1. Прав администратора **не потребовалось ни на одном шаге** |
| инструменты | `apk add build-base texinfo bison flex zlib-dev bash git` | gcc 15.2.0, GNU Make 4.4.1 |
| сборка | `./configure --target=e2k-linux --disable-nls --disable-werror --disable-{gdb,sim,gas,ld,gold,gprof,readline,libdecnumber,libquadmath,libctf}` + `make all-binutils` | **собралось**: `binutils/objdump`, `GNU objdump (GNU Binutils) 2.41.0-29.023` |

**Две помехи, которые пришлось снять (обе записаны, обе воспроизводимы):**

1. **CRLF в клоне на Windows** (`core.autocrlf=true`): сборочные скрипты падают на `sh`
   («: not found», «syntax error: unexpected newline»). Снято пересборкой рабочего дерева
   средствами git внутри дистрибутива: `core.autocrlf=false` → `git rm --cached -r .` →
   `git reset --hard` (LF берётся из объектов, сеть не нужна).
2. **Отсутствующий `libsframe`** в выборочном клоне: `bfd` требует `../libsframe/libsframe.la`
   («No rule to make target»). Снято добавлением каталогов `libsframe` и `libctf` в
   sparse-checkout.

### 4.2. Что подано на вход

Образцы (`src/scripts/extractE2kSamples.ts`) упакованы в ELF64 скриптом
`src/scripts/e2kExternalObjdump.ts`: секция `.text` — образцы подряд с выравниванием до 16 байт,
`e_machine = 175` (`EM_E2K` = `EM_MCST_ELBRUS`), `e_flags` = `bfd_mach_e2k_8c << 24`
(из него дизассемблер берёт уровень ISA — `opcodes/e2k-dis.c:2632`, для 19 это 4, при котором
распознаются маски наборов 0xff, 0xfc, 0xfe).

### 4.4. Находки внешней проверки

| находка | что это значит |
|---|---|
| дизассемблер печатает **`%b[N]`** (`movts`, `adds`, …) и **`%db[N]`** (`movtd`, `smulhd`), а наши образцы записаны как `%rN` | 8-битное поле слота дизассемблер относит к **базовым** регистрам (`opcodes/e2k-dis.c:417`, `:454`), а не к рабочим. Номера совпадают; вопрос — в имени файла регистров, и он **не решён**: наши образцы и документация называют поле `%rN`. Это записано как находка, а не как «совпало всё» |
| набор `nop` на адресах-заполнителях (`100008`, `100018`, …) | наше выравнивание образцов до 16 байт читается как отдельные команды `nop` — ожидаемо и ничего не ломает |
| строка дизассемблера печатается **без байтов**, текст инструкции — **следующей строкой** | формат вывода e2k-objdump не совпадает с обычным; разбор в `src/scripts/e2kExternalObjdump.ts` учитывает это (и это измеренный факт, а не догадка) |

### 4.5. Чего внешняя проверка НЕ доказывает

| утверждение | почему не доказано |
|---|---|
| код исполнится на e2k | дизассемблер и исполнение — разные вещи; эмулятора нет, железа нет |
| проверены все реализованные операции | образцов десять из 23 операций и трёх форм |
| приёмка **ассемблера** (наши байты — то, что выдал бы MCST-ассемблер из той же инструкции) | это обратная задача: мы подали байты, а не собрали текст. Для полной сверки нужен `e2k-linux-as`, а `gas` в сборке отключён |

Воспроизведение: `npx tsx src/scripts/e2kExternalObjdump.ts` (отчёт —
`.tmp/e2k-external-objdump.json`; путь к своему дизассемблеру — `E2K_OBJDUMP=…`).

| **собрать QEMU-e2k на Linux** | не выполнен | то же; QEMU дал бы приёмку байтов эмулятором |
| **поднять свой Compiler Explorer с компилятором e2k** | невозможен сейчас | сервис открыт (github.com/compiler-explorer) и допускает добавление компилятора, но **нужен сам бинарь** (e2k-gcc или lcc для e2k) — его у проекта нет |
| **ручная сверка по документации МЦСТ** | проверен, **не помогает** | в PDF нет битовой раскладки (§3.1) |
| **онлайн-дизассемблер** | проверены шесть сервисов, **не найдено** (§3) | сервиса с поддержкой e2k не существует (на 2026-09-15) |
| **железо «Эльбрус»** | недоступно | доступ к машине |
| **письмо в МЦСТ** | отложено владельцем | — |
| **согласие четырёх независимых описаний** | уже есть | это **не** измерение: `docs/e2k-sources-raw.md` §3 |

**Порядок предпочтения:** сборка binutils на Linux (даёт MCST-дизассемблер) → сборка QEMU
(даёт эмулятор) → свой инстанс Compiler Explorer с бинарём компилятора e2k. Всё остальное либо
уже проверено и не помогает, либо недоступно.
