# План эволюции языка Основа

## Общие принципы

1. Семантическая обратная совместимость — старый код остаётся рабочим.
2. Добавление, а не передел — новые конструкции не отменяют существующие.
3. Приоритет LLM-читаемости — изменения понятны и воспроизводимы моделями.
4. Маленькие шаги — версии 1.x с короткими циклами.

## Цикл релиза версии

Каждая версия проходит обязательный цикл:

```
реализовать фичу
       ↓
добавить в промпты и реестр
       ↓
прогнать 50+ целевых задач (сценарии с новой конструкцией)
       ↓
накопить трейсы в датасете
       ↓
файн-тюн / валидация golden-тестов
       ↓
следующая версия
```

### Гейт для перехода к следующей версии

Версия считается готовой только при выполнении всех условий:
- фича реализована и задокументирована
- промпты и реестр обновлены
- накоплено 50+ успешных трейсов с новой конструкцией
- golden-тесты покрывают новые сценарии

## Версии

### v1.1 — Удобство без взрывных изменений

Фокус: снизить трение, не трогая ядро.

| Фича | Мотивация |
|------|-----------|
| массив[индекс] как сахар над система.массив.получить | Естественный синтаксис |
| Многострочные литералы [...] и {...} | Упростить сложные структуры |
| Опциональный тогда в если | если х > 0 тогда — лучше читаемость |
| Аргументы главная(аргументы) | Передача параметров из CLI при запуске |

### v1.2 — Обработка ошибок

Фокус: базовый механизм ошибок без усложнения типов.

| Фича | Мотивация |
|------|-----------|
| попробовать / иначе_попытка / выбросить | Простой try/catch-подобный синтаксис |
| Результат<T,E> — Успех/Неудача | Явная обработка успеха/ошибки |
| система.файлы.прочитать_безопасно → Результат | Возврат результата вместо падения |

Минимум датасета: 50+ задач на «файлы/сеть + обработка ошибок».

### v1.3 — Модульность

Фокус: разбиение больших программ.

| Фича | Мотивация |
|------|-----------|
| использовать модуль Имя из "путь" | Подключение других модулей |
| процедура экспорт имя(...) | Выделение публичного API модуля |

#### Контракт модульности v1.3

- **Модуль = файл**: один файл .osnova — один модуль, всегда.
- **Импорт только между файлами**: использовать всегда ссылается на другой файл.
- **Никаких вложенных модулей**: логические единицы внутри файла не вводятся.
- **Один namespace на модуль**: имена процедур не конфликтуют между файлами.

Минимум датасета: 50+ задач на многомодульные приложения.

### v1.4 — Типы

Фокус: типизация без сложных generics.

| Фича | Мотивация |
|------|-----------|
| тип Человек { имя: Строка, возраст: Целое32 } | Пользовательские структуры |
| Явные аннотации: пусть имя: Строка = ... | Для анализа и подсказок LLM |
| Опциональные типы ?Строка | Nullable без полноценного Option |

Минимум датасета: 50+ задач с пользовательскими типами.

### v2.0 — Новый уровень

Фокус: выразительные конструкции после стабилизации 1.x.

| Фича | Мотивация |
|------|-----------|
| совпадает / когда | Pattern matching вместо длинных если/иначе_если |
| Процедуры высшего порядка | пусть колбэк = процедура(х) ... конец |
| для_каждого по произвольным коллекциям | Не только массивы |
| Расширенный Результат | вскрыть, отобразить, цепочки обработки |

Требование: стабилизация всех версий 1.x и обновлённый датасет.

## Что не спешить делать

- **VLIW-конструкции** — до появления реального VLIW-бэкенда.
- **Полноценные generics** — начать с конкретных типов структур.
- **Async/await** — пока достаточно синхронной модели.
- **Макросы** — сначала развить базовую выразительность.

## Согласование с платформой

- **v1.1–v1.2**: без изменений OsVbcModule, только новые опкоды при необходимости.
- **v1.3**: при мультимодульности — либо один объединённый модуль,
  либо расширение формата с механизмом загрузки.
- **v1.4+**: метаданные типов в байткоде; без влияния на VM,
  если не потребуется JIT/AOT.
