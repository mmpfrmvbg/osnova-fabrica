# Манифест приложения ОСи (v0.1)

Базовый скелет: **манифест приложения + модуль Основа**. Лаунчер ОСи читает манифесты, строит каталог и запускает рантайм Основа по точке входа.

---

## 1. Формат манифеста приложения (YAML)

Файл манифеста: `*.osapp.yaml` (например, `notepad.osapp.yaml`). Лаунчер сканирует каталог приложений и обрабатывает все такие файлы.

```yaml
id: "notepad.osn"          # уникальный id в каталоге ОСи
name: "Блокнот ОСи"        # человекочитаемое имя
version: "0.1.0"

entry:
  module: "блокнот"        # имя модуля Основа
  procedure: "запуск"      # точка входа (процедура или задача)
  args: []                 # опциональные аргументы

category: "utility"        # crm | todo | game | utility | system | other

ui:
  kind: "window"           # window | tray | cli | service
  icon: "icons/notepad.png"
  single_instance: true

permissions:
  files:
    read: ["~/Документы"]
    write: ["~/Документы/ОСь"]
  network:
    outbound: false
  system:
    clipboard: true

runtime:
  min_osnova_version: "0.1.0"
  min_os_version: "0.1.0"  # минимальная версия ОСи
```

### Поля манифеста

| Поле | Обязательно | Описание |
|------|-------------|----------|
| `id` | да | Уникальный идентификатор в каталоге ОСи (например, `notepad.osn`). |
| `name` | да | Человекочитаемое имя приложения. |
| `version` | да | Семантическая версия (например, `0.1.0`). |
| `entry.module` | да | Имя модуля Основа (совпадает с `модуль <имя>;` в коде). |
| `entry.procedure` | да | Имя процедуры или задачи — точка входа (`запуск`, `main` и т.п.). |
| `entry.args` | нет | Список аргументов по умолчанию (если поддерживается рантаймом). |
| `category` | нет | Категория приложения: `crm`, `todo`, `game`, `utility`, `system`, `other`. |
| `ui.kind` | нет | Тип интерфейса: `window`, `tray`, `cli`, `service`. |
| `ui.icon` | нет | Путь к иконке относительно корня пакета приложения. |
| `ui.single_instance` | нет | Разрешать только один экземпляр приложения. |
| `permissions` | нет | Права доступа к файлам, сети, буферу обмена и т.д. |
| `runtime.min_osnova_version` | нет | Минимальная версия рантайма Основа. |
| `runtime.min_os_version` | нет | Минимальная версия ОСи. |

---

## 2. Требования к модулю Основа

В коде приложения должен быть модуль с именем, указанным в `entry.module`, и процедура (или задача) с именем из `entry.procedure`.

Пример для «Блокнот ОСи»:

```основа
модуль блокнот;

использовать система.окно;
использовать система.файлы;

процедура запуск() {
    // инициализация окна, цикл обработки событий и т.п.
}
```

Лаунчер ОСи:

- читает все `*.osapp.yaml` в каталоге приложений;
- строит по ним меню/иконки;
- по клику пользователя запускает рантайм Основа с параметрами: пакет приложения, `entry.module`, `entry.procedure`, при необходимости `entry.args`.

---

## 3. Системное приложение (служба / демон без UI)

Для служб и демонов достаточно того же манифеста с отличиями в `ui` и `entry`:

```yaml
id: "logger.osn"
name: "Служба журналирования"
version: "0.1.0"

entry:
  module: "журнал"
  procedure: "запуск"   # или задача с бесконечным циклом
  args: []

category: "system"

ui:
  kind: "service"      # без окна, запуск в фоне
  # icon не нужен

permissions:
  files:
    write: ["/var/os/log"]
  network:
    outbound: false

runtime:
  min_osnova_version: "0.1.0"
  min_os_version: "0.1.0"
```

В коде Основа — тот же контракт: модуль `журнал`, процедура (или задача) `запуск`. Рантайм при `ui.kind: "service"` не создаёт окно и может управляться лаунчером/ОСью как служба (старт при загрузке, остановка, перезапуск).

**Итог:** отдельный «скелет манифеста системного приложения» не обязателен — достаточно пользовательского манифеста с полем `ui.kind: "service"` и категорией `system`. Этого хватает для служб и демонов без UI.

## 4. Связь с пакетом приложения (`.osvpk`)

Манифест приложения ОСи (`*.osapp.yaml`) может:

- лежать **внутри** пакета `.osvpk` (в корне или в подкаталоге), тогда лаунчер извлекает его при установке;
- либо храниться **отдельно** в каталоге приложений ОСи, а в манифесте указывать путь к пакету (если лаунчер это поддерживает).

Формат пакета `.osvpk` и поля `manifest.json` внутри него описаны в `launcher-runtime-manifest.md`. Поля `entry`, `permissions`, `runtime` в `*.osapp.yaml` могут дублировать или расширять манифест пакета — точное соглашение о приоритете (osapp vs manifest.json) задаётся лаунчером ОСи.

---

## 5. Протокол лаунчер ↔ рантайм OS‑nova

Лаунчер ОСи запускает процесс рантайма Основа и передаёт ему данные из манифеста через **аргументы CLI** и (опционально) **файл конфигурации** или **переменные окружения**. Рантайм по ним загружает пакет, настраивает песочницу и вызывает точку входа.

### 5.1. Вызов рантайма (CLI)

Лаунчер выполняет команду вида:

```text
osnova-runtime run [ОПЦИИ] --manifest <путь к .osapp.yaml>
```

или, если рантайм умеет работать без отдельного манифеста (всё из пакета):

```text
osnova-runtime run --package <путь к .osvpk или каталогу приложения>
```

Рекомендуемый вариант: **всегда передавать путь к манифесту** (или к каталогу, где лежит манифест и код), чтобы рантайм один раз прочитал YAML и получил все поля.

### 5.2. Аргументы CLI и маппинг полей манифеста

Ниже — минимальный набор аргументов и способ передачи остальных данных.

| Назначение | Способ передачи | Источник в манифесте |
|------------|-----------------|----------------------|
| Какой пакет/каталог грузить | `--package <path>` или `--app-dir <path>` | Лаунчер знает путь к установленному приложению (каталог с манифестом и кодом или распакованный `.osvpk`). |
| Манифест (если не внутри пакета) | `--manifest <path>` | Путь к `*.osapp.yaml`. |
| Модуль точки входа | `--module <имя>` | `entry.module` |
| Процедура/задача точки входа | `--procedure <имя>` | `entry.procedure` |
| Аргументы вызова точки входа | `--args <json-массив>` или `--args "a,b,c"` | `entry.args` |
| Режим UI (окно / сервис / cli) | `--ui <kind>` или из манифеста | `ui.kind` |
| Один экземпляр | `--single-instance` | `ui.single_instance` (лаунчер может сам проверять и не запускать второй процесс). |

Пример полной команды:

```text
osnova-runtime run \
  --manifest "/data/os-apps/notepad.osapp.yaml" \
  --package "/data/os-apps/notepad.osn" \
  --module блокнот \
  --procedure запуск \
  --ui window
```

Если рантайм принимает **только путь к манифесту**, то `entry.module`, `entry.procedure`, `entry.args`, `ui.kind` и т.д. он читает сам из YAML; тогда лаунчер может вызывать просто:

```text
osnova-runtime run --manifest "/data/os-apps/notepad.osapp.yaml"
```

и в манифесте должен быть указан путь к пакету/каталогу (например, поле `package_path` или каталог манифеста считается корнем приложения).

### 5.3. Права доступа и окружение

Поля `permissions` (файлы, сеть, буфер обмена) не передаются как CLI-аргументы по одному, а либо:

- **Вариант A:** рантайм читает манифест сам (по `--manifest`) и применяет `permissions` при создании песочницы;
- **Вариант B:** лаунчер формирует **вспомогательный конфиг** (JSON/YAML) с уже разрешёнными путями и флагами и передаёт его, например:
  - `--config <path>` — путь к файлу с разрешениями и настройками;
  - или переменные окружения, например `OSNOVA_APP_PERMISSIONS=/path/to/permissions.json`.

Рекомендация: рантайм читает манифест по `--manifest` и сам маппит `permissions` в свою модель доступа (список разрешённых путей на чтение/запись, флаги сети и clipboard).

### 5.4. Что делает рантайм после старта

1. Разбирает аргументы (и при необходимости читает манифест по `--manifest`).
2. Проверяет `runtime.min_osnova_version` и при несовместимости выходит с ошибкой.
3. Загружает пакет приложения (байткод/модули из каталога или `.osvpk`).
4. Настраивает песочницу по `permissions`.
5. Вызывает точку входа: модуль `entry.module`, процедура или задача `entry.procedure`, с аргументами `entry.args` (если рантайм поддерживает передачу аргументов в точку входа).
6. Для `ui.kind: "window"` создаёт окно и передаёт управление в код приложения; для `service` — работает в фоне без окна.

### 5.5. Итоговая схема маппинга

| Поле манифеста | Куда попадает |
|----------------|---------------|
| `id` | Логирование, идентификация процесса; опционально в `--app-id`. |
| `entry.module` | CLI `--module` или чтение из манифеста. |
| `entry.procedure` | CLI `--procedure` или чтение из манифеста. |
| `entry.args` | CLI `--args` (сериализованный список) или из манифеста; рантайм передаёт их в вызов точки входа. |
| `ui.kind` | CLI `--ui` или из манифеста; определяет режим (окно / service / cli). |
| `ui.single_instance` | Обрабатывается лаунчером (не запускать второй процесс) или флаг `--single-instance` для рантайма. |
| `permissions` | Чтение рантаймом из манифеста (или из конфига по пути из CLI); применение при создании песочницы. |
| `runtime.min_osnova_version` | Проверка в рантайме при старте. |
| Путь к пакету/каталогу | `--package` / `--app-dir` или неявно: каталог, в котором лежит манифест. |

### 5.6. Минимальная реализация CLI

Минимальный CLI, реализующий эти шаги, находится в репозитории:

- `src/tools/osnova-runtime/cli.ts` — точка входа (`osnova-runtime run`);
- `src/tools/osnova-runtime/run.ts` — разбор аргументов, загрузка манифеста, проверка версии, загрузка пакета, применение permissions, вызов точки входа (пока без VM — только логирование).

Запуск (без сборки):

```bash
npx tsx src/tools/osnova-runtime/cli.ts run --manifest path/to/app.osapp.yaml
```

После сборки проекта:

```bash
npm run build
node dist/tools/osnova-runtime/cli.js run --manifest path/to/app.osapp.yaml
```

Или через скрипт: `npm run osnova-runtime:dev run -- --manifest path/to/app.osapp.yaml`.
