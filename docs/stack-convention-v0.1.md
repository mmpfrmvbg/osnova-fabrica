# Конвенция стека и аргументов VM Основа v0.1

Формальное описание порядка операндов на стеке для бинарных операций и для вызовов `invoke`/`call`. Все генераторы байткода и хендлеры invoke должны следовать этой конвенции.

---

## 1. Бинарные арифметические и сравнения

**Правило:** аргументы пушатся в порядке «первый операнд, второй операнд» (сверху стека — второй). Результат операции — «первый ∘ второй».

- Код: `push a; push b; op`
- Стек перед op: `[a, b]` (b на вершине)
- Интерпретатор: `b = pop(); a = pop(); push(a ∘ b)`

Таким образом:
- `sub`: `a - b`
- `div` / `rem`: `a / b`, `a % b` (делитель — второй)
- `lt`, `le`, `gt`, `ge`: `a < b`, `a <= b`, `a > b`, `a >= b`

Для `add` и `mul` порядок не меняет результат, но для единообразия используется тот же шаблон.

---

## 2. Invoke (системные вызовы)

**Правило:** аргументы пушатся в **порядке вызова**: первый параметр функции — первым на стек (ниже по стеку), последний — на вершине.

- Код: `push arg1; push arg2; ...; invoke "name"`
- Стек перед invoke: `[arg1, arg2, ...]` (последний аргумент на вершине)
- Интерпретатор: `for (i = 0; i < argc; i++) args.unshift(stack.pop())`  
  В результате `args[0] = arg1`, `args[1] = arg2`, …

Хендлеры в vm-runner получают `args` в естественном порядке: `args[0]` — первый параметр, `args[1]` — второй и т.д.

### 2.1. Таблица invoke (порядок параметров)

| Invoke | args[0] | args[1] | args[2] | Примечание |
|--------|---------|---------|---------|------------|
| `система.хранилище.записать` | key | value | — | |
| `система.хранилище.прочитать` | key | — | — | |
| `система.массив.получить` | array | index | — | arr[index] |
| `система.массив.длина` | array | — | — | |
| `система.объект.получить` | obj | key | — | obj[key] |
| `система.строка.объединить` | a | b | — | a + b |
| `система.окно.получить_события` | *(нет аргументов)* | — | — | argc = 0 |
| `система.интерфейс.установить_значение` | widgetId | value | — | |
| `система.файлы.записать_все` | path | data | — | |
| … | | | | |

### 2.2. inferInvokeArgCount

Число аргументов для каждого invoke должно точно совпадать с сигнатурой. Если argc завышен — со стека снимаются лишние значения (портятся данные). Если занижен — хендлер получает неполные args, а на стеке остаётся мусор. Для invoke без аргументов (например, `получить_события`) обязательно указывать 0.

---

## 3. Call (вызов процедуры)

Аналогично invoke: аргументы пушатся в порядке вызова (первый параметр — первым). Интерпретатор снимает `proc.argc` значений через `unshift(pop)` и передаёт в кадр процедуры как `locals[0], locals[1], ...`.

---

## 4. Рекомендации для тестов

- **Табличные тесты опкодов:** для каждой бинарной операции и для invoke задавать «входной стек → инструкция → ожидаемый стек (или ошибка)».
- **Тесты invoke:** проверять, что после вызова с заданным стеком хендлер получает правильные `args[i]` и результат на стеке корректен.
- **inferInvokeArgCount:** вынести таблицу argc в один источник (или тест), чтобы при добавлении нового invoke не забыть обновить argc.
