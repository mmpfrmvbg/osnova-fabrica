# Карта конвейера: файл → что делает → чего не делает

**Сеанс:** анализ + мозговой штурм, 2026-09-19. **Не реализация.**
**Назначение:** база для `01-opportunities.md` … `04-first-experiment.md`. Каждое утверждение —
ссылка `файл:строка` на реальный код. Где источника нет — помечено **ГИПОТЕЗА**.

**Что читать первым.** В проекте **два разных конвейера**, и их нельзя смешивать:

| конвейер | вход | выход | кто ведёт |
|---|---|---|---|
| **A. Оболочка** (`osnova-shell-image`) | `RegModule` | 10-байтовые носители `IR.*` | `src/e2k/emitterShell.ts:350` |
| **B. Реальный e2k** | тот же `RegModule` | байты e2k (8/16 байт) + ELF | `src/e2k/e2kRealRun.ts:729` |

Конвейер A даёт **носители нашего IR** и настоящий расчёт тактов (`nopCycles`, `issueAt`) — но
носители не e2k. Конвейер B даёт **настоящие байты e2k** — но без тактов и без каналов.
**Ни один из двух не соединяет «такты» с «байтами»** — это главный факт карты.

## 0. Сквозная схема (обе ветви, по коду)

```
RegModule (src/runtime/vm/regcode.ts:297)
   │
   ├─ A ─ emitShell (src/e2k/emitterShell.ts:350)
   │       ├─ regionsOf — участки атомов        :319
   │       ├─ scheduleRegWithReorder           :396   ← ЗДЕСЬ считаются такты (и теряются)
   │       ├─ lowerInstruction → носители IR   :472
   │       └─ encoder.encode                   :492
   │
   └─ B ─ runKernelThroughRealEncoding (src/e2k/e2kRealRun.ts:729)
           ├─ allocateProgram                   :759   ← копии + отрезки жизни + окно
           ├─ layoutOf / secondPass             :765-766
           ├─ pairPredicates                    :768
           ├─ callDisplacementsOf               :778
           ├─ lowerCarrier → команды e2k        :799
           ├─ encoder.encode ("e2k")            :817
           └─ encoder.decode + сверка           :835
```

Ветвь B **никогда не вызывает планировщик**: в `e2kRealRun.ts` нет импорта из `src/vliw/`
(проверено: `import` — строки `62-73`, среди них ни одного `../vliw/*`).
Ветвь A **никогда не выдаёт настоящие байты e2k**: `emitterShell.ts:476` берёт размер у
оболочки, а `:486` требует, чтобы мнемоника была носителем `IR.*`.

## 1. `src/e2k/latencyMap.ts` — «носитель IR → класс задержки»

**Умеет.** Отображает каждый носитель оболочки на один из четырёх классов (`ALU`, `MUL`, `MEM`,
`BRANCH`) и на **число тактов**, с источником отображения: `ПО ПРИРОДЕ` / `НАШЕ РЕШЕНИЕ` /
`НЕТ КЛАССА` (`latencyMap.ts:48`, таблица — `:139-206`). Носители без класса названы отдельно:
`IR.const` и `IR.invoke` (`:192-205`).

**Не умеет.** Читать и писать память: носителей `IR.load`/`IR.store` в оболочке **нет**, и это
сказано прямо — `CARRIERS_ABSENT_FROM_SHELL` (`:216-221`), «класс MEM остаётся без носителей»
(`:218`). Различать уровни памяти: число для `MEM` взято одно — «Ld L1 hit» 3 такта
(`CLASS_LATENCY.MEM`, `:84`).

**Место в конвейере.** Таблица для **симулятора на оболочке** (`:2`), по ней считается счёт тактов
ветви A. Файл не участвует в ветви B: `e2kRealRun.ts` его не импортирует.

**Наше решение / ограничение e2k.** Классы `ALU/MUL/MEM/BRANCH` — **наша группировка**, у
документа строки называются иначе (`Int`, `Fp`, `Fdivs/d`, `Ld L1`…) — `:13-15`. Числа тактов —
**допущение из руководства МЦСТ**, не замер: паспорт `status: 'ДОПУЩЕНИЕ'`, ограничение
«не валидировано на железе» (`:226-231`).

## 2. `src/e2k/liveness.ts` — интервалы и отрезки жизни

**Умеет.** Считает `def`/`use` по раскладке операндов эмиттера (`defUseOf`, `:150-186`), интервалы
`[первое определение, последнее чтение]` (`liveIntervalsOf`, `:189`), **точные** живые на входе и
выходе обратным анализом с переходами (`liveSetsOf`, `:105-138`), отрезки жизни, рвущиеся смертью
значения (`liveSegmentsOf`, `:245-262`).

**Не умеет.** Межпроцедурного анализа: `incomingRegisters` (`:260-269`) только **называет**
входные vreg'ы («читаются, но не определяются»), и на этом межпроцедурная часть заканчивается.
Анализ идёт по **линейному порядку** носителей, и это названо ограничением с обоснованием:
«Для циклов это даёт **более длинные** интервалы, чем нужно, то есть оценка консервативна»
(`:39-40`).

**Место в конвейере.** Ветвь B, внутри `allocateProgram` (`regAlloc.ts:335`, `:337`).

**Наше решение / ограничение e2k.** Раскладка операндов — **наша** (`emitterShell.ts:205-298`,
таблица в комментарии `liveness.ts:20-30`). Ограничение — наше: линейный порядок выбран
сознательно (переходы уже разложены двухпроходной раскладкой).

## 3. `src/e2k/regAlloc.ts` — раскладка по отрезкам

**Умеет.** Linear scan по отрезкам (`allocateSegments`, `:426-470`), применение раскладки с
пересчётом целей переходов (`remapJumpTargets`, `:192-217`), отчёт по каждой процедуре:
`peak`, `peakLive`, `segments`, `incoming`, `windowRegistersNeeded`, `fitsCalleeWindow`
(`ProcedureAllocation`, `:220-257`).

**Не умеет.** Вытеснения в память (spill): «`spill` (вытеснение в память) здесь НЕ делается: это
следующий слой» (`:18-19`, повторено в отказе `:148`). Раскладывать больше десяти регистров:
`ALLOCATABLE_REGISTERS = [0..9]` (`:48`), а `%b[10..15]` заняты рантаймом массивов (`:77`),
`%b[16..31]` недоступны, потому что окно не расширяется (`:23-25`).

**Место в конвейере.** Ветвь B, шаг `allocateProgram(emitted.instructions, …)`
(`e2kRealRun.ts:759`) — **до** раскладки адресов, и это подчёркнуто: «раскладка **укорачивает**
поток, поэтому двухпроходная раскладка адресов, сопоставление пар и понижение идут дальше по нему»
(`e2kRealRun.ts:755-757`).

**Наше решение / ограничение e2k.** Ограничение e2k: окно. Бюджет **измерен** — у вызываемой
процедуры 8 регистров против 16 у вызывающего (`WINDOW_REGISTERS_CALLEE = 8`, `:71`, замер
`src/e2k/e2kCallWindowQemu.test.ts`). Наше решение — не расширять окно `setwd`
(«поведение модели неустойчиво», `:24-25`).

## 4. `src/e2k/copyElim.ts` — устранение пересылок

**Умеет.** Снимает `IR.move d, a`, переименовывая чтения `d` в `a`, при трёх условиях: `d` не
переопределяется, `a` не переопределяется (**«не украшение»** — `:21-23`), между пересылкой и
последним чтением нет границы базового блока и нет перехода (`:129-138`). Принимает только то, что
не поднимает пик (`:215`).

**Не умеет.** Работать через границы процедур: «Нет устранения копий через границы процедур»
(`:42`).

**Место в конвейере.** Ветвь B, первым в `allocateProgram` (`regAlloc.ts:320`).

**Наше решение / ограничение e2k.** Полностью наше решение (правило Бриггса в упрощённом виде,
`:38`). Границы блоков выводятся из **наших же** переходов — цели переходов записаны индексами
потока модуля (`:87-90`), и это исправление случая 17 реестра проверяемости.

## 5. `src/e2k/rematerialize.ts` — повторная материализация констант

**Умеет.** Размножает определение `IR.const` по его чтениям (минимум два чтения, `:118`), с
отказом при цели перехода или переходе внутри промежутка (`:129-138`). Возвращает карту индексов —
копии вставляются, индексы сдвигаются **вверх** (`:51-57`).

**Не умеет.** Материализовать вычисляемые значения и анализировать доминирование — «вместо него —
то же консервативное правило границ блоков» (`:22-26`). **Эффект на корпусе — ноль**: измерено
реализацией, «материализуется **ноль** определений» (`docs/e2k-opcodes-real.md:867`).

**Место в конвейере.** Ветвь B, сразу после устранения копий (`regAlloc.ts:323`).

**Наше решение / ограничение e2k.** Наше решение, и оно **уже проверено на бесполезность** на
пяти ядрах — пример того, как оптимизация не даёт эффекта и это названо, а не замалчивается.

## 6. `src/e2k/predicatePairing.ts` — пара «сравнение → условный переход»

**Умеет.** Находит пару `сравнение → переход`, когда результат сравнения читает **ровно один**
следующий условный переход (`:235-245`), выводит полярность `0x40`/`0x60` (`:246`, `:254`) и
**отказывает с причиной** в пяти случаях (`:18-24`, коды — `:210-244`, `:260-269`).

**Чего в нём нет — и это главное для сеанса.** Проход **не производит** сравнений и не превращает
условие в сравнение. Он только сопоставляет **уже существующие** пары. Ветки `default` для
неизвестных мнемоник возвращает `known: false` (`:161-163`) — то есть появление нового носителя
даёт отказ, а не новую пару.

**Почему так.** Условный переход несёт условие **регистром-значением** (`registersOf`,
`:151-153`), а `ct` читает **предикат** (`:6-9`). Значит пару можно составить только там, где
значение уже произвёл `IR.lt`/`IR.eq`/… — шесть сравнений из таблицы (`comparisonMnemonicOf`,
`:65-82`). Ни в эмиттере оболочки, ни в `RegModule` нет операции «сравнить и запомнить предикат»:
опкоды `RegOp` — `src/runtime/vm/regcode.ts:65-115`, среди них нет ни одного предикатного.

**Место в конвейере.** Ветвь B, между раскладкой адресов и понижением (`e2kRealRun.ts:768`).

**Наше решение / ограничение e2k.** Разделение «значение vs предикат» — **ограничение e2k**
(`SS.ctcond.psrc[4:0]`). А вот отсутствие прохода «`если` → `cmp` + `ct`» — **наше** решение
(точнее, его отсутствие), потому что предикация как таковая в кодировщике уже есть.

## 7. `src/e2k/widePacker.ts` — упаковка в широкую команду

**Умеет.** Собирает **уже готовые** инструкции e2k в одну широкую команду: HS + слоги ALS по
возрастанию канала (`encodeWideGroup`, `:111-144`), до шести слогов (`MAX_SLOTS = 6`, `:32`),
с проверкой RAW/WAR/WAW (`dependent`, `:98-108`) и занятости канала (`:205`). Замер по пяти ядрам:
команд меньше на 23–38 % (`docs/e2k-wide-commands.md:265-266`).

**Не умеет.** Планировать и переставлять — «Не планирует и не переставляет: порядок инструкций
сохраняется, меняется только упаковка» (`:20-22`). Класть в широкую команду литералы и сравнения:
у сравнения поле `nop = 2` живёт в HS и было бы общим для всей команды (`:83-85`).
И **самое важное:** `packWide` не вызывается из конвейера. Единственные импорты — тесты
(`src/e2k/widePackets.test.ts:29`, `src/e2k/e2kWideQemu.test.ts:38`, `src/e2k/e2kWideFir.test.ts:36`);
в `e2kRealRun.ts` и `emitterShell.ts` импорта нет.

**Следствие (факт из двух цитат).** Действующая ветвь B кодирует **одну команду на инструкцию**:
`e2kRealRun.ts:817` зовёт `encoder.encode(command)` по одной команде, а `headerWord`
(`e2k-real.ts:530-539`) ставит ровно один бит ALS.

**Место в конвейере.** Формально — надстройка над кодировщиком; фактически — **остров, не
подключённый к конвейеру**.

**Наше решение / ограничение e2k.** Ограничение формы — «две операции в один канал — отказ
ассемблера» (`docs/e2k-wide-commands.md` §2.6, `gas/config/tc-e2k.c:8668`). А **запрет зависимости
внутри команды — наше правило**, обоснованное замером (дефект 6.2: код возврата 5 вместо 13,
`docs/e2k-wide-commands.md:218`).

## 8. `src/e2k/e2k-real.ts` — кодировщик

**Умеет.** 24 операции ALS в формах ALF1/ALF2/ALF3/ALF11/ALF7 (`:141`, таблица `:269-276`), шесть
операций управления слогами SS/CS0/CS1 (`:631-672`), литералы LTS, файл регистров в операнде,
предикат-приёмник `pdst`.

**Не умеет — по полям, прямо в коде:**

| поле формы | значение | цитата |
|---|---|---|
| `lm` (режим цикла) | «в этой реализации ноль» | `e2k-real.ts:97` |
| `ss` (наличие SS-слога) | «в этой реализации ноль» | `:104` |
| `sw` | «в этой реализации ноль» | `:106` |
| `cs[1:0]` | «в этой реализации ноль» | `:108` |
| `cd`, `pl` | «здесь ноль» | `:110-113` |
| бит 31 ALS (спекулятивный) | «интерфейс его не выражает, здесь всегда ноль» | `:118` |

`headerWord` (`:530-539`) не выставляет `lm` вовсе, то есть он нулевой по построению. Разбор
**отвергает** чужое значение: `lm` в списке полей, обязанных быть нулевыми (`:1068-1081`), а
установленный спекулятивный бит — исключение `:1121-1123`.

**Место в конвейере.** Низ ветви B (`e2kRealRun.ts:817`) и низ ветви A (нужен свой ключ).

**Наше решение / ограничение e2k.** Отказ выражать поле — **наше** ограничение интерфейса
(«не терять поле молча», `:1046`). Само поле `lm` — **факт e2k**; то, что оно не используется, —
наше состояние.

## 9. `src/e2k/emitterShell.ts` — эмиттер на оболочке

**Умеет.** Размечает участки атомов и **переставляет** внутри участка, только если
`region.optimizable` (`:394`); понижает IR в носители, отказывая на операциях без носителя
(`NO_CARRIER`, `:104-114`); кодирует по одному слову на операцию.

**Не умеет — и это ключ ко всей карте.** Планировщик вызывается, но из его результата берётся
**только порядок**:

- `emitterShell.ts:396` — `const scheduled = scheduleRegWithReorder(body, { memoryLevel: "l1", offsetBase: region.start });`
- `emitterShell.ts:397` — `localOrder = scheduled.order;`

Числа тактов, которые планировщик посчитал (`issueAt`, `nopCycles`, `packets` —
`reorderScheduler.ts:759-762`), **не читаются нигде**: `grep` по `emitterShell.ts` даёт семь
вхождений `scheduled`, и все — либо `scheduled.order`, либо локальная копия модуля (`:456`).

**Дальше — жёстко:** канал выдачи не назначается («модель устройства этим эмиттером не
используется», `:28`, `:546`), упаковки нет (`:545`), а мнемоники обязаны быть носителями `IR.*`
(`:486-490`).

**Место в конвейере.** Ветвь A целиком.

**Наше решение / ограничение e2k.** Всё это — наши ограничения оболочки, а не свойства e2k.
Оболочка объявлена «НЕ e2k» в описании кодировщика (`:532`).

## 10. `src/e2k/e2kRealRun.ts` — понижение IR → e2k

**Умеет.** Один проход: раскладка регистров → адреса → смещения → пары предикатов → смещения
вызовов → понижение → кодирование → **разбор обратно и сверка** (`:784-842`). Отчёт называет
**три разных числа** и запрещает их смешивать: носители, снятые копии, команды e2k (`:614-618`).

**Не умеет.** Обходить процедуры иначе, чем по индексу: `calledIndices` собирается по носителям
`IR.call` (`:879-884`), а окно вызываемой считается по `allocation.report` (`:885`). Исполнять:
«Не исполняет реальный машинный код: эмулятора e2k нет» (`:57`). Планировать: импортов из
`src/vliw/` нет (`:62-73`).

**Место в конвейере.** Ветвь B целиком.

**Наше решение / ограничение e2k.** Таблица понижения — **наше решение**, и это сказано: «у
операции `IR.add` нет „своего" кода операции в e2k, есть **выбранная** нами операция `adds`»
(`:24-26`).

## 11. `src/vliw/scheduler.ts` — in-order упаковка по слотам

**Умеет.** Упаковывает `RawInstruction` в пакеты строго в исходном порядке, закрывая пакет, если
продюсер ещё лежит в нём (`:48-59`).

**Не умеет.** Переставлять — и это названо причиной: «в отличие от готового list scheduling, который
переставляет push/pop и ломает стек» (`:50-52`). Считать задержки: у него нет ни одного обращения к
`latencyFor`.

**Место в конвейере.** Оболочка (формат `VliwPacket`, `src/vliw/e2kModel.ts`), **не** ветвь B.
`regcode.ts:274-275` описывает `deps` как «hint для планировщика», но эмиттер на оболочке
**отвергает модуль с пакетами** (`emitterShell.ts:365-369`).

**Наше решение / ограничение e2k.** Полностью наше — это формат `.osvbc`, а не e2k. Слот-модель
`I0/I1/M/B` признана выдуманной: «В руководстве МЦСТ таких имён нет» (`src/vliw/e2kDevices.ts:11-14`).

## 12. `src/vliw/dependencyGraph.ts` — граф зависимостей по стеку

**Умеет.** Строит рёбра producer→consumer, симулируя стек (`:41-186`); отдельно упорядочивает
эффекты через `lastEffect` (`:140-143`, `:155-158`).

**Есть готовый, но не задействованный вход — чистота.** Опции `callPure` и `invokePure`
объявлены (`:22`, `:27`) с прямым смыслом: «Чистый ли invoke по имени (read-only системный вызов →
**не упорядочивается с эффектами**)», а по умолчанию «любой invoke считается эффектом» (`:25-26`).
Кто их подаёт — надо искать вызывающего; в самой ветви B такого вызывающего нет (импортов из
`src/vliw/` в `e2kRealRun.ts` нет).

**Не умеет.** Межпроцедурного анализа: `callArgc`/`callPure` — **входные функции**, то есть знание
о чистоте должно прийти **извне**, а не вычисляется здесь.

**Место в конвейере.** Оболочка (пакеты `.osvbc`), не ветвь B.

**Наше решение / ограничение e2k.** Наше; ограничение e2k здесь одно — вызов и запись в память
суть эффекты, и это верно для любого железа.

## 17. `docs/e2k-syscall-abi.md` — ABI системного вызова и окно

**Умеет.** Описывает окно точно: индекс окна → физический регистр как
`(wd_base_d + idx) % MAXSR_D`, выход за `size_d` — исключение (`:42`); `call` проверяет
`psize_q ≤ wbs ≤ size_q` (`:91`); `call` сдвигает окно (`:116`).

**Чего в нём нет.** Правила **сохранения** регистров при вызове: в файле нет ни слова о том, какие
регистры обязан сохранять вызывающий, а какие вызываемая. Ближайшее — «сама передача управления»
(`:113`) и общий вывод «восстанавливать окно после возврата» (`:259`). То есть **модели
call-окна как соглашения о сохранении нет** — есть модель геометрии окна.

**Место.** Ограничение e2k для раскладки регистров (ветвь B).

## 20. `docs/language-v2-requirements.md` — измеренные отказы модели
