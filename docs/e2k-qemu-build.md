## 2. Точная причина, почему сборка не состоялась

**Шаг, на котором остановилось: 3.1 — запуск `configure`.** До `make` дело не дошло.

### 2.1. Команда и её результат

Попытка выполнена из каталога `qemu`:

```
./configure --target-list=e2k-linux-user --disable-docs
```

Результат (PowerShell, дословно):

```
Невозможно запустить документ в середине конвейера:
D:\PROJECTS\OSNOVA-FABRIKA\.tmp\e2k-sources\qemu-e2k\qemu\configure
```

`configure` — это **shell-скрипт** (`#!/bin/sh`), а Windows не исполняет его напрямую.

### 2.2. Чего нет в окружении

| инструмент | состояние | зачем нужен |
|---|---|---|
| `sh` | **НЕТ** | `configure` и `meson.build` начинаются с него (`qemu/meson.build:78`: `sh = find_program('sh')`) |
| POSIX-оболочка вообще | **НЕТ** | `bash.exe` в системе — это запускатель WSL; `wsl -l -v` отвечает «нет установленных дистрибутивов» |
| C-компилятор (`gcc`, `cc`, `clang`) | **НЕТ** | `qemu/meson.build:81`: `cc = meson.get_compiler('c')` |
| `make` | **НЕТ** | шаг 3.1 предписывает `make` |
| `meson`, `ninja` | **НЕТ** | система сборки QEMU 11.x |
| `pkg-config`, `glib-2.0` | **НЕТ** | обязательные зависимости QEMU |

Проверено командой `Get-Command` по каждому имени; ни одного попадания, кроме `bash.exe`.

### 2.3. Почему это не ошибка порта e2k

Цель `e2k-linux-user` — **user-mode** эмуляция (`configs/targets/e2k-linux-user.mak`,
`TARGET_ARCH=e2k`). Сборка user-mode требует POSIX-хоста: `configure` и весь `meson.build`
написаны на shell и требуют C-компилятора. На Windows-хосте без WSL-дистрибутива и без
инструментальной цепочки сборка не начинается **не из-за e2k**, а из-за хоста: тот же
`configure` не собрал бы и `x86_64-linux-user`.

### 2.4. Шаги 3.2 и 3.3 постановки

| шаг | состояние |
|---|---|
| 3.1 распаковать, настроить, собрать | **распаковано** (§1), **настроить не удалось** — §2.1, `make` не запускался |
| 3.2 записать путь к бинарю, версию, CPU | путь бинаря — `.tmp/e2k-sources/qemu-e2k/build/qemu-e2k`; **бинаря нет**; версия порта — `11.0.1`; CPU — шесть моделей `elbrus-v2`…`elbrus-v7` (§1) |
| 3.3 записать точную причину | эта запись, §2.1–2.2: останов на запуске `configure`, нет `sh` и нет C-инструментов |

## 3. Что из-за этого НЕ проверено

| проверка | почему не выполнена |
|---|---|
| наши байты принимает MCST-objdump или QEMU-e2k | нет ни собранного QEMU, ни собранного binutils: компилятора C нет |
| расшифровка наших байт слогами по `target/e2k/instr-bits.h` | нужен запуск кода; вместо него — сверка **исходников** (`docs/e2k-sources-raw.md` §3) |
| прогон пяти DSP-ядер на реальном эмуляторе | QEMU не собран; см. `docs/e2k-qemu-run.md` |

**Что это значит для доказательности:** раскладка полей подтверждена **совпадением четырёх
независимых описаний** (`binutils` МЦСТ, LLVM-порт, QEMU МЦСТ, реверс `elbrus-docs`), но **не
проверена инструментом**. Это слабее, чем прогон через MCST-objdump, и здесь сказано прямо.

## 4. Что нужно, чтобы сборка состоялась

| условие | зачем |
|---|---|
| Linux-хост (или WSL с установленным дистрибутивом) | `configure` — shell-скрипт; user-mode цель требует POSIX-хоста |
| `gcc`/`clang`, `make` | сборка |
| `meson >= 1.5`, `ninja`, `python3` | система сборки QEMU 11.x |
| `glib-2.0`, `pkg-config` | обязательная зависимость |

Порядок: распаковать архив → `mkdir build && cd build` → `../configure --target-list=e2k-linux-user
--disable-docs` → `make -j`. Ожидаемый бинарь — `build/qemu-e2k`. **Ни один из этих шагов в этом
окружении не выполним**, поэтому «QEMU-e2k собран» здесь не утверждается.
