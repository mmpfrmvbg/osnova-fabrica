# Языковые нужды chat-приложения (план v1.8)

Источник: анализ apps/chat/chat.osnova + аудит реестра v1.7.0.

---

## а) Есть в языке и работают в VM

- `пока` — цикл ввода-вывода
- `система.массив.создать` / `система.массив.добавить` — история сообщений
- `система.строка.объединить` — ручная сборка строк
- `система.сеть.пост` — отправка сообщений
- `попробовать / иначе_попытка` — обработка сетевых ошибок
- `система.лог.вывести` — вывод ответов

---

## б) Есть в реестре и invokeRegistry, НЕ реализованы в vm-runner

- `система.json.создать(значение)` — сериализация объекта в JSON-строку;
  нужна для формирования тела запроса вместо ручной сборки через объединить
- `система.json.разобрать(строка)` — парсинг ответа сервера;
  нужна для извлечения поля `reply` из JSON-ответа
- `система.ввод.текст(подсказка)` — интерактивный ввод от пользователя;
  нужна для цикла ввода в терминальном режиме
- `система.строка.найти(строка, подстрока)` — поиск индекса подстроки;
  нужна для разбора ответов и детектирования команд (напр. "/выход")

---

## в) Нужны, отсутствуют совсем

- `прервать` — выход из цикла (`пока истина`) по команде пользователя;
  без него graceful exit невозможен без флага-переменной
- `система.строка.из_числа(число)` — конвертация числа в строку
  для формирования порядковых номеров сообщений в истории;
  сейчас заблокирована как FORBIDDEN, нужно пересмотреть для v1.8
- `система.объект.создать()` — явное создание пустого объекта через syscall
  (сейчас только литерал `{}` — нет проблемы для статичных структур,
  но нужно для динамической сборки тела запроса)

---

## Приоритеты для v1.8

| Конструкция | Приоритет | Блокирует |
|---|---|---|
| `система.json.создать` | P0 | боевой чат без ручной сборки JSON |
| `система.json.разобрать` | P0 | чтение ответа сервера |
| `система.ввод.текст` | P0 | интерактивный режим |
| `прервать` | P1 | graceful exit из цикла |
| `система.строка.найти` | P1 | детектирование команд |
| `система.строка.из_числа` | P2 | нумерация сообщений |
