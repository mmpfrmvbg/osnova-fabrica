Порт, которым измерены числа машинной плоскости, — с паспортом
================================================================

Зачем этот каталог
------------------

Все замеры `src/e2k/**` и `src/vliw/**` (окно вызываемой, коды выхода, байты, такты оболочки)
получены на **одной конкретной сборке** `qemu-e2k` в WSL-дистрибутиве `e2k`. Пока у этой
сборки не было паспорта, «модель» была моделью без имени: непонятно, что именно измерено и
что изменится, если сборку пересобрать.

Правка
------

**Правок четыре, в двух файлах.**

1. `linux-user/e2k/cpu_loop.c`, `target_cpu_copy_regs` — инициализация окна
   ([`osnova-local-cpu_loop.patch`](osnova-local-cpu_loop.patch), sha256 `93af9cbf…`):
   - `_d = 2 * _q` — добавляются парные поля окна. Причина записана в самом патче:
     `_d = 2 * _q` (`target/e2k/cpu.h:58`), порт эти поля только **читает**, поэтому без них не
     доступен ни один оконный регистр и системный вызов не может прочитать номер из `%r0`.
   - **Геометрия окна `size_q = 12`** (было 8), `size_d = 12 * 2` — вызываемая получает
     `2 * (12 − psize_q=4) = 16` регистров вместо восьми (`docs/hardware-debt.md` §3.36, §3.44).
     Почему 12: это первая ступень лестницы §3.36 с запасом — пяти ядрам нужно максимум **10**,
     минимальный по формуле — 9. Поле `size_q` — семь бит (`MAXSR_Q = 112`), поэтому 12 выразимо.
2. `target/e2k/tcg/translate-ct.c` — пересборка `WD` в `e2k_cpu_exec_ct_RETURN` (возврат) и
   `e2k_cpu_exec_ct_CALL` (вызов) ([`osnova-local-translate-ct.patch`](osnova-local-translate-ct.patch),
   sha256 `763fd9df…`): те же `_d = 2 * _q`. `cpu_loop.c` задаёт окно только на входе; после
   `call`/`return` порт строит `WD` заново, и без этих строк `_d` снова нулевые — оконные
   регистры недоступны. **Без второго патча пересборка «по репозиторию» даёт другой бинарь** —
   это и был D4-риск.

```c
/* cpu_loop.c: инициализация окна */
env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, size_q , 12);
env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, psize_d, 4 * 2);
env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, size_d , 12 * 2);

/* translate-ct.c, e2k_cpu_exec_ct_RETURN (в CALL формулы соседние) */
new_wd = FIELD_DP64(new_wd, WD, base_d, ((wd_base_q + MAXSR_Q - wbs) % MAXSR_Q) * 2);
new_wd = FIELD_DP64(new_wd, WD, size_d, (wd_psize_q + wbs) * 2);
new_wd = FIELD_DP64(new_wd, WD, psize_d, wpsz * 2);
```

Патчей два, потому что правки лежат в разных файлах. В `cpu_loop.c` обе строки меняются одним
файлом (вторая трогает `size_d`, которую меняет первая). Оба патча проверены ВНЕСЕНИЕМ
(`patch -p1` на pristine-копии релиза): `diff -q` результата с живым деревом пуст для обоих
файлов. **2026-11-09:** первый патч перегенерирован — из него убран лишний комментарий, которого
нет в живом источнике (код не менялся, бинарь `4e37a372…` тот же).

**Чего эти патчи не доказывают.** Они сняты как разница с `backup-cpu_loop.c` и
`backup-translate-ct.c`, а не с git-ревизии: её по-прежнему нет. Зато известен релиз — МЦСТ
qemu-e2k 11.0.1 (tarball sha256 `15b29347…`, `docs/e2k-sources-raw.md`), и его pristine-копия
лежит в `.tmp/e2k-sources/qemu-e2k`. Полный `diff -rq` против неё даёт ровно эти два файла —
других локальных правок в дереве нет.

Как проверить, что измеряешь то же
----------------------------------

Оракул `src/e2k/qemuModelIdentity.test.ts` (шлюз `npm run gate:qemu`, в полный прогон не входит)
спрашивает у живой сборки версию и sha256 и сверяет с паспортом
(`src/e2k/qemuModelPassport.ts`). Расхождение — **красное с названной причиной**: «модель
изменилась, закреплённые числа требуют перемера». Это тот случай, когда покраснение полезно:
оракул сменился — значит сменилась и истина, а не код.

Как пересобрать (когда понадобится)
-----------------------------------

```bash
# в WSL-дистрибутиве e2k
cd /root/qemu-src/qemu
patch -p1 < /mnt/d/PROJECTS/OSNOVA-FABRIKA/tools/qemu-e2k/osnova-local-cpu_loop.patch
patch -p1 < /mnt/d/PROJECTS/OSNOVA-FABRIKA/tools/qemu-e2k/osnova-local-translate-ct.patch
cd /root/qemu-build && make -j"$(nproc)" qemu-e2k
sha256sum /root/qemu-build/qemu-e2k      # новый хеш → обновить паспорт и перемерить числа
```

Полный sha256 бинаря: `4e37a37243189dec4f7405ed465c7eade2d51f5edab95060a6ada880f23fe081` — см.
`src/e2k/qemuModelPassport.ts`, там же хранится ссылка на этот патч и **геометрия окна**
(`window: { psizeQ, sizeQ, wbs }`), которой объявлены закреплённые числа.

**Состояние на 2026-09-28 (§3.49):** обе правки ВНЕСЕНЫ и живут в сборке; паспорт описывает
именно эту сборку. Прежняя сборка (`9a5be965…`, `size_q = 8`) — та, на которой снята лестница
§3.36; её числа перемерены при переходе на 12.

**Состояние на 2026-11-09 (D4-fix):** в репозитории оба патча; `patch -p1` на pristine-копии

внесением патчей.
