Порт, которым измерены числа машинной плоскости, — с паспортом
================================================================

Зачем этот каталог
------------------

Все замеры `src/e2k/**` и `src/vliw/**` (окно вызываемой, коды выхода, байты, такты оболочки)
получены на **одной конкретной сборке** `qemu-e2k` в WSL-дистрибутиве `e2k`. Пока у этой
сборки не было паспорта, «модель» была моделью без имени: непонятно, что именно измерено и
что изменится, если сборку пересобрать.

Паспорт (сверено 2026-09-25, `wsl -d e2k -- bash tools/qemu-e2k/probe-port.sh`):

| Что | Значение |
|---|---|
| Бинарь | `/root/qemu-build/qemu-e2k` |
| Версия | `qemu-e2k version 11.0.1` |
| sha256 | `9a5be965f04c312b…` (полный — в конце файла) |
| Собран | 2026-09-18 15:02:05 |
| Исходники | `/root/qemu-src/qemu` — **не git-репозиторий**: ни ревизии, ни апстрима |
| Прежняя версия файла | `/root/backup-cpu_loop.c` (до нашей правки) |
| Наша правка | `osnova-local-cpu_loop.patch` рядом с этим файлом |

Правка
------

Одна, в `target_cpu_copy_regs` (`linux-user/e2k/cpu_loop.c`): после строк, задающих
`psize_q = 4` / `size_q = 8`, добавляются парные поля окна:

```c
env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, psize_d, 4 * 2);
env->sregs.wd = FIELD_DP64_E2K(env->sregs.wd, WD, size_d , 8 * 2);
```

Причина записана в самом патче: `_d = 2 * _q` (`target/e2k/cpu.h:58`), порт эти поля только
**читает**, поэтому без них не доступен ни один оконный регистр и системный вызов не может
прочитать номер из `%r0`.

**Чего этот патч не доказывает.** Он снят как разница с `backup-cpu_loop.c`, а не с известного
апстрима: точная ревизия, от которой пошло дерево, неизвестна, и других локальных правок мы
перечислить не можем. Полный набор правок станет перечислимым только после пересборки из
**git-чекаута известной ревизии** — это названный долг, а не сделанное.

Как проверить, что измеряешь то же
----------------------------------

Оракул `src/e2k/qemuModelIdentity.test.ts` (шлюз `npm run gate:qemu`, в полный прогон не входит)
спрашивает у живой сборки версию и sha256 и сверяет с паспортом
(`src/e2k/qemuModelPassport.ts`). Расхождение — **красное с названной причиной**: «модель
изменилась, закреплённые числа требуют перемера». Это тот случай, когда покраснение полезно:
оракул сменился — значит сменилась и истина, а не код.

Как пересобрать (когда понадобится)
-----------------------------------

```bash
# в WSL-дистрибутиве e2k
cd /root/qemu-src/qemu
patch -p1 < /mnt/d/PROJECTS/OSNOVA-FABRIKA/tools/qemu-e2k/osnova-local-cpu_loop.patch
cd /root/qemu-build && make -j"$(nproc)" qemu-e2k
sha256sum /root/qemu-build/qemu-e2k      # новый хеш → обновить паспорт и перемерить числа
```

Полный sha256 бинаря: `9a5be965f04c312b…` — см. `src/e2k/qemuModelPassport.ts`,
там же хранится ссылка на этот патч.
