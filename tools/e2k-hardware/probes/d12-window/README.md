# Зонд D12: что переживает блок рантайма массивов после системного вызова

> Замер снят 2026-11-08 на живой E8C2. **Отсюда не воспроизводится**: e2k-toolchain и доступа к
> машине на хосте нет. Каталог держит ЗАПИСЬ замера и сам прибор — того, кто увидел то, чего модель
> не видит.

## Вопрос, ради которого зонд существует

Рантайм массивов держал состояние в клетках `%b[12..15]` плоскости **точки входа**
(`ENTRY_ARRAY_CELLS` в `src/e2k/arrayRuntime.ts`: `zero` / `one` / `eight` / адрес ячейки кучи).

Сайт печати делает системный вызов формой

```
setwd wsz = 0x8 ; sdisp %ctpr1, 0x3 ; ipd 3 ; call %ctpr1, wbs = 0x4 ; setwd wsz = 0x10
```

`call wbs = 4` сдвигает окно на `2·4 = 8` регистров. Значит `%b[12..15]` **вызывающего** — это
`%b[4..7]` **вызываемого**. Вызываемый (ядро) вправе занять свои клетки — и занимает.

**Что это даёт на практике.** `eight` (8) обнулялся → `а[i]` читалось по адресу `база + 8i` вместо
`база + 8 + 8i`, то есть `а[i]` = `а[i-1]`, а `а[0]` = слово длины. `%b[15]` (адрес ячейки кучи)
обнулялся → `создать` читало кучу по адресу 0 и падало кодом **139**. `длина` этих клеток не
использует — поэтому она и не ломалась.

## Почему без этого зонда дефект невидим

**Модель этого закона не воспроизводит.** На тех же байтах модель даёт исходные 1/8/17, железо —
0/0/0. Поэтому 228 файлов прогона были зелёными, а цель падала: это класс «прибор не различает»
(случай 52 реестра проверяемости). Проба — единственное, что модели и цели **противопоставляет**.

## Пробы

| файл | клетка | вызовов | что это |
|---|---|---|---|
| `probe-b12.s` | `%b[12]` | 2 | вопрос: `write(1,NULL,0)`, затем `exit(%b[12])` |
| `probe-b13.s` | `%b[13]` | 2 | вопрос |
| `probe-b14.s` | `%b[14]` | 2 | вопрос |
| `probe-b15.s` | `%b[15]` | 2 | вопрос |
| `probe-b14-nowrite.s` | `%b[14]` | **1** | **контроль**: без `write`, только `exit` |

Значения помечены так, чтобы каждое было отличимо в младшем байте кода возврата:
`%b[12]=0x00`, `%b[13]=0x01`, `%b[14]=0x08`, `%b[15]=0x11`.

**Контроль — не украшение.** Без `b14-nowrite` четыре нуля не значат ничего: «0» мог бы получиться и
от неработающего зонда (не та клетка, стёртый регистр, промах по адресу). Ответ **8** без вызова
доказывает, что проба читает именно ту клетку, которую записала.

## Замер (`report-hardware.txt`, E8C2 `a1d3a4a788e9`, `e2k`, `6.1.0-0.8-e8c2`, 2026-11-08 07:33 MSK)

```
exit(b12) = 0
exit(b13) = 0
exit(b14) = 0
exit(b15) = 0
exit(b14-nowrite) = 8
```

Модель на **тех же байтах** (`probe-b14` и `probe-b14-nowrite`, перемер 2026-11-14):

```
probe-b14:         код=8
probe-b14-nowrite: код=8
```

То есть модель **не различает** пробу с вызовом и без: у неё клетка цела в обоих случаях. Железо
различает. Это и есть канал D12.

## ⚠️ Расхождение с таблицей §3.187.1 — названо, а не сглажено

Таблица в `docs/hardware-debt.md` §3.187.1 показывает колонку «контроль БЕЗ вызова (железо)» со
значениями **0 / 1 / 8 / 17** для всех четырёх клеток. В отчёте прогона записан **один** контроль:
`exit(b14-nowrite) = 8`.

Три значения (`%b[12]`→0, `%b[13]`→1, `%b[15]`→17 в колонке контроля) в отчёте **отсутствуют**.
Они правдоподобны — без вызова клетка обязана хранить записанное — но правдоподобие не замер.
Сторож `src/scripts/d12Probe.audit.ts` требует ровно **один** названный контроль, потому что ровно
один был снят. Дописать в отчёт три недостающих прогона можно только на машине.

## Границы (названы)

- Замер — про E8C2 с ядром `6.1.0-0.8-e8c2`. Для другой машины/ядра закон окна даёт
  **предсказание** (то же поведение везде, где `call wbs = 4` двигает окно на восемь регистров), но
  предсказание — не замер.
- Зонд говорит только про клетки окна, не про чтение памяти.
- `%b[12]` до и после равен 0 потому, что нужное значение там **и есть** 0, — а не потому, что
  клетка уцелела. Ноль в этой клетке не является свидетельством сохранности.
- Правка сайта печати (три команды восстановления) стережётся другим прибором —
  `src/e2k/arrayBlockRestore.test.ts`. Здесь предмет другой: **сам зонд**.

## Прогон на машине

`run.sh` рядом — канонический стенд. Всё составное (`as`, `ld`, `tee`, редирект) живёт **в залитом
скрипте**, а не в аргументе `ssh`: `ssh хост "a; b"` приходит на машину одним аргументом, и `;`
уезжает в программу параметром (ловушка из `AGENTS.md`).

```sh
scp -P 8194 -r d12-window mmpvbg@w205p.mcst.ru:/tmp/
ssh -p 8194 mmpvbg@w205p.mcst.ru 'sh /tmp/d12-window/run.sh'
```

Разбор механизма и правка — `docs/hardware-debt.md` §3.187 / §3.187.1.
