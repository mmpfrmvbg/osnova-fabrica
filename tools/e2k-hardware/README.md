# Кит для живой машины Эльбрус

Зачем
-----

Наш компилятор — TypeScript под Node, и на контейнер Эльбруса он **не поедет**. Значит на машину
везут готовые **e2k-ELF**, собранные на стороне разработки, вместе с эталонами и скриптами.
Машина только исполняет и сравнивает: её роль — **оракул**, а не сборочный цех.

Паспорт модели, на которой получены эталоны, — `src/e2k/qemuModelPassport.ts`
(QEMU 11.0.1, своя сборка с локальной правкой окна). Это важно: пока железо не проверено, все
числа — числа **модели**, и первый прогон на машине их либо подтверждает, либо опровергает.

Состав
------

| Файл | Что |
|---|---|
| `bin/*.elf` | по бинарю на каждый пример корпуса, объявленный исполняемым на цели |
| `expected.tsv` | `бинарь → канал эталона → эталон`; читается `awk`/`cut`, без python и jq |
| `expected.json` | то же плюс `shows`, `hardware` («что докажет на машине»), sha256 бинаря и чем получен эталон |
| `machine.sh` | отчёт о машине: процессор, ядро, `lcc`/`as`/`objdump`, утилиты, ограничения контейнера |
| `run.sh` | прогон всех бинарей с таймаутом и сверкой с `expected.tsv` **по каналу** |
| `probes.sh` + `probes.tsv` | **зонды**: два вопроса к машине без эталона (окно вызываемой, знак остатка) |
| `probes/` | исходники зондов; собираются `npx tsx src/scripts/e2kHardwareProbes.ts` |

Канал эталона — третье поле в `expected.tsv`, и оно обязательно:

- **`возврат`** — результат отдан кодом возврата процесса; `run.sh` сверяет код (как было);
- **`вывод`** — результат отдан БАЙТАМИ stdout (печать `система.лог.вывести`, записи `39`–`44`
  корпуса). `run.sh` сверяет вывод через `cmp` и требует код `0`. В таблице эталон записан
  экранированным (`10\n`, `1\n2\n3\n`), потому что строка `awk`-таблицы перевода строки не несёт;
  `printf '%b'` разворачивает `\n` обратно, и сверка идёт **байт в байт**.

Почему канал понадобился: без него эталон печатающей записи («10») сравнивался бы с кодом возврата
(0), и машина отчитывалась бы о расхождении там, где всё верно (docs/hardware-debt.md §3.43).

Зонды — не примеры. У примера есть эталон, и машина обязана его повторить; у зонда есть
**вопрос**, и машина даёт ответ. Поэтому они лежат в отдельной таблице и судит их человек.
| `probe-window.sh` | эксперимент «окно вызываемой» — вопрос §3.18 (готовится) |
| `probe-rem.sh` | эксперимент «знак остатка `SMODX`» — вопрос §3.21 |

Зонды запускаются `sh probes.sh` (вопросы 2 и 3 из `docs/e2k-hardware-access.md`).
Готовые исходники — `probes/probe-rem.osnova` (через **вызов** `система.математика.остаток`,
потому что у оператора `%` формы понижения нет) и `probes/probe-bool.osnova`
(честно не собирается: булев литерал `истина` на цель не выражается).

Пересобрать кит (на стороне разработки):

```bash
npx tsx src/scripts/e2kHardwareKit.ts
```

Порядок первой сессии (1–2 часа)
--------------------------------

1. `sh machine.sh > machine.txt 2>&1` — что за машина. Без этого отчёта результат нечем подписать.
2. `sh run.sh` — прогон всех бинарей кита. Каждый результат либо **совпал** с эталоном по своему
   каналу (код возврата либо байты вывода), либо это расхождение с числом.
3. Fallback: собрать на машине `fallback/hello.c` их `lcc` и `fallback/hello.s` их `as`,
   запустить. Это доказывает, что тулчейн и загрузчик машины рабочие **отдельно от наших байтов**.
   Если наш ELF не запустится, а их — запустится, мы знаем, что дело в нас.
4. `probe-window.sh` — сколько регистров видит вызываемая процедура (модель говорит 16: порт собран
   с `size_q = 12`, контроль зонда стоит в `%r15`, вопрос — в `%r16`, §3.49).
5. `probe-rem.sh` — `(-7) % 3`: руководство МЦСТ §10.3.3 обещает −1, наша VM даёт −1,
   модель даёт 0. Машина рассудит.
6. `objdump -d` на любом нашем бинаре — их дизассемблер против наших байтов (независимая сверка).

Правила
-------

- **Ничего не подгонять.** Если код возврата не совпал — это расхождение, и оно записывается
  числом вместе с моделью процессора и версиями тулчейна.
- **Модель ≠ железо.** Расхождение модели с машиной — не «наша ошибка» и не «их ошибка»:
  это измерение, которое мы потом объясняем.
- **Всё, что не проверено на машине, остаётся «не проверено».** Статус «e2k: работает» в корпусе
  пока означает «работает на модели»; после машины он получит вторую половину.
- Бинарь без совпавшего sha256 не исполнять: сначала сверить с `expected.json` — иначе непонятно,
  что именно бежит.
