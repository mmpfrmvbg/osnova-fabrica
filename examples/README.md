# Корпус примеров

> Файл сгенерирован: `npx tsx src/scripts/examplesIndex.ts`. Руками не править —
> расхождение с корпусом ловит оракул `src/scripts/examples.audit.test.ts`.

Здесь лежат законченные программы: каждая собирается и исполняется, у каждой
эталон результата получен **независимо** от прогона, который её проверяет.
Статус `нет` у цели обязан называть причину — молчаливое «не работает»
причиной не считается.

## Границы, названные честно

Сюда попадают программы дерева, которые в корпус не входят: они делают то,
чего язык на цели пока не умеет. Это не дефект корпуса, а честная граница.

| Программа | Что делает | e2k | Причина |
|---|---|---|---|
| `tests/dsp/kernels/fir.osnova` | Полное ядро FIR с вызовом процедуры «фильтр»: две петли и одно ядро | нет | окно вызываемой — 8 регистров против нужных 10: долг назван и отложен владельцем (§3.24, docs/hardware-debt.md) |
| `apps/osnova-todo/todo.osnova` | Приложение списка задач: строки, хранилище, обработка ошибок | нет | строки на цель не проверены, реестр системных вызовов исполняется VM (§13.12); обработка ошибок на границе процедуры в e2k-подмножестве не реализована (§13.7) |
| `apps/task-manager/main.osnova` | Приложение задач: точка входа, снятая из реестра приложений | нет | не компилируется: 6 семантических ошибок (арность и отсутствующий импорт) — приложение снято из реестра с названными причинами (§13.13) |
| `src/runtime/fixtures/ilp_mid.osnova` | Фикстура планировщика: вычисление с остатком в горячем цикле | нет | остаток `%` на цель не понижается: у носителя «IR.rem» формы понижения нет, инструкция в образ не попадает. Замер .tmp/probe-percent.ts: `7 % 3` и `10 % 5` дают отказ носителя, `7 div 3` работает (REFUSALS в src/e2k/e2kRealRun.ts, docs/e2k-real-run.md §2.2) |
| `src/runtime/fixtures/cycle_array.osnova` | Фикстура планировщика: перебор массива с проверкой чётности через остаток | нет | остаток `%` на цель не понижается: у носителя «IR.rem» формы понижения нет, инструкция в образ не попадает. Найденным классом «возврат из ветви» НЕ объясняется: в примере возврат один, в конце процедуры. Причина не установлена |
| пример `21-две-накапливающие-переменные` | на модели 46 против 2350 на VM при полном понижении (отказов 0). Класс подтверждён и обобщён пробами .tmp/probe-two-accumulators.ts, .tmp/probe-multiply-by-literal.ts и .tmp/probe-sum-compare.ts: теряются старшие разряды у ЛЮБОГО значения не меньше 256 — `22 * 100` даёт 152, `1000 - 22` даёт 210 = 978 - 256*3, `978 - 22` даёт 188 = 956 - 256*3, причём и константа 1000 теряет разряды прямо в выражении. Обходом было бы подставить множитель поменьше; это запрещено, поэтому статус «e2k: нет». Причина не установлена — долг линии e2k |
| пример `25-два-накопителя-разных-знаков` | на модели 188 против 956 на VM при полном понижении (отказов 0) — тот же класс, что пример 21: 956 - 256*3 = 188. Изоляция .tmp/probe-sum-compare.ts: `1000 - 22` даёт 210 = 978 - 256*3, то есть разряды теряет даже константа в выражении, а не только произведение. Причина не установлена — долг линии e2k |
| пример `26-сравнение-сумм-двух-массивов` | на модели 0 против 1 на VM при полном понижении (отказов 0). Объясняется найденным классом: `вернуть` внутри `если` не срабатывает, модель уходит на запасной возврат (минимальная проба .tmp/probe-early-return.ts: `если 1 > 0 → вернуть 7` даёт 0 вместо 7, при этом сравнение с присваиванием верно). ОТДЕЛЬНО .tmp/probe-sum-compare.ts: после второго последовательного цикла накопитель первого читается как 3 вместо 6 — это другой симптом, и он в класс возврата из ветви не укладывается. | пример `30-две-суммы-в-одном-цикле` | на модели 0 против 1 на VM при полном понижении (отказов 0).
