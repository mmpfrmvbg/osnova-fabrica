# Корпус примеров

> Файл сгенерирован: `npx tsx src/scripts/examplesIndex.ts`. Руками не править —
> расхождение с корпусом ловит оракул `src/scripts/examples.audit.test.ts`.

Здесь лежат законченные программы: каждая собирается и исполняется, у каждой
эталон результата получен **независимо** от прогона, который её проверяет.
Статус `нет` у цели обязан называть причину — молчаливое «не работает»
причиной не считается.

## Границы, названные честно

Сюда попадают программы дерева, которые в корпус не входят: они делают то,
чего язык на цели пока не умеет. Это не дефект корпуса, а честная граница.

## Что на железо не поедет

Список собран из статусов, а не написан руками: границы плюс примеры
корпуса, объявленные неисполняемыми на цели. У каждого названа причина и
**слой**: обвязка (наш раннер), понижение, кодировка, модель — или «не
установлено». «Дефект модели» без такого разложения не доказательство.

| Что | Слой | Причина |
|---|---|---|
| пример `03-арифметика` | понижение | вывода числа на цель нет: реестр системных вызовов исполняется VM и на цели не понижен (§13.12) |
| пример `05-условия` | понижение | вывода числа на цель нет: реестр системных вызовов исполняется VM и на цели не понижен (§13.12) |
| пример `07-сумма-массива` | понижение | массивы на цели работают (§13.12), но вывода числа на цель нет: реестр системных вызовов исполняется VM и на цели не понижен (§13.12) |
| пример `09-деление-и-остаток` | модель | знак остатка на цели расходится с VM (smodx даёт 0: §13.6a, docs/hardware-debt.md §3.21), и вывода числа на цель нет: реестр системных вызовов исполняется VM и на цели не понижен (§13.12) |
| пример `10-модули-и-импорт` | понижение | вывода числа на цель нет: реестр системных вызовов исполняется VM и на цели не понижен (§13.12) |
| пример `21-две-накапливающие-переменные` | канал наблюдения | на модели 46 против 2350 на VM при полном понижении (отказов 0) — прогон 2026-09-27 тем же вызовом, что у оракула цели (src/scripts/e2kProgramRun.runOnE2k). 46 = 2350 mod 256: код возврата есть МЛАДШИЙ БАЙТ верного числа, поэтому эталон 2350 через этот канал не наблюдается (измерено: тело `70000 div 10 = 7000` даёт код 88 = 7000 mod 256). Вычислительного дефекта у примера 21 замером НЕ показано. СЛОЙ — «канал наблюдения» (решение владельца 2026-09-27), а не «модель»: прежнее объяснение («значения >= 256 теряют старшие разряды, рушится ALU-путь») снято, снята и замена его на «до регистра доезжает только младший байт литерала» — различающая проба .tmp/osnova-byte-width-discriminator.ts (2026-09-27): `movts 1000` → ÷10 = 100, `movtd 1000` → 100, `movtd 70000` → 88, `22 * 100` → ÷10 = 220, круг через память (`std` + `ldw`) → 100, то есть литералы целы и ALU считает широко. СТАТУС остаётся «нет» намеренно: печати у языка пока нет, и вернуть 2350 нечем; канал вернёт его, когда заработает `система.лог.вывести` (в корпусе это 39–44, `via: "вывод"`). Оракул корпуса теперь ОТКАЗЫВАЕТ, если у исполняемой записи эталон >= 256 (src/scripts/examplesE2k.audit.test.ts, сторож канала наблюдения).
